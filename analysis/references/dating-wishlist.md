# 定年取证清单（按优先级）

> **用途**：为 `analysis/eras.py` 的 nid 定年补充外部创建时间证据，供人工查找。
> **生成**：2026-11-16，数据现算自 `analysis/out/novels.csv`（245,779 行）与 91 个 API 锚点。
> **证据等级**：用户说明「粗略」日期**误差小于 7 天、约 80% 即为准确创建日**，可作等式级回测。
> **回传格式**：书名（最好同时给 nid）+ 日期 + 标注「精确 / 粗略」+ 来源（URL / 截图 / 接口）。
> **为何要 nid**：书名存在同名与标点差异（如《英雄再临(英雄？我早就不当了)》），nid 是唯一键。

---

## 判断依据：当前证据在时间段上严重不对称

定年在 log(nid) 空间按相邻锚点分段线性插值，置信分档按锚点时间隔：≤90 天 high、≤365 天 mid、>365 天 low。

- **4 条精确日期全部落在 2023–2024 的 high/mid 段**，偏差 0 / −3 / +24 / −1 天（≤24 天）。
- **3 条粗略日期全部落在 2012–2016 的 low 段**，偏差 −57 / −28 / +76 天（≤76 天，且参考日本身误差 <7 天）。

即：曲线最准的区间已被反复验证，**误差最大、锚点最稀疏、且承载报告 01 早期题材与供给结论的 low 段反而证据最少**。因此优先级按「能补多大的锚点间隔」排序，而不是按书的知名度。若 P0 能拿到 3 本以上，可评估对 low 段做局部重标定（会连带改变年度统计，需单独决策，不会自动并入）。

## 批量取证提示（比逐本查详情页高效）

1. **征文公告页 / 参赛作品列表**：一次含数十至数百本，届次提供天然年份约束。已验证第六～九届冬季征文分别对应 2022/2023/2024/2025 年冬季。注意征文允许旧书参赛，参赛 ≠ 该年创建。
2. **年度 TOP10 页**：2020 年度榜单的 10 个 nid 与接口原始响应已存 `analysis/references/my2020-top10.json`；同类年度页若有其他年份，可一次取 10 本。
3. **萌神大赛历届冠军公告**：13 本冠军作品明确，但标签年份是届次年份、不是上架年份，公告日期只能作上界。
4. **作者作品列表**：「漢唐歸來」已知 4 本分布在 2018 / 2020 / 2023 / 2024，若作者页显示创建时间，一次可覆盖四个年份。
5. **作品详情页 / 接口的 `addTime` 字段**：最理想，与现有 91 个 API 锚点同质，可直接作等式锚点。

## 回传后的处理

新日期按类型存入 `verified_dates.jsonl`（精确）或 `approximate_dates.jsonl`（粗略），报告 01 §1 会现算偏差表；**默认不并入 91 个插值锚点**。若 P0 取得 ≥3 本且偏差方向一致，再单独评估 low 段局部重标定及其对三份报告年度统计的影响。
