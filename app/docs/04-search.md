# APP 设计文档 04：搜索与自动收录

> **定案 v1.0**。口径依据：`docs/sfacg-endpoints.md`（端点实测）与本地全库现算。
> 不涉及详情抓取（归 05）、种子构建（归 02）、榜单口径（归 03）。

## 0. 结论

搜索 = 本地 + 官方三层合并。核心事实：**官方搜索是 ≤30 条截断检索且不可翻页**，
所以本地种子不可替代（宽泛词命中比官方多 5–80 倍）；官方的价值是**精确书名 12/12 命中**
与触及库外书；自动收录收益为边际补充（官方结果 9.2% 在库外）。

四条红线：
1. UI 不承诺「搜遍全站」，只说「找到 N 本」，禁用「共/全部/完整收录」；
2. 本地优先于官方（因本地更全，不是更快）；官方结果不排在本地前；
3. 官方结果不进统计（`discovered` 无定年无分位，不参与榜单）；
4. HTML 静默限流必须显式识别——「结果为空」判断会把限流当成「没有这本书」。

## 1. 官方接口能力（实测）

| 接口 | 条数 | 分页 | nid | 简介 | 评分 | 限流 |
| --- | --- | --- | --- | --- | --- | --- |
| HTML `s.sfacg.com` | **≤30（截断）** | ✗ | ✓ | ✓ | ✗ | **静默限流** |
| JSON `op=search` | 6–15 | ✗ | ✓ | ✗ | ✓ | 未触发 |
| 联想 `op=searchreffer` | 15 | ✗ | ✗ | ✗ | ✗ | 未触发 |

三者不可替代：简介只在 HTML，评分/分类只在 JSON，联想只给书名无 nid。
字段与选择器见 `docs/sfacg-endpoints.md` §2/§4。

**截断证据**：搜「的」官方声明 28 条，库内标题含「的」有 97,424 本——声明数即截断数，
真实命中总量不可知。六种分页参数（`Page/page/pi/PageIndex/PageSize`）返回结果完全相同，
全部无效。**官方目录可枚举**（`op=novelbytype` 深翻页），但那是构建期工具（§6）。

**本地优先的证据**（种子 18,877 本，`est_year 2007–2025` 全库 241,864 行）：

| 关键词 | 种子内 | 全库 | 官方最多 | 本地/官方 |
| --- | ---: | ---: | ---: | ---: |
| 魔法 | 757 | 4,210 | 28 | 27× |
| 重生 | 868 | 4,357 | 30 | 28.9× |
| 少女 | 2,343 | 10,813 | 29 | **80.8×** |
| 转生 | 983 | 4,593 | 30 | 32.8× |
| 英雄 | 138 | 1,270 | 29 | 4.8× |
| 剑 | 498 | 3,641 | 30 | 16.6× |

精确书名官方 12/12 命中且排第 1（含全角标点的长书名未覆盖，需回归测试）。
**搜索是收敛工具不是发现工具**——发现走榜单与分类浏览（03）。

## 2. 三层架构

```
L0 联想：本地前缀索引(0ms) ⇄ 官方 searchreffer(~293ms)，二选一
    本地命中 ≥3 → 只用本地；0–2 条 → 本地+官方联想（标「站内有」）；
    停止输入 400ms 且本地 0 命中 → 只发官方联想
    官方联想词按书名去全/半角重（15→13）
L1 本地：<5ms 同步渲染。seed.db + user.db 内存索引，带分位可直接进榜单视图
L2 官方：212–314ms 异步追加。HTML ∪ JSON 按 NovelID 集合运算合并
```

L2 合并规则：**不能按位置切片**——两接口排序不一致（JSON 第 12 条跳过 HTML 第 12 位），
必须按 nid 做集合运算。只用 JSON 丢 17/29 条且无简介；只用 HTML 无评分。
库内书用官方值刷新缓存不改排序；库外书追加 C 组并写 `discovered`。

并发：HTML 与 JSON 串行、间隔 ≥800ms（同域名族并发会加速触发限流）；
单请求 8s，合计预算 12s；HTML 失败降级 JSON，两者皆败保留 L1。

## 3. 合并与排序

| 组 | 条件 | 排序键 |
| --- | --- | --- |
| A 已收录 | 命中 `books` | 用户当前维度（`fav_pctl`/`pr` 等，与榜单同口径） |
| B 本机新增 | 命中 `discovered`/`shelf` | `observed_at` 倒序，无分位 |
| C 官方目录 | 仅官方结果 | 官方相关度，不重排 |

A/B 可合并排序；**C 必须单独成组**（无任何可比数据），默认折叠为
「站内还有 N 本相关」，不展开。提供一键「按相关度」切换（C 提前混排），
开关状态不持久化。

A 组按 `fav_pctl` 排序时相邻书可能跨世代（绝对值差 20 倍），**必须显示世代标签**。

## 4. 自动收录

官方结果 9.2% 在库外（8 关键词 217 条，库外 20）——是「补新」通路非「补漏」
（真遗漏全站约 1k 本，见 §6）；每次搜索期望新增 ≈2.8 本，定位是补上
「用户明确表达过兴趣、但我们恰好没有」的书。

写入规则：
- 仅当 nid 不在 `books` 且不在 `discovered` 时写入；
- `words/favs/praises` 留 NULL（接口不返回，不猜）；
- `source`：html/json/both；同 nid 再命中只更新 `observed_at` 与空字段；
- 容量：超 5,000 条按 `observed_at` 最旧清理从未打开的条目；
  `shelf`/`observations`/`watchlist` 出现过的永不清；
- 「重建索引」不含 `discovered`（否则每次重建结果集不同）。

官方结果质量边界：不按成绩排序（相关度）；分类词按「标题含该字样」处理。
C 组文案用中性措辞「站内还有这些」，不给相关度背书。

## 5. 限流与配额

静默限流实测：连打 17–18 次 HTML 搜索（0.5s 间隔）→ **HTTP 200** + 正常页面 +
「请输入关键字」+ 0 结果，持续 >3 分钟；仅影响 `s.sfacg.com`，JSON/联想/详情不受影响。

识别与降级（在解析器内做，不在调用方）：
```
响应含「请输入关键字」→ 判限流：丢弃、不写缓存、立即切 JSON、
    指数退避 60s→180s→600s、UI 提示「官方检索暂时受限，已显示本地结果」
```

客户端配额：防抖 400ms；同词缓存 24h；单次搜索 2 请求；日上限 200 次搜索，
超限纯本地并注明。**不为补数据构造搜索词**，只记录用户真实搜索。

## 6. 全库枚举：构建期工具

`op=novelbytype` 深翻页：九类 42,568 页 = 255,408 目录槽位，实际返回 221,354±5,578
（13% 槽位被跳过——**目录容量 ≠ 站上活书数**）。全量 16 小时 / 62 MB，
且只给 nid+书名+作者+评分+分类、无成绩字段。**端上不用，构建期/v2 维护用。**

悬疑普查分解：目录库外 187 本里 165 本是快照后新书（nid>774,850，时间差），
**真遗漏 22 本（0.47%）→ 全站约 1k 本**；反方向 10.1% 库内书不在目录（523/5,170）。
排序不按 nid、无「最新」参数，v2 新书发现须整类重扫。

## 7. 空结果与文案

三档兜底：① 官方联想命中 →「你是不是想找：〈书名〉」；② 输入是九类词 → 跳分类浏览；
③ 都没有 →「换个词试试」+ 引导入口，**不给推荐列表**。

文案红线：禁「共找到 N 本」「全站/全部」「未收录=不存在」；C 组禁标「推荐/相关」；
占位文案用「搜书名或作者」。

## 8. 不做

官方结果翻页（参数无效）；标签同义词扩展（「百合」非标签，与「橘味」交集仅 1 本；
「末世」与「末日」交集 0）；搜索历史云同步；拼音全拼；模糊纠错；端上全库枚举；
官方结果并入 `books`。
