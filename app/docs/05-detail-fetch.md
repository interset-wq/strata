## 0. 结论

**一句话**：详情页抓取是 v1 唯一的增量通路，但它抓的是"用户打开的这一本当前值"，不是全库刷新；
端上只写 `user.db`，`seed.db` 永远只读，两者靠 `nid` 关联、按 `observed_at` 取较新者。

| 结论 | 依据 |
| --- | --- |
| 1. **一般读者只抓移动版**（15 KB）；PC 版（73 KB）仅在观测列表订阅点击追踪时抓 | 移动版覆盖读者侧全部字段；PC 版的点击绝对值对作者有价值，但范围严格限于 `watchlist`（§3.3、07 §4.3） |
| 2. **不做点击变化观测，但恢复绝对值写入**：量化步长 1,000（±500），差值可能全是噪声 | `人气：11899.5万` = 118,995,000；不建点击变化榜，但订阅用户记绝对值画趋势（§3.4、07 §4.3） |
| 3. **状态码零信息量**：无效 nid 返回 200，判存在必须匹配否定文案 | PC「小说不存在」1,643 B、移动「出错啦」3,738 B，均与有效页同状态码（§4.3） |
| 4. **三态分级写入**：存活写观测，死亡/僵尸不写成绩观测 | 僵尸数字非法（如负收藏 58 本）若写入会污染时间序列（§4.3、§5.1） |
| 5. **写回只追加观测**：`books` 不写，`discovered` 仅回填空字段，`user_stats` 可重算 | 01 §3.1 种子只读随包；02 §3.1 观测不可重建、统计可重建 |
| 6. **限速器与搜索共用**：全局单例，详情页排队优先，队列溢出直接丢弃 | 04 §8 约定；01 §3 明确请求量随用户数线性增长是生存约束 |
| 7. **解析器必须是纯函数 + golden test**，接口变更先改测试 | 01 §3 已定；网页选择器是无契约接口，无测试等于无声回归（§4.4） |
| 8. **标签/目录不抓；评论仅观测列表书抓** | 标签无写回目标、目录体积过大；评论为精确整数、作者需要，逐本查在观测场景成立（§8、07 §4.4） |

## 1. 口径声明

### 1.1 本文只定义端上抓取，不定义构建期采集

构建期的采集（原始 jsonl → `build_csv.py` → `novels.csv`）是另一条完全独立的通路：
它一次性扫全库、产出种子，归 02 文档。本文的抓取发生在**安装之后、用户使用过程中**，
对象是**用户当前打开的单本书**，产物写入本机 `user.db`。

两者最容易混淆的一点是**同一个字段来自不同时点**：
种子的 `favs` 是 2026-05-03 快照，端上抓到的是抓取时刻的当前值。
二者不是"哪个对"的关系，而是"基线 vs 当前"的关系——这是 01 §3 "用得越多越准"的全部含义。

### 1.2 触发口径沿用 01 §3，本文不重开

进入详情页即触发、唯一主通路、不后台批量、不定时轮转——这些是 01 §3 的既定决策。
本文只补充**触发之后**发生的事：请求哪个端点、怎么解析、判哪一态、写哪张表。

一条必须重申的边界：**未打开的书不会被刷新**。
从搜索或榜单点进详情页与直接输入 nid 走同一条路径，没有第二条更新通路（01 §3.2）。

### 1.3 数据源优先级

同一本书的同一个字段，可能有三个来源：

| 优先级 | 来源 | 表/位置 | 时点 | 用途 |
| --- | --- | --- | --- | --- |
| 1（最新） | 端上详情抓取 | `user.db.observations` | `observed_at` | 当前值展示、本机时间序列 |
| 2 | 端上搜索命中 | `user.db.discovered` | `observed_at` | 仅未收录书，且只有部分字段 |
| 3（基线） | 种子快照 | `seed.db.books` | 2026-05-03 | 分位、世代、榜单排序、冷启动展示 |

**取值规则**：对 `favs`/`praises`/`words`/`status`/`updated_at` 这些两端都有的字段，
取 `observed_at` 较新的一侧（02 §3.2）。分位、世代、定年字段无端上对应物，永远取种子。
`clicks` 是例外：端上不抓（§3.3），无论有无观测都取种子值。

### 1.4 与既有文档的接口

| 依赖 | 本文履行的义务 |
| --- | --- |
| 04 §12 | 收录书（`discovered`）首次进入详情页的抓取与写回契约（§5.2）；与搜索共用同一限速器（§6.1） |
| 01 §3 | "更新该书最新值 + 追加一条观测"的落法（§5.1、§5.4）；失败回落与数据时间标注（§6.4、§7） |
| 03 §4.7 | `observations` 累积到什么程度才够本机收藏涨幅榜（§5.4、§7.2）；点击变化榜已因精度不足取消（§3.4） |

## 2. 核心命题：抓的是逐本当前值，不是全库刷新

### 2.1 为什么不能后台批量

01 §6 已定"不做后台批量爬虫、不做全库 7 天轮转"。端点档案 §8.2 给出的实测约束支撑了这个决定：

- 详情页本身连打 30 次 @0.5 s 未见限流，但**"未见限流"不等于"可以无限打"**——
  HTML 搜索就是在 17–18 次后静默限流的，站方没有统一的限流契约可依赖。
- 请求量随用户数线性增长。一个 10 万用户的 App 若每人后台刷 100 本，就是 1,000 万次请求／轮，
  这是对站点和环境都不负责任的量级（01 §3.2）。
- 逐本触发让请求量与**真实兴趣**成正比：用户打开哪本，说明关心哪本。这是唯一可持续的配额依据。

### 2.2 官方搜索不得替代详情页

04 §2.3 已证：三个官方搜索接口都不返回成绩字段。
`discovered` 表里的 `words`/`favs`/`praises` 在搜索落库时**留 NULL，不猜**（04 §5.2）。
因此一本未收录书要拿到成绩，只有一条路——**进入详情页抓一次**。

这条链路是自动收录真正闭环的地方：搜索只负责"发现 nid"，详情页负责"填满成绩"。
二者不能合并成一个请求。

### 2.3 抓不到的书停留在种子基线

死亡页、僵尸页、网络失败、被限流——任何情况下都不清空已显示的值。
UI 回落种子值（或上一次观测值），并标注数据时间与状态。详见 §6.4、§7.2。

## 3. 端点：移动版为主，PC 版按需

### 3.1 两版实测对照

| 维度 | 移动版 `m.sfacg.com/b/{nid}/` | PC 版 `book.sfacg.com/Novel/{nid}/` |
| --- | --- | --- |
| 体积 | **14.7 KB** | **73,527 B**（约 5 倍） |
| 书名 / 作者 / 封面 | `.book_info span` / `.book_info3` / `.book_info img[src]` | 同页有，但解析更绕 |
| 分类 / 状态 / 定价 | `.book_info div`（`科幻 已完结 VIP`） | `.count-detail .text-row .text` 第 1/2 行、`.title .tag` |
| 字数 | `.book_info3`（`5446886字`） | 第 2 行 `字数：5446886字[已完结]` |
| 收藏 / 赞 / 月票 | `.book_interact li` 第 1/2/4 项 `<small>` | `#BasicOperation .btn` |
| **点击数** | **无** | 第 3 行 `人气：11899.5万` |
| 标签 | 在 JS 里，无结构化 | `.tag-list .tag .highlight .text` |
| 简介 | `.book_bk_qs1`（完整，非截断） | 同页有 |
| banner 位 | 不判 | `.d-banner` 是否存在 |

### 3.2 默认抓移动版的三个理由

1. **体积 5 倍差**：14.7 KB vs 73 KB，在移动网络与每本书都触发的场景下是硬约束。
2. **核心字段全覆盖**：`favs`/`praises`/`words`/`status`/`updated_at`/简介/封面——`observations`
   能存的字段（除 `clicks`）移动版全给。
3. **解析面更小**：选择器少、无「万」单位换算、无 `[已完结]` 括号拆解，出错面小一个量级。

与数据集对照可校验抓取口径：nid=48704 在内容上界时点 `favs` 281,034 / `praises` 89,008，
详情页实测 281,988 / 89,171——**差值即 2026-05 之后的真实增量**，不是解析偏差。

### 3.3 PC 版：默认不抓，但观测列表订阅点击时抓

**一般读者进入详情页只发 1 个移动版请求。** PC 版（73 KB）有一个例外路径，见 07 §4.3：

| PC 版独占 | 处理 |
| --- | --- |
| 点击数 `clicks` | 一般读者不抓（种子绝对值够用、变化榜已取消，§3.4）。**但 `watchlist` 中开启"点击追踪"的书要抓**——作者需要当日点击绝对值画趋势（07 §4.3），只显示绝对值、不做变化 |
| 结构化标签 | 不抓。`books.tags`/`book_tags` 都在只读种子里，端上无写回目标（§8.2） |
| banner 位 `featured` | 不抓。种子字段，端上不重算；封面时间戳是运营时间、有 +338 天中位偏差（报告 01） |

**补抓条件收窄为一句话**：仅当该书在 `watchlist` 且用户开启点击追踪时，才追加 1 个 PC 版请求；
与移动版/评论请求合并进同一限速队列（07 §5.3）。前台普通浏览永远只有移动版 1 个请求。

> 本节原稿写的是"v1 不抓 PC 版、整条例外路径删除"。07 引入作者工作台后，
> 点击绝对值对订阅用户有了明确价值，该例外路径**部分恢复**——但范围严格限于观测列表订阅，
> 不是回到"两版都抓"。

### 3.4 为什么不做点击变化观测（决定及其依据）

PC 版人气显示到 **0.1 万**，`11899.5万` 解析为 118,995,000，**量化步长 1,000、误差 ±500**。
（这个 ±500 是单次显示的量化精度，不是与数据集 118,520,000 的那个差值——后者来自时点不同。）

**决定（2026-11-17，用户确认）**：不做点击变化观测。

理由不是"站点不提供点击数"，而是**这个精度支撑不起变化量这个派生指标**：

- 点击本身是**累计量**（报告 02/08），跨时点不可比还叠加曝光分母与书龄；
  再经过 0.1 万的量化，本机两次观测之差可能**全部是量化噪声**——
  例如 118,995,000 与 118,996,000 的差 1,000 恰好是一个量化步，无法判断是真实增长还是显示取整。
- 观测榜的价值前提是"变化可归因"，点击数的噪声底与有效信号同量级时，
  榜上排名反映的更可能是谁恰好跨过取整边界，而非真实热度迁移。
- 相比之下 `favs` 是**精确整数**、更接近真实偏好（报告 02），收藏涨幅榜不受此限制——
  这也是 C 类观测榜收敛到单一收藏维度的原因。

**连带处置**：`user_stats.click_delta_30d` 恒 NULL（不算变化量）。
`observations.clicks` 则**对 `watchlist` 中开启点击追踪的书恢复写入当日绝对值**——
绝对值序列可信、足以画趋势，这是 07 作者工作台的需求（07 §4.3）；
一般读者仍不抓 PC 版、不写点击。
数据集里的 `clicks` 另用于 03 的 A 类离线点击分位榜（构建期静态分位，与本机观测是两回事）。

> 关键区分：**恢复写绝对值 ≠ 恢复做变化**。写入 `clicks` 与 `click_delta_30d` 恒 NULL 不矛盾——
> 前者是原始观测，后者是不可信的派生差值。

## 4. 解析：纯函数 + golden test + 三态判定

### 4.1 移动端字段映射

| 写回字段 | 选择器 / 位置 | 示例（nid=48704） | 解析要点 |
| --- | --- | --- | --- |
| `favs` | `.book_interact li` 第 1 项 `<small>` | 281988 | 去千分位逗号；**负数按僵尸判**（§4.3） |
| `praises` | 同第 2 项 `<small>` | 89171 | 同上 |
| `words` | `.book_info3` | `5446886字` | 剥「字」；`0` 视为缺失 |
| `status` | `.book_info div` | `科幻 已完结 VIP` | 取含「完结/连载」的片段；**当期态** |
| `updated_at` | `.book_info3` | `24-03-25 20:57` | `YY-MM-DD` **补 20 世纪** → `2024-03-25 20:57:00` |
| 简介 | `.book_bk_qs1` | 完整文本 | 只入内存展示；`discovered` 回填用（§5.2） |
| 封面 | `.book_info img[src]` | `//rs.sfacg.com/...jpg` | **协议相对 URL 补 `https:`** |

打赏项（第 3 项）**只有「打赏」二字、无数字**，不解析成数量（端点档案 §4.1）。
月票（第 4 项）有数字，但 `observations` 表无对应列，v1 丢弃（§8.1）。

### 4.2 两个解析陷阱（移动端）

| 陷阱 | 错法 | 正法 |
| --- | --- | --- |
| 两位年份 | 把 `24-03-25` 当 1924 或原样存 | 固定补 `20` 前缀；写入 TEXT 供字典序比较 |
| 负数/非法数字 | 把 `-5` 收藏当有效值写观测 | 数字字段合法性校验在**写入前**拦住（§4.3） |

> **「万」单位解析仅在订阅点击追踪时实现**：PC 版人气 `11899.5万` 的专属陷阱（§3.3）。
> 解析式为 `float(x.replace("万","")) * 10000`，须接受 ±500 量化；
> 解析结果只作绝对值展示，不做变化观测（§3.4、07 §4.3）。

### 4.3 三态判据：先判态，再解析

端上抓到 HTML 后，按顺序执行（端点档案 §4.4、§11.5）：

```
响应到达（HTTP 状态码一律忽略）
  ├─ 含「小说不存在」(PC) / 「出错啦」(移动) → 死亡
  │    → 不写成绩观测；UI 标注「官方页面不存在」，回落本地值
  ├─ 无「点击阅读」/「目录列表」入口，或 div.book_Catalog 下无 <a>  → 僵尸
  │    → 不写成绩观测；UI 标注「该书当前不可阅读」，回落本地值
  ├─ 数字字段非法（收藏/赞/字数为负、全零异常、字数与章节明显不符） → 僵尸
  │    → 同上；典型样本：negative_favs 58 本有阅读入口但 like_num < 0
  └─ 有入口 + 数字合法 → 存活 → 按 §4.1 解析，进入 §5 写回
```

**三条红线**：

- **不看状态码**。无效 nid 返回 200，与正常页同 content-type（端点档案 §4.4）。
- **不用体积阈值判活**。僵尸页 13–15 KB、与存活页体积中位只差 35 B；">5 KB 含书名"必判错。
- **不细究下架原因**。"应版权方要求，该小说已经下架"是充分非必要条件——出现它必是僵尸，
  **没出现不能判存活**。多数僵尸页简介不写声明，主判据只能是"缺陷检测"（无入口 / 数字非法）。

结构化判据优先于关键词：`div.book_Catalog` 下有无 `<a>` 比正文搜"点击阅读"更稳。
（僵尸页该容器为空；`/i/{nid}/` 目录页僵尸 4–6 KB 空壳、存活 167 KB，可作二次确认但不必抓。）

**方向性提醒**：僵尸实证集中在 `nid ≤ 83,624` 的低 id 段；高 id 抽样 40/40、库内 >60 万抽样 30/30
全存活。**端上判活率不能被低 id 僵尸率污染**，但也不要把"高 id 没见过僵尸"外推成"高 id 不会死"。

### 4.4 解析器必须是纯函数 + golden test

01 §3 已定此契约，这里给出落地约束：

- **签名**：`parse_detail(html: bytes, url: str) -> Result<DetailState, ParseError>`，
  不访问网络、不读数据库、不读全局时钟；时间由调用方注入。
- **fixture**：每态至少一份真实 HTML。存活样本已有 `temp/_page_48704.html`（14 KB）、
  `_page_21899.html`；死亡与僵尸的 HTML 原文**尚未留档**（现有 `out/_page_states_probe.json`
  只有特征没有原文）——这是 §10 #1 的待办，补齐前 golden test 只覆盖存活态。
- **变更顺序**：站方改版 → 先更新 fixture 与期望值 → 测试红 → 改解析器 → 测试绿。
  禁止反过来（先改解析器再补测试），那等于没有测试。
- **失败可见**：解析失败返回结构化 `ParseError`（含端点、选择器、原因），不返回半截结果；
  上报仅限本机日志，不上传（01 §6）。

## 5. 写回契约

### 5.1 `observations` 追加（唯一的成绩真相）

仅**存活态**写入，Go 侧单事务完成（01 §3）：

```sql
-- 基础 INSERT（所有详情页进入都写）
INSERT INTO observations(nid, observed_at, favs, praises, words, status, updated_at, source)
VALUES (?, ?, ?, ?, ?, ?, ?, 'detail');
-- 以下两列仅在对应请求实际发生时 UPDATE 同一行（07 §4）：
--   clicks            ← 订阅点击追踪、抓了 PC 版时（§3.3）
--   short_comments / long_comments ← 作者工作台抓取评论时（§8.1、07 §4.4）
-- 同时按观测增量更新 user_stats（§5.4）
```

| 字段 | 来源 | 缺失时 |
| --- | --- | --- |
| `nid` | URL 路径 | 必填 |
| `observed_at` | 抓取开始时刻的 unix 秒 | 必填；由引擎注入，不由解析器 |
| `clicks` | 仅订阅点击追踪、抓了 PC 版时写（§3.3、07 §4.3） | 一般读者 NULL，不写 0 |
| `short_comments`/`long_comments` | 仅作者工作台抓评论时写（§8.1、07 §4.4） | NULL = 本次未抓；**不是 0** |
| `favs`/`praises`/`words` | §4.1 解析 | 解析失败则不写整行 |
| `status`/`updated_at` | §4.1 解析 | 允许 NULL |
| `source` | 固定 `'detail'` | 区分搜索命中与详情抓取 |

主键 `(nid, observed_at)` 天然去重（02 §3.1）：同一秒重复抓取被忽略，不需要额外判重写入。
保留策略按 02 §3.1：保留 180 天、按月批量 `DELETE`，不做 VACUUM。

### 5.2 `discovered` 回填（未收录书首次打开）

04 §5.3 规定收录书可进入详情页、抓到的成绩写 `observations`、**但仍不进 `books`**。
这里补完另一半：**抓取结果同时回填 `discovered` 仍为空的列**。

| 列 | 回填规则 |
| --- | --- |
| `words`/`favs`/`praises`/`cover_url`/`summary` | 原为 NULL 的，用本次抓取值填入；**已有值不覆盖**（与 04 §5.2 一致） |
| `title`/`author`/`genre` | 搜索时已有，不覆盖 |
| `observed_at` | 更新为本次抓取时刻 |
| `source` | 保留原值（`html`/`json`/`both`），**不改成 detail**——它记的是"从哪发现的" |

**仍不写 `books`**：`books` 是种子内容，运行时不可写（01 §3.1）。
`discovered` 的书没有定年、没有分位、没有历史指标，不参与任何榜单与分位分母（02 §3.2、04 §5.3）。

### 5.3 绝不写 `books`

这条值得单列，因为它是整个双库设计的地基。`seed.db` 是只读打开、覆盖安装整包替换的副本
（01 §3.1）；任何"顺手更新一下种子里这本书的收藏"都会：① 升级后丢失，② 污染分位分母
（分位在全库固定集合上算，02 §5.1 规则 1），③ 让种子与发布版本不再一一对应。
**端上的所有写操作只落在 `user.db`。**

### 5.4 `user_stats` 增量与当前值

`user_stats` 是派生缓存，每次观测写入后增量更新（02 §3.1）：

| 列 | 更新 |
| --- | --- |
| `fav_delta_30d` | 由 `observations` 中 30 天前的 `favs` 与本次值相减；无 30 天前观测则保持 NULL |
| `click_delta_30d` | **v1 恒 NULL**（点击变化观测取消，§3.4）；列保留兼容表结构 |
| `obs_count` | +1 |
| `first_seen` / `last_seen` | 首次写 / 更新为本次时刻 |

**"更新当前值"的落法**：01 §3 表格里的"更新该书最新值"**不是**新增一张"当前值表"，
而是 `observations` 追加后，跨库查询时取较新者（02 §3.2）。冷启动无观测时取种子值。

`user_stats` 可从 `observations` 全量重算——观测丢了就丢了，统计丢了能重建（02 §3.1）。
03 §4.7 的本机涨幅榜在 `obs_count` 不足或跨度 <30 天时**隐藏整榜**，不做降级展示。

## 6. 限速、去重与失败降级

### 6.1 与搜索共用同一限速器

04 §8.2 要求搜索的静默限流识别规则与本篇抓取器共用一套限速器。落地为 Go 侧**全局单例**
（`engine/crawler`，01 §7），不按调用方分实例：

| 规则 | 值 / 行为 |
| --- | --- |
| 端点间隔 | ≥1 s（端点档案 §8.2 建议值），全局共享，不因切换端点而重置 |
| 详情页优先 | 限速器排队时详情页请求优先于搜索请求（01 §3） |
| 队列上限 | 设硬上限，**溢出直接丢弃**而非积压——快速翻书时宁可少刷几本 |
| 同书合并 | 并发的同一 nid 请求合并为一次（01 §3） |
| 单端点日上限 | 详情页的独立配额见 §10 #3（待定初值）；搜索侧 200 次/日沿用 04 §8.3 |

**静默限流检测要复用**：虽然详情页目前未测到限流，但同一站点、同一套"200 + 合法结构"的失败风格，
解析器里必须有兜底——响应缺少任何已知结构（书名、`.book_interact`、否定文案三者皆无）时，
按"未知失败"处理，**不当成空数据、不写观测**（与 04 §8.2 同理）。

### 6.2 去重窗口

同一本书 30 秒内重复进入详情页只发一次请求（01 §3 初值）。窗口内二次进入：
读本地已有值，不追加观测——避免把同一时刻的同一状态记成两条时间序列样本。

### 6.3 失败分级

| 级别 | 情形 | 处理 |
| --- | --- | --- |
| F1 网络 | 超时、连接失败 | 回落本地值；不重试到用户无感——前台操作要立即响应 |
| F2 限流 | 响应结构缺失、疑似静默限流 | 回落本地值；退避由限速器统一管理 |
| F3 死亡 | 否定文案 | 标注"官方页面不存在"；回落本地值；不写观测 |
| F4 僵尸 | 无阅读入口 / 数字非法 | 标注"当前不可阅读"；回落本地值；不写观测 |
| F5 解析 | 选择器未命中、格式异常 | 结构化 `ParseError`；回落本地值；本机日志 |

**任何一级都不清空正在显示的值、不显示空白、不显示"不存在"**（01 §3）。
F3 的"官方页面不存在"是状态标注，不是这本书从用户视野里消失。

### 6.4 UI 回落契约

回落时 UI 必须同时给出**值**和**这个值是什么时候的**：见 §7。

## 7. 数据时间标注规范

### 7.1 两个时间戳，分别标记

01 §3 要求种子值与本地抓取值分别标记来源与 `observed_at`。落法：

| 展示元素 | 取值 |
| --- | --- |
| 成绩数值 | 有观测取最新观测，无观测取种子 |
| 来源标签 | `本地刷新于 YYYY-MM-DD HH:MM`（有观测）/ `种子快照 2026-05-03`（无观测） |
| 回落态 | `本地刷新于 …（官方页面当前不可读，显示上次记录）` |

**禁止**把种子值标成"当前"，也**禁止**把回落值标成"实时"。
2026-05-03 这个快照日从 `seed_meta` 读，不硬编码在 UI（02 §2.4）。

### 7.2 本机时间序列的成熟度提示

03 §4.7 的两个观测榜依赖 `observations` 的累积程度，UI 按状态提示：

| 条件 | 展示 |
| --- | --- |
| 同一 nid 只有 1 条观测 | 只显示当前值，不显示涨跌幅 |
| ≥2 条观测但跨度 <30 天 | 显示"观测中，尚不足 30 天" |
| ≥2 条观测且跨度 ≥30 天 | 显示收藏涨幅（精确整数差值）；**无点击涨幅榜**（§3.4） |
| 全书观测样本不足 | 整榜隐藏，不降级展示（03 §4.7） |

## 8. 新维度评估：评论、标签、目录

### 8.1 评论：仅观测列表中的书抓

端点档案 §6：`op=getcomment` 可用，nid=48704 短评 82,291 / 长评 452，**均为精确整数**。
解析时**必须过滤 `CommentID=0` 的置顶公告**。

**原稿写的是"v1 不抓"**，两条理由是"只能逐本查"与"无写回目标"。
07 作者工作台使这两条都不成立，因此评论抓取**部分恢复**：

| 场景 | 是否抓评论 |
| --- | --- |
| 一般读者打开详情页 | **不抓**（评论不是读者选书的核心指标，省一次请求） |
| `watchlist` 中的书（作者工作台/后台爬取） | **抓**：短评数/长评数写入 `observations.short_comments` / `long_comments`（07 §4.4） |

**仍是逐本查、仍不能做全库统计**——03 §7 "长评/短评榜不可做"的判定只对**全库**成立，
观测列表内对一两本书做时间序列完全可行，两者不矛盾（03 回填见 07 §10）。

> 评论是精确整数、无点击的量化问题，因此可做变化观测与曲线（07 §4.4）——
> 这恰是作者比点击更可靠的反馈信号。

### 8.2 标签：只有 PC 版有结构化

移动版标签在 JS 里，PC 版 `.tag-list` 有结构化标签。但端上抓到标签后**没有写回目标**：
`books.tags` 在只读种子里，`book_tags` 同理。v1 不为了标签而补抓 PC 版（§3.3 的触发条件不含标签）。

### 8.3 目录与章节：不抓

`m.sfacg.com/i/{nid}/` 是 168 KB（存活）或 4–6 KB（僵尸），比详情页大一个数量级。
章节数、卷数不是 `observations` 的字段，也不是任何榜单的维度。
三态判据用 `div.book_Catalog` 有无 `<a>` 即可，无需抓目录页（§4.3）。

## 9. 明确不做

| 不做 | 原因 |
| --- | --- |
| 全库后台批量 / 定时轮转 | 01 §6；请求量随用户数线性增长是生存约束。**观测列表的订阅式爬取除外**（07 U5） |
| 对一般读者抓 PC 版详情页 | 只有订阅点击追踪的 `watchlist` 书才抓（§3.3、07 §4.3）；标签/featured 永无写回目标 |

| 对一般读者抓评论；抓标签、目录章节 | 评论仅观测列表书抓（§8.1、07 §4.4）；标签无写回目标、目录体积过大（§8.2–8.3） |
| 把抓取值写进 `books` | 种子只读、分位分母固定（§5.3） |
| 把死亡/僵尸写成 0 值观测 | 污染时间序列（§4.3、§5.1） |
| 靠 HTTP 状态码判成功失败 | 本站状态码零信息量（§4.3） |
| 按体积阈值判活 | 僵尸与存活体积中位只差 35 B（§4.3） |
| 细究下架原因 | 多数页不写声明，且原因不进判据（§4.3） |
| 上传抓取结果或失败日志 | 无服务端、无观测上报（01 §6） |
