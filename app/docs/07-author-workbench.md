# APP 设计文档 07：作者工作台与观测列表

> **定案 v1.0**。口径依据：`docs/sfacg-endpoints.md` §4.4/§6/§11.5。
> 上游契约：01 §3（触发与限速）、02 §3（`observations`/`watchlist`/`novel_chapters`）、
> 05（三通路、三态判据、写回）。本文不改动全库层面的任何决定。

## 0. 结论

官方作者后台只给收藏动态变化；作者真正关心的是**更新量（直接关系全勤 RMB）、点赞、
收藏、评论、长评、点击**及同期对照——做成"订阅书 × 时间"的可视化是核心竞争力。

| 结论 |
| --- |
| v6 起 `watchlist` 统一原书架：`poll_enabled` 区分激活（追踪数据）/未激活（只存，原「想读」），`role` 区分本人作品/同期对照 |
| 后台定期爬取只作用于观测列表（用户显式订阅、≤100 本、间隔 ≥6h）；全库轮转仍禁 |
| 点击按通路分档：PC 版 ±500 只显绝对值；App API `viewTimes` 精确整数可做单书曲线；跨书变化榜不做 |
| 评论可做变化观测（`op=getcomment` 精确整数）；"热力图"专指更新热力图 |
| 更新量第一指标：**主方案 = App API 章节时间戳**（数据缺口概念不存在），观测差分为回退 |
| 复合指标端上现算不落表；作者功能不写 `books`、不改分位分母 |
| App API 是可选增强，失效即降级；定年继续 `log(nid)` 反推 |

## 1. 观测列表 `watchlist`

```sql
CREATE TABLE watchlist(
  nid INTEGER PRIMARY KEY,
  role TEXT NOT NULL DEFAULT 'self',      -- self 本人 | peer 同期对照
  added_at INTEGER NOT NULL,
  poll_enabled INTEGER NOT NULL DEFAULT 1,
  poll_interval INTEGER NOT NULL DEFAULT 86400,  -- 最小 21600（6h），档位 6h/24h/7d
  last_poll_at INTEGER, note TEXT,          -- 前台打开不更新 last_poll_at
  list_id INTEGER NOT NULL DEFAULT 0        -- v6 分组（0 = 主列表，原书架分组）
);
CREATE INDEX idx_watch_poll ON watchlist(poll_enabled, last_poll_at);
CREATE INDEX idx_watch_role ON watchlist(role);
-- watch_lists(id, name, created_at)：v6 由 shelf_lists 改名而来，数据保留
```

- 加入：从详情/搜索/榜单均可，需选 role；重复加入只更新 `added_at`。
- v6 起与原书架合并：`poll_enabled=0` 的未激活条目（只存、不后台抓取）即原书架数据，
  user.db v5→v6 迁移自动迁入；激活切换 = `PUT /strata/watchlist/:nid {active}`。
- 移除只删本行，**`observations` 历史保留**；暂停 `poll_enabled=0`，恢复不补跑缺口。
- `role` 可改（UPDATE 一列），历史曲线连续。
- 容量：上限 100 本（self ≤20、peer ≤80 建议值）；超限提示移除，不自动删。
- 同期判定：`est_year` 差 >2 年软警告（不硬拦）；定年未知不进对照图。
- `discovered` 清理豁免 `watchlist` 中的条目（订阅是更强的兴趣信号）。

与 C 类观测榜（03 §4.7）分工：观测榜面向读者、对象为本机全部观测书、仅 favs 排行；
工作台面向作者、仅 `watchlist` 书、全指标仪表盘。

## 2. 全勤奖与更新量（第一指标）

官方规则（已查证）：**日更 ≥3,000 字 + 每月允许一次断更 → 500 元/月**（权威源
`i.sfacg.com/fuli.shtml`；征文公告另有 1,000 元档与勤更累计奖；第三方导航 2,000 字口径不采纳）。
**阈值可配置不硬编码**（存 `prefs`，标注来源与查证日期），默认取官方口径。

口径冲突处置：日门槛 3,000 vs 2,000 → 默认 3,000；500/1,000 双档 → 1,000 做可选目标线；
待审章（`auditStatus=1`）是否计入官方判定未知 → **单列标注不静默计入**；VIP 章分开展示。

### 更新量归因（主备方案）

| | **主方案：章节时间戳** | **回退：观测差分** |
| --- | --- | --- |
| 来源 | App API `chaps` 逐章 `addTime`+`charCount` | `observations.words` 按自然日聚合差分 |
| 单日更新量 | 直接可读（该日章节 `charCount` 求和） | 当日累计 − 上一有观测日累计 |
| 断更识别 | 精确（无章节的自然日） | 仅"有观测且 Δ=0" |
| 数据缺口 | **不存在**（章节是历史事实） | 存在：没打开 App 的天数是缺口 |
| 全勤单日判定 | 可做 | 不可做（看板显示"N 天未观测"） |

回退方案归因规则：按**自然日（本地时区）**分组取每日最后一次 `words`；
相邻有观测日相差 1 天 → 高置信归后一日；相差 N 天 → 标"含 N 天累计"；
>7 天 → 中间格标"数据缺口"**不染色**（空白 ≠ 断更）——这是回退方案最致命的误导点，
主方案从根上消除。

无论哪套来源，UI 固定标注"**估算值，非官方判定**"（官方按正常章节正文计、按月结算，
我们是过程预警）。章节过滤：`isRubbish` 废章、待审态单列、`isVip` 分开统计。

## 3. 多指标观测

| 指标 | 来源 | 精确性 |
| --- | --- | --- |
| 更新量 Δwords | 主：章节聚合；回退：words 差分 | 正文口径（主方案） |
| favs / praises / words | 移动版 / App API | 精确整数 |
| 短评 / 长评 | `op=getcomment`（须过滤 `CommentID=0` 置顶公告） | 精确整数，可变化观测 |
| clicks | PC `人气…万` / App `viewTimes` | 按通路分档 |

点击口径：PC 版差值可能全是取整噪声 → 只显绝对值；App API 精确 → 单书日增曲线可做
（标注"累计量，非独立日更"）；**跨书点击变化榜与 `click_delta_30d` 仍不做**
（累计量跨书比需曝光分母分档，端上没有分母）。写入 `observations.clicks` 绝对值
与 `click_delta_30d` 恒 NULL 不矛盾（原始观测 vs 派生差值）。

### 复合指标（现算不落表）

观测集 ≤100 本 ×180 天，现算毫秒级；定义会迭代，落表反加迁移负担。
与全库预计算（02 的 `pr` 列）是不同场景。

| 指标 | 公式 | 门槛 |
| --- | --- | --- |
| 赞藏比 pr | `praises/favs` | `favs ≥ 10`；限同期同字数档，不做"谁更好"结论（短篇低曝光下方向反转） |
| 评论率 cr | `(short+long)/favs` | `favs ≥ 10` 且两列都抓到 |
| 收藏/点赞/评论日增 | Δ/Δdays | 相邻有观测日相差 1 天才算 |
| 字数日增 | Δwords/Δdays | 不设门槛；首要用途喂热力图，不进热度比较 |

不做：收藏转化率 `favs/clicks`（曝光分母效应）、跨书点击日增、跨世代复合比较、
同期总排名（不同指标领先者不同，合成名次丢信息）。书在种子里可并排显示
"种子赞藏比 vs 本机现值"，**不算差值**。

## 4. 后台定期爬取（U5）

与全库轮转的本质区别：用户显式开启、对象 ≤100 本（实际 1–3）、日请求 ≤300、
可随时 `poll_enabled=0` 关闭。06 的"不叠加调度"收窄为"不叠加**全库**调度"。

| 项 | 规则 |
| --- | --- |
| 触发 | `poll_enabled=1` 且到期；App 启动 + 前台定时器检查；**不做真后台服务**，未运行不爬、下次启动补一次 |
| 限速 | 共用全局单例：端点间隔 ≥1s；优先级 前台详情 > 搜索 > U5；U5 溢出直接丢弃；日上限 300 与搜索 200 分开计数 |
| 失败 | 死亡/僵尸标注不写观测；网络失败记 `last_poll_at` 防反复重试；连续 3 次失败暂停订阅并提示 |

单本次请求数：移动版 1 + 评论 1 +（点击追踪时）PC 版 1；启用 App API 则详情 0.7 KB、
章节清单一次性 222–489 KB，无需 PC 版。

## 5. 图表矩阵与红线

| 图表 | 内容 |
| --- | --- |
| **更新热力图（首屏）** | 某日新增字数，色阶**锚全勤阈值**（不做书内归一化——归一化会把 2,900 字染成高产色）；默认 12 周，可切 4/12/26；区分"无更新"与"数据缺口"（缺口不染色） |
| 全勤达标看板 | 月累计/目标、断更次数（已用/允许 1）、预计达标 |
| 同期对照折线 | self + peer 同指标同轴；点击仅 App API 通路可叠加 |
| 复合指标走势 | §3 现算指标，须过门槛 |
| 同期位置散点 | 横轴 favs（对数）、纵轴 pr；只画同期书，**不排名** |
| 当前值仪表盘 | 最新观测 vs 种子基线 |

红线：点击变化量按通路分档、跨书一律不做；热力图锚绝对阈值；全勤标注"估算值非官方判定"；
App API 失效时相关图表自动隐藏（不显示空图或编造数据）；对照图标注 `est_year` 差；
样本不足显示"观测不足"，不画单点假趋势；所有值标注来源与时点；
不画全库热力图（全库时序不存在）；C 类观测榜与工作台不混页。

## 6. 数据模型变更

| 变更 | 表 |
| --- | --- |
| 新建（v1） | `watchlist`（§1，作者追踪列表） |
| v6 统一书架 | `watchlist` 加 `list_id`；`shelf` 并入且被 DROP、`shelf_lists` 改名 `watch_lists`（见 02 §3） |
| 加列 | `observations.short_comments` / `long_comments`（v2 迁移，默认 NULL） |
| 恢复写入 | `observations.clicks`（不改 schema，只改写入逻辑） |
| 新建 | `novel_chapters`（章节快照；清理按"超出热力图回溯窗口 12 周"而非抓取时间） |
| 不变 | `user_stats.click_delta_30d` 恒 NULL；复合指标不落表 |

`novel_chapters` 体积：1,740 章落库 ≈130 KB/本，100 本上限最坏 13 MB，可接受。
作者的书是否在种子里均可观测：在则显示种子基线对照，不在则标注"本机收录，无基线"。

## 7. 不做

全库后台轮转；服务端观测上报/作者账号/云同步；跨书点击变化榜与 `click_delta_30d`；
收藏转化率；跨世代复合比较与同期总排名；全库热力图；写 `books`/改分位分母；
真后台服务；极短爬取间隔（硬下限 6h）；存评论正文；取章节正文；
App API 取代 web 基线；`addTime` 替换定年；引入用户凭据。
