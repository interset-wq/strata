## 0. 一句话结论

App 提供两种浏览模式——**novly 模式**（直接用平台累计值，易懂但头部固化）与
**量化模式**（世代分位/PR，更会找书但难懂）；但**展示层与推荐层解耦**：
用户无论用哪种模式浏览，后台推荐统一走量化信号，平台累计值严禁回流推荐打分。

---

## 1. 为什么要双模式

两种排序哲学各有真实取舍，不是谁对谁错：

| 维度 | novly 模式（平台展示） | 量化模式（我们自己的指标） |
| --- | --- | --- |
| 数据源 | 平台累计值：`clicks`/`favs`/`praises` | 同代分位 `fav_pctl`/`click_pctl` + `pr`/`pctl_pr` + 深榜 |
| 优点 | 与官方 app 心智一致，数字直观，用户易懂 | 剔除书龄与曝光分母，能发现被埋没的好书 |
| 缺点 | 头部永久高曝光（报告 02/08 的马太效应） | 自定义指标难理解，需要解释成本 |
| 参照系 | 全库绝对值累计 | 以 `est_year` 为参照的世代内分位 |

关键事实（报告 02/08）：累计 `clicks` 混杂书龄与曝光分母，老书靠时间堆出的绝对值
新书永远追不平；novly 模式等于把这套马太效应原样搬进来。量化指标正是为破这个局造的，
数据侧已 ready——种子 `books` 里原始值与分位值并存（见 §4.1），引擎也有两套端点。

---

## 2. 核心架构：展示层与推荐层解耦

这是双模式成立的关键——**用户选的模式只决定"怎么看榜单"，不决定"后台推什么"**。

```
用户选择 novly 模式 ──> 展示层：按平台累计值渲染榜单/详情
                            │（仅展示，只读）
                            │  数据流物理隔开 ↓ 不回流
后台推荐层 ──> 统一走量化信号：同代分位 / PR / 深榜 / 形式维度
                            │
                            └─> 推荐结果注入两种模式的发现流（"你可能错过"）
```

- 用户选 novly 浏览，只是选了呈现口径；推荐层始终用量化信号，**不需要用户理解指标**。
- 推荐结果不解释指标，只解释书——用户不关心 Why，只关心"这几本确实对我胃口"。
- 这绕开了"量化指标用户看不懂 → 量化榜变摆设"的死结：推荐不需要用户主动选，一直在后台生效。

## 3. 推荐层设计

### 3.1 信号性质：口碑驱动，非协同过滤

我们没有用户行为日志（数据集是一次性快照，只有书的客观指标），所以推荐是
**内容/口碑推荐**而非协同过滤：

- 逻辑："同代分位接近 + 题材相同 + PR 高"聚在一起 → 高分冷门书。
- 这恰是官方 app 做不到的——官方靠行为数据只会把用户推向已被点击的头部；
  我们的信号源本身剔曝光、剔书龄，**天然带发现属性**。

### 3.2 推荐信号白名单（红线）

推荐打分**只能**用下列量化字段：

- 同代分位：`fav_pctl` / `click_pctl` / `praise_pctl`
- 派生指标：`pr` / `pctl_pr`
- 深榜：`deep_ranks`（世代内 Top200）
- 形式维度（附录 D 实施后）：`books.form`（short/medium/long/dialogue/ip_collab，
  互斥单值，见 §6）

**严禁** `clicks` / `favs` / `praises` 原始累计值进入推荐打分——
否则马太效应从后门渗入，整个解耦白做。原始值只用于展示层的锚点数字。

### 3.3 候选池门槛

分位按世代算、`pr` 要求 `favs ≥ 10`（报告 21）。冷门新书/稀薄题材分位不稳、
PR 算不出 → 不能进推荐候选池，否则推出来是噪声。需显式"可推荐门槛"
（如 gen 内样本量下限、`favs ≥ 10`），达不到不参与推荐。种子 30,878 本、深榜覆盖各代
Top200，候选池够厚，缺的是把门槛定下来（待拍板具体数值）。

### 3.4 反馈回路隔离（长期红线）

上线后一旦记录用户点击，回路形成：我们推的书 → 用户点击 → 变成平台 clicks →
**若这些 clicks 被拿来当信号，就回到平台老路**。所以从第一天起两条数据流物理隔开：

- **展示/诊断流**：平台累计值，只读，只给用户看，**不回流进推荐打分**。
- **推荐信号流**：量化字段 +（未来的）我们自己的用户反馈，两者都不被平台 clicks 污染。

守住这条隔离，用户即使用 novly 模式浏览，后台推荐依然是我们那套发现逻辑，
且不会随使用时间劣化。

## 4. 数据基础与端点映射

### 4.1 种子字段（两套口径并存）

`books` 表（24 列，见 02 文档）同时存：
- 原始值：`clicks` / `favs` / `praises` / `words`；
- 量化值：`fav_pctl` / `click_pctl` / `praise_pctl` / `pr` / `pctl_pr`；
- 世代键：`est_year` / `est_date` / `est_conf`（`log(nid)` 定年，报告 10）。

### 4.2 端点映射

| 模式 | 端点 | 口径 | meta |
| --- | --- | --- | --- |
| novly 展示 | `GET /strata/rankings/favs` 等 | 原始累计值 | 种子池 |
| 量化展示 | `GET /strata/rankings/deep?year=&metric=&limit=` | 世代内分位/Top200 | `pool=universe` + 真实 depth + `in_seed` |
| 推荐层 | 后端内部，不直接暴露原始累计值 | 白名单字段（§3.2） | — |

深榜的 `in_seed` 标记：命中 nid 不在 `books` 里时走搜索/详情兜底，
不得因不在种子里就过滤掉（见 10 文档 §2）。

## 5. 分页与「到底」策略

用户担心"所有页面都能滑到底 → 觉得内容少"。但**不是所有页面都该无限下滑**。

| 页面类型 | 到底策略 | 理由 |
| --- | --- | --- |
| **发现流**（推荐/量化发现） | **无限滚动**（游标分页，每批 20 本） | 书够多：有真实封面的非授权书 12,107 本，每屏 20 本≈600 屏，用户滑不到底 |
| 分位榜/深榜 | 有限（Top200），底部"看看更多"引导进发现流 | 「Top200」的价值恰在于有限、精选；把榜单当发现流入口 |
| 搜索 | 有限（结果集本身有限） | 搜索是目标明确的场景 |

**发现流红线**：
1. **游标分页，不是页码分页**：每批 20 本，滑到底自动拉下一批，靠稳定排序（量化分位）
   保证不重不漏。
2. **防重复优先于防触底**：推荐层若反复吐头部书，用户滑三屏就觉得"怎么都是这几本"。
   候选池要做去重与多样性打散——这是推荐层的活，不是分页的活。
3. **封面是硬门槛**（针对当前种子）：无封面书不进发现流候选。当前种子深榜 7,838 本里
   仅 832 本有封面（10.6%）；**但 release 使用补全后的优化种子**（封面 URL 队列见 11 提案），
   故本条不阻塞设计，只约束上线时的种子版本。

## 6. 形式维度作为榜单过滤器（附录 D 实施后）

官方 genre 只按主题分 9 类、无形式轴，造成榜单形式噪声（提案 09 附录 D）。
我们在 `books` 主表加互斥单值字段 `form`（short/medium/long/dialogue/ip_collab），
五值的精确判定口径、优先级与伪代码见**权威定义 `app/docs/13-form-definitions.md`**：

- **核心收益是过滤噪声，不只是加入口**：长篇榜排除 `dialogue`（对话小说虽可长至
  88 万字，但对只看长篇的用户是噪声）；短篇榜排除 `medium`（中篇并入会让 favs Top200
  里 197/200 是中篇，真短篇永拿不到推荐位）；
- 保留中篇档（官方为投稿评审取消了，但榜单过滤必须留）；互动并入 dialogue；
- `ip_collab` 靠**征文名称**确定性判定（近年无新增 IP 合作征文，名单封闭）；
  标题 IP 词不作判据——那是对话小说的同人特征（报告 22）；
- 发现流/榜单可按 `form` 过滤，给每类形式**独立入口**；
- `form` 不参与分位计算，只作分类标签；这是量化模式"更好找书"的具体抓手。

## 7. 默认模式与可解释性（产品决策，待拍板）

1. **默认模式**：建议 novly 模式做默认（建立信任、符合官方心智），
   但在详情页同代分位、相关推荐、深榜入口处处处注入量化发现。让用户先待得住，再被引导发现。
2. **定位诚实**：量化模式文案用"你可能错过的书"，不是"更科学的榜"——
   给发现心智，不做价值观审判。
3. **分位永远与绝对值并列**：详情页"收藏分位 99.9% + 收藏 43,161"这种并列是对的，
   保留原始数字做锚，把分位当解读层而非替代层。用户看得懂数字，自然慢慢懂分位。
4. **数据薄处诚实降级**：样本少的世代/题材分位不稳（报告 10 有样本 14–70 的方向性证据），
   不硬套漂亮数字。

## 8. 明确不做

- **不把平台 clicks 回流进推荐打分**（§3.2/§3.4 红线）。
- **不做协同过滤**（无行为日志）。
- **不让量化模式变成说教式产品**（§7.2）。
- **不因当前种子封面缺口降低数据标准**（§5 红线 3，release 用优化种子）。
- **不改报告 10 / `log(nid)` 定年**（项目硬约束）。
- **本文不改任何代码、种子、报告**——仅设计契约。
