## 0. 一句话结论

双模式 = **经典模式class**（采用和novly类似的逻辑，平台累计值，易懂但头部固化）+ **量化模式**（世代分位/PR，
更会找书但难懂）；**展示层与推荐层解耦**：用户无论用哪种模式浏览，后台推荐统一走
量化信号，平台累计值严禁回流推荐打分。

## 1. 两种模式

| 维度   | 经典模式（平台展示）                       | 量化模式（自有指标）                                             |
| ------ | ------------------------------------------ | ---------------------------------------------------------------- |
| 数据源 | 平台累计值 `clicks`/`favs`/`praises` | 同代分位 `fav_pctl`/`click_pctl` + `pr`/`pctl_pr` + 深榜 |
| 优点   | 与官方 app 心智一致，易懂                  | 剔除书龄与曝光分母，能发现被埋没的好书                           |
| 缺点   | 头部永久高曝光（报告 02/08 马太效应）      | 自定义指标有解释成本                                             |

累计 `clicks` 混杂书龄与曝光分母（报告 02/08），novly 模式等于把马太效应原样搬进来；
量化指标为破此局而造，数据侧已 ready（种子两套口径并存，§4.1）。

## 2. 展示层与推荐层解耦

用户选的模式只决定"怎么看榜单"，不决定"后台推什么"：

- novly 模式 → 展示层按平台累计值渲染（只读）；
- 推荐层 → 统一走量化信号（分位/PR/深榜/form），推荐结果注入两种模式的发现流；
- 推荐不解释指标，只解释书。

这绕开"量化指标用户看不懂 → 量化榜变摆设"的死结：推荐不需要用户主动选，一直在后台生效。

## 3. 推荐层设计

### 3.1 口碑驱动，非协同过滤

无用户行为日志（数据集是一次性快照），推荐是内容/口碑推荐：
"同代分位接近 + 题材相同 + PR 高"→ 高分冷门书。信号源本身剔曝光、剔书龄，天然带发现属性。

### 3.2 信号白名单（红线）

推荐打分只能用：`fav_pctl` / `click_pctl` / `praise_pctl` / `pr` / `pctl_pr` /
`deep_ranks` / `books.form`（附录 D 实施后）/ `cqs`（运行时质量分，见 18）。

`lqs` 已随 schema v8（2026-11-24）物理删列——原只由 `pr` 的「世代 × 收藏档」分位与
归一化篇幅构成、不含任何原始累计值；接入规格见 `/docs/lqs-ranking-integration.md`
（历史归档），现行推荐口径见 18。

> **实施状态（2026-11-24）**：app 开发主线仍是**经典模式**（展示层只读平台
> 累计值，经典榜排序键 `clicks` 不变）；推荐层已按最小完备接入
> （quantitative-mode-metrics §4 首期档）：发现流 = `GET /strata/recommend` ——
> long/dialogue/medium 走 cqs 流（见 18），short/ip_collab 回退纯 `fav_pctl` 流
> （两级 lqs 流已随 schema v8 移除；游标保持 3 段 "0|favpctl|nid" 语法，历史规格
> `/docs/lqs-ranking-integration.md` 归档）。`mqs` 归档未接线
> （中篇域由 cqs 流覆盖），`/docs/medium-quality-score.md` 保留备查；
> `ref_pctl` 未启动。

**严禁** `clicks` / `favs` / `praises` 原始累计值进入推荐打分——否则马太效应从后门渗入。
原始值只用于展示层锚点。

### 3.3 候选池门槛

`pr` 要求 `favs ≥ 10`（报告 21）；分位薄的世代/题材推出来是噪声。需显式可推荐门槛
（gen 内样本量下限、`favs ≥ 10`），具体数值待拍板。

### 3.4 反馈回路隔离（长期红线）

上线后用户点击会变成平台 clicks；若这些 clicks 被当信号即回到平台老路。两条数据流
从第一天起物理隔开：展示/诊断流（平台累计值，只读不回流）与推荐信号流（量化字段 +
未来的自有用户反馈）。

## 4. 数据基础与端点映射

种子 `books`（28 列）并存原始值（`clicks/favs/praises/words`）、量化值（分位五列）、
世代键（`est_year/est_date/est_conf`）。

| 模式       | 端点                                               | 口径                                                 |
| ---------- | -------------------------------------------------- | ---------------------------------------------------- |
| novly 展示 | `GET /strata/rankings/classic`                   | 原始累计值                                           |
| 量化展示   | `GET /strata/rankings/deep?year=&metric=&limit=` | 世代内 Top200，meta 带 `pool=universe`+`in_seed` |
| 推荐层     | 后端内部                                           | 白名单字段（§3.2）                                  |

深榜 `in_seed=false` 的 nid 走搜索/详情兜底，不得过滤（见 10 文档 §2）。

## 5. 分页与「到底」策略

| 页面        | 策略                             | 理由                                  |
| ----------- | -------------------------------- | ------------------------------------- |
| 发现流      | 无限滚动（游标分页，每批 20 本） | 种子内有封面的书，滑不到底 |
| 分位榜/深榜 | 有限 Top200，底部引导进发现流    | 榜单价值在有限精选                    |
| 搜索        | 有限                             | 目标明确场景                          |

发现流红线：

1. 游标分页（非页码），稳定排序保证不重不漏；
2. 防重复优先于防触底（推荐层负责去重与多样性打散）；
3. 无封面书不进发现流候选——release 用补全后的优化种子（11 提案），只约束上线时种子版本。

## 6. 形式维度（附录 D 实施后）

官方 genre 只按主题分 9 类、无形式轴。`books` 主表加互斥单值 `form`
（invalid/short/medium/long/dialogue/ip_collab，invalid 不入种），**权威判定口径见 `docs/form-definitions.md`**：

- 核心收益是过滤噪声：长篇榜排除 `dialogue`（对话可长至 88 万字）；短篇榜排除
  `medium`（中篇并入会让 Top200 里 197/200 是中篇）；保留中篇档；互动并入 dialogue；
- `ip_collab` 靠征文名称确定性判定（名单封闭，见 13）；
- 榜单/发现流按 `form` 过滤、给独立入口；`form` 不参与分位计算。

## 7. 可解释性（待拍板）

1. 默认模式建议 novly（建立信任），详情页/相关推荐/深榜入口注入量化发现；
2. 量化模式文案用"你可能错过的书"，不做"更科学的榜"式说教；
3. 分位永远与绝对值并列展示（"分位 99.9% + 收藏 43,161"），分位是解读层非替代层；
4. 数据薄处（小世代/题材）诚实降级，不硬套数字。

## 8. 明确不做

平台 clicks 回流推荐打分；协同过滤；说教式量化文案；因 MVP 降低数据标准；
改报告 10 / 定年。
