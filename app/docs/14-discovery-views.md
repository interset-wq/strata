## 1. 发书日历（P1）

### 1.1 功能

按 `est_date` 日/周/月聚合种子书，浏览"同期出发的作品"；选一批同期书加入
watchlist（`role=peer` 同期对照，07）即构成作者工作台的对照组。这是竞品
验证过的作者侧刚需，而我们的定年数据（281 锚点，内插中位误差 2 天 / P99 9 天）
比竞品抓的"首章发书日期"更稳——**且完全不需要任何网络请求**。

### 1.2 查询

```sql
SELECT nid, title, author, genre, favs, cover_url, est_date, est_conf
FROM seed.books
WHERE est_date BETWEEN :from AND :to
ORDER BY favs DESC LIMIT :n;
```

30,878 行全表扫描 <10ms，**不建新索引**（est_date 无索引；按代浏览走
`idx_year_favpctl` 已够）。

### 1.3 口径约束（UI 必须标注）

| 约束 | 规则 |
| --- | --- |
| 日期语义 | `est_date` 是**作品创建时间估计**，非竞品的"首章发书日期"（我们无章节级时间）。UI 标「入库日期（估计）」 |
| 精度分档 | `est_conf=exact` = 官方 addTime，日粒度精确；`high`/`mid` = 内插，中位 2 天，**按周/月聚合稳健、按日聚合需标注**；`low` = 锚点间隔 >365 天，只入月视图，不入日视图 |
| 右删失 | 默认落点 = `/calendar` 响应 `bounds.last`（库内 est_date ∪ calendar_universe 两层并集）；**前后翻页不设上限**（2026-11-27 用户裁定：月/周/日/VIP 均可越过 bounds，越界无数据显示空态；年月选择器 2000–2100）。bounds 缺失时回退 genMin..genMax |
| 估计覆盖 | **App 层判定**（种子与引擎不改，用户裁定「不需要动种子」）：`/calendar` `bounds.last` 不在月末 → 该月数据不完整，估计上界 = 上一个完整月的月末（当前 2026-09-30）；末日恰在月末则该月完整、照常估计。上界之后的月/周/日不显示任何全平台数字，只显示内置数，并注明「数据不完整，全平台估计只到 YYYY年M月」（2026-11-26 用户裁定：高误差区直接不估算） |
| 排序 | 每格内按 `favs` 降序；`est_conf` 徽标随条目显示 |

### 1.4 与双模式的衔接

日历是发现流（12）的**新视图**：novly 模式按日浏览、收藏入架；
（E.30：同期分位徽标随分位列退役）推荐层不消费日历——日历只改变浏览路径，不改打分。

## 2. 增长榜多窗口（P2）

### 1.5 签约升 VIP 预告层（2026-11-24，官方 PreOrder 端点接入）

日历粒度段「VIP」（2026-11-24；2026-11-26 去「日」段后为月/周/VIP 三段）：官方每周签约升 VIP 推荐期次（端点事实与语义实证 →
docs/sfacg-endpoints.md §7.5，引擎代理 `/strata/preorder`，契约 → docs/08）。

- **语义（2026-11-25 用户裁定）**：官方「上架」= 签约升级为 VIP；我们此前
  的「上架」语义（≈入库/创建）与官方完全不符，全面改用官方语义。
  期次徽标 = 主编推荐 / 签约升级。
- **形态**：粒度切换加「VIP」段；内容 = 聚焦周周六期次的编辑精选清单
  （3–10 本）：封面 + 标题 + 徽标 + tags；期次复用既有的前后导航
  （步进一周）。
- **库内外分流**：`in_seed` 书点击进详情页；库外书不可进详情（上游无
  作者/字数/收藏），intro 内联展示。
- **口径红线**：`date` = 预定签约升 VIP 周（官方编辑精选，非全库枚举），
  与 est_date「上架日期（估计）」（≈入库/创建）是两套口径，分列展示、
  不得互推（§7.5 实证：date 恒晚于 est_date 13–110 天，零反例）。

**扩容（2026-11-28 用户定）：VIP 段两条官方数据线并列**。同一周六期次下：
① 预约层（`/strata/preorder`，PreOrder.ashx JSON）仍是编辑精选预告，带
「主编推荐」徽标 + intro；② 新增**专题层**（`/strata/vippush`，vipPush H5
直出页解析，§7.6）展示当周上架全书（11-28 期 26 本），只有标题/封面/题材/
标签，复用同款书行、库外同样 rank-seed 预写收录。两段各有独立段头与
loading/error/重试，共用页尾两个官方页入口；互不相同、不可合并替代。
引擎侧两段均 24h 期次缓存 + 前台限速，契约见 `docs/08-engine-api.md`。
- **在线层**：限速器前台车道 + 24h 期次缓存；离线/失败时该视图显示
  失败可重试，不影响月/周/日的种子视图。
- **时间边界（2026-11-27 用户裁定）**：VIP 是在线期次，不受 seed 右删失
  限制；首次进入默认当前周，前后翻周无上限，可查看 bounds.last 之后的
  期次（例如 2026-11-27 时的下一周）。



### 2.1 功能

涨幅榜从 30 天单档扩展为 **24h / 7d / 30d** 三档。数据全部来自 `observations`
（U3 详情抓取 + U5 订阅已覆盖），`delta = favs(最新观测) − favs(窗口内最早观测)`，
窗口内不足两条观测 → 该窗口显示「—」。**零新增请求**。

### 2.2 红线（沿用 05 §5）

- 成熟度规则不变：1 条观测只显当前值；≥2 条但窗口不足显示"观测中"；
  窗口内 ≥2 条才显示涨幅；样本不足整榜隐藏，不做降级展示；
- 纵向同书对比，属兴趣信号——**不进推荐打分**（12 §信号白名单）；
- 跨书不可横比曝光口径：收藏增量可横比（同为收藏计数），点击增量不做
  （`click_delta_30d` 恒 NULL 的定案不变）。

### 2.3 月票排除

竞品有月票增长维度；我们 `book_meta.tickets` 只存当期值（05 §6），无时序，
**不做月票增长**。

## 3. 观测时序桶分层（P3，悬置）

竞品方案：hourly 桶留 96h + daily 桶永久，体积极小。本项目 `observations`
180 天全量保留（02 §3）当前无压力；当 U5 订阅规模使 user.db 增长到需要裁剪时，
把 30 天前的观测聚合成 daily 桶（每日保留最早/最晚两条）再删原始行，曲线
不失真。**记入 06 待决，不在 v1 实现**。
