# APP 设计文档 14：发现流增强视图——发书日历与增长窗口

> **设计定案 v1.0**。来源：竞品 `sf.iluyf.com`（上游 `github.com/jiuweiyaya/sfacg-rank`）
> 借鉴评估。原则：**只用已有数据在展示层长出新视图，不新增任何 HTTP 请求**。
> 双模式契约见 12；观测成熟度红线见 05 §5；定年口径见 `docs/metrics-definitions.md` §1.1。

## 0. 结论

| 视图 | 数据来源 | 新增请求 | 优先级 |
| --- | --- | --- | --- |
| **发书日历** | `seed.books`（est_date 定年） | **零** | **P1，最容易落实** |
| 增长榜多窗口 | `observations` 时序 | **零** | P2 |
| 观测时序桶分层 | `user.db` 存储策略 | — | P3，存储压力出现再启用 |

不学：定时全量重扫（竞品每小时全抓 1,650 本，覆盖窄且把命运绑在站方容忍度上；
本项目"请求量=兴趣量"+ 种子发版补覆盖，可持续性更强）；静态站+浏览器排序
（本地引擎是同哲学的更强形态，无迁移价值）。

## 1. 发书日历（P1）

### 1.1 功能

按 `est_date` 日/周/月聚合种子书，浏览"同期出发的作品"；选一批同期书加入
watchlist（`role=peer` 同期对照，07）即构成作者工作台的对照组。这是竞品
验证过的作者侧刚需，而我们的定年数据（104 锚点，内插中位误差 2 天 / P99 9 天）
比竞品抓的"首章发书日期"更稳——**且完全不需要任何网络请求**。

### 1.2 查询

```sql
SELECT nid, title, author, genre, favs, cover_url, est_date, est_conf
FROM seed.books
WHERE est_date BETWEEN :from AND :to
ORDER BY favs DESC LIMIT :n;
```

30,878 行全表扫描 <10ms，**不建新索引**（est_date 无索引；按代浏览走
`idx_year_favpctl` 已够）。

### 1.3 口径约束（UI 必须标注）

| 约束 | 规则 |
| --- | --- |
| 日期语义 | `est_date` 是**作品创建时间估计**，非竞品的"首章发书日期"（我们无章节级时间）。UI 标「上架日期（估计）」 |
| 精度分档 | `est_conf=exact` = 官方 addTime，日粒度精确；`high`/`mid` = 内插，中位 2 天，**按周/月聚合稳健、按日聚合需标注**；`low` = 锚点间隔 >365 天，只入月视图，不入日视图 |
| 右删失 | 内容上界 `content_end=2026-05-03`：种子只覆盖 2007..2025（`gen_min..gen_max`），日历**不显示 2026**，与世代榜口径一致 |
| 排序 | 每格内按 `favs` 降序；`est_conf` 徽标随条目显示 |

### 1.4 与双模式的衔接

日历是发现流（12）的**新视图**：novly 模式按日浏览、收藏入架；量化模式可在
同日期格内叠加 `fav_pctl` 徽标（同期分位，一步到位看"这本书在同期算什么水平"）。
推荐层不消费日历——日历只改变浏览路径，不改打分。

## 2. 增长榜多窗口（P2）

### 2.1 功能

涨幅榜从 30 天单档扩展为 **24h / 7d / 30d** 三档。数据全部来自 `observations`
（U3 详情抓取 + U5 订阅已覆盖），`delta = favs(最新观测) − favs(窗口内最早观测)`，
窗口内不足两条观测 → 该窗口显示「—」。**零新增请求**。

### 2.2 红线（沿用 05 §5）

- 成熟度规则不变：1 条观测只显当前值；≥2 条但窗口不足显示"观测中"；
  窗口内 ≥2 条才显示涨幅；样本不足整榜隐藏，不做降级展示；
- 纵向同书对比，属兴趣信号——**不进推荐打分**（12 §信号白名单）；
- 跨书不可横比曝光口径：收藏增量可横比（同为收藏计数），点击增量不做
  （`click_delta_30d` 恒 NULL 的定案不变）。

### 2.3 月票排除

竞品有月票增长维度；我们 `book_meta.tickets` 只存当期值（05 §6），无时序，
**不做月票增长**。

## 3. 观测时序桶分层（P3，悬置）

竞品方案：hourly 桶留 96h + daily 桶永久，体积极小。本项目 `observations`
180 天全量保留（02 §3）当前无压力；当 U5 订阅规模使 user.db 增长到需要裁剪时，
把 30 天前的观测聚合成 daily 桶（每日保留最早/最晚两条）再删原始行，曲线
不失真。**记入 06 待决，不在 v1 实现**。
