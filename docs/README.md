## 三句话版本

1. **官方 11 个榜回答的是「现在什么火」，我们回答「过去什么好」。** 种草榜 15 分钟刷新、月票按月清零、完结榜也只是当期口径——没有任何一个榜用的是累计成绩。一本 2015 年完结的神作不会给站方带来收入，所以永远进不去；而它的成绩实测不随时间衰减。
2. **内置的不是全库，是「榜位闭包 ∪ 标签闭包 ∪ banner 全集」19,856 本（gzip 实测 2.4 MB）。** 用户的消费深度决定数据量：24.6 万本里只有约 1 万本能产生有意义的名次；标签再补 8 千本，否则小众标签会空；banner 再补 65 本——那批人气不高却被站方力推的书，任何 top N 都截不到。
3. **详情靠端上按需抓，抓到的顺手回填种子；v1 全程没有服务端。** 用户点开一本书，详情 API 一次返回全指标 → 本地立即更新 + 记一条观测日志 → 种子替换后重放日志，数据不丢。搜到未收录的书当场收录。种子走 GitHub Release 静态分发，与 App 版本解耦。**服务端是第三期的事**——等自己的爬虫跑通、且端上数据证明「用户看到的书有 5% 我采不到」时再建，判据写在 `architecture.md` §6.5。

## 五个产品入口（对照 App 的 11 个榜）

App 有 11 个榜：推荐 / 人气 / 畅销 / 新书 / 收藏 / 月票 / 打赏 / 种草 / 粉丝 / 角色 / 完结。
**它们全部是「当期榜」**——种草榜 15 分钟刷新，月票/打赏按月清零，完结榜也只是
「完结的书里现在最火的」。官方回答的是「现在什么火」，没有一个是「过去什么好」。

| 入口 | 定义 | 官方 11 榜里有没有 |
| --- | --- | --- |
| **年度殿堂** | 每年 banner 书里人气第 1（**19 本，覆盖 2006–2025**） | 无。一年一本，把「每个时代的王者」摆一屏 |
| **一口气读完** | 完结 + `word≥100万` + `view≥10万`（1,422） | 部分有「完结榜」，但那是当期口径；我们按累计成绩，且要求够长 |
| **被埋没的好书** | `ptype=2` + 完结/断更 + `view≥10万`（4,930） | **完全没有**。免费书不进任何榜 |
| **考古** | 完结 + `add_time` 早 + 5 年无更新 + `view≥50万`（956） | 无。无任何推荐位 |
| **官方精选** | `banner=1`（667） | 散落在各推荐位，**从未聚合成一个入口** |
| **年代轴** | `catalog.add_time` 按年分桶 + `era_stats` 语境（11 年） | 完全无。官方全部是当期口径 |

> 差异化不靠「官方漏了哪个维度」，而靠**时间观不同**：
> 官方是「现在有多火」，我们是「历史上有多好」。一本 2015 年完结的神作
> 不会给站方带来任何收入，所以永远不会出现在那 11 个榜里——
> 但它的成绩实测**不随时间衰减**（5 年前完结 536 万 ≈ 1 年内完结 511 万）。

## 唯一要正面承认的对手维度：角色榜

App 有「角色榜」，说明**角色确实是读者找书的方式**——这印证了我们标签里 `role` 一类
（女性主角 / 嫁人 / 倒追 / 纯爱）的方向是对的。区别是：
官方只能给「现在最热的角色」，我们能给「所有带倒追标签的书，按成绩排」。
