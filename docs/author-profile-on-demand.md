# 作者资料：App 按需抓取（设计定案）

> **定位**：作者详情页资料的「App 按需抓取」设计定案——不预采、不随种子内置。
> **状态**：现行权威（用户裁定 2026-11-20）；`app/` 实现由开发 agent 负责，本文只记数据与抓取契约、不规定其代码结构。
> **权威范围**：本文唯一维护作者资料的触发流程、DOM 选择器、返回契约、限速与失败降级边界。
> **口径**：所有计数/比例/误差均为快照现算值，仅供参考，禁止硬编码进代码；API 覆盖不到的信息以手机 App 为准。
> **更新日期**：2026-11-22。

## 0. 为什么只能按需取

作者 `intro` 和头像不在 App API 的 18 个业务字段里，只能从 Web 详情页取：移动版
`m.sfacg.com/b/{nid}/` 给头像 + 作者名 + 作品集、但**无 intro**；PC 版 `book.sfacg.com/Novel/{nid}/`
才有 intro（§2 实证）。两项随作者改动属**快照值**、内置种子会过期；作者页本就有该作者的书，任选一本即可。

## 1. 触发与取数

1. 用户打开作者详情页，页面先用种子已有书目正常渲染，不等网络。
2. 从该作者名下选一本书（收藏最高或列表第一本），对**移动版详情页**发一次请求取头像/作者名/作品集；
   **仅当要展示 intro** 时再追加一次该书 **PC 详情页**请求。选书只在已有数据里挑，**不额外请求作者书目列表**。
3. 解析作者区 → 填入页面；失败/空值按 §4 降级，**不阻塞书目列表**。
4. 同一作者短时间重复打开可用进程内缓存（运行时优化，非预置数据）。

身份匹配：显示名 `casefold()`（大小写不敏感）、**空格敏感**；能命中 `dataset/author_ids.jsonl`
时用 `authorId` 分组更稳（显示名可改）。头像 URL 里的数字（如 `.../avatars/upload/APP/1708/...`）**不是** `authorId`，不要反推。

## 2. DOM 选择器

### 2.1 移动版 `m.sfacg.com/b/{nid}/`（默认基线，实证 172004 / 477889 / 2237 / 4131）

作者区 `<ul class="book_Author">`：

| 内容 | 选择器 | 处理 |
|---|---|---|
| 头像 | `.book_Author li:first-child img@src` | 同 PC，`common/0.gif` 按缺省头像处理 |
| 作者名 | `.book_Author li:first-child` 的 `img` 后文本 | 与 `authorId` 分组时以 id 为准 |
| 作品集 | `.book_Author li:nth-child(2) a@href + a` 文本 | `/b/{nid}/` 链接，即该作者的书；**移动版不截断 = 作者全部作品**（用户 2026-11-22 裁定；**PC 版作品集会截断**，不得用作书目来源） |

**移动版没有 intro**：PC 上 172004 的「新人作者，请多包涵」在移动版全文不存在；作者区第二栏
「请勿转载 / 未经网站或授权方许可」是站点文案、不是作者自述。手机 App 别处的作者自述是另一数据源，先问维护者。

### 2.2 PC 版 `book.sfacg.com/Novel/{nid}/`（仅取 intro 时请求，实证 nid=172004）

| 内容 | 选择器 | 处理 |
|---|---|---|
| 简介 | `.author-box .author-desc` | 纯文本、压缩空白；**可为空串**（有些作者没写），不编造、不拿书籍简介顶替 |
| 头像 | `.author-box .author-mask img@src` | URL；`common/0.gif` 是缺省头像，按「无头像」占位 |
| 显示名 | `.author-box .autor-name` | class 拼写就是 `autor`（页面如此）；仅展示，身份以 `authorId` 为准 |

兜底：`.author-box` 缺失时可从 `.author-info` 取头像与名字（`.author-name span`），但 intro 仍
只能来自 `.author-box .author-desc`，取不到即空串。

判活：本站 HTTP 状态码零信息量（无效 nid 也返回 200）；页面含「小说不存在」视为死亡，
不对该 nid 重试。不取正文、不登录、不带用户态 cookie。

## 3. 返回契约（给 UI 的数据形状，非既有端点）

建议返回以下并集字段；端点名由开发 agent 定：

| 字段 | 类型 | 说明 |
|---|---|---|
| `nid` | int | 用来取作者资料的那本书 |
| `author_name` | string | 页面显示的作者名，可能为空 |
| `author_intro` | string | **只有 PC 版有**；可为空串（正常值），移动版为 NULL/缺省空 |
| `author_avatar` | string | URL，缺省图为 `common/0.gif` |
| `works` | array | 可选：移动版 `.book_Author` 作品集（nid + 标题）；本地已有则不重复请求 |
| `offlibrary` | array | = `works` − `seed.books`（引擎差集，保持页面序）：作者页「其他作品」区块（2026-11-22 加）；`works` 本身仍是官方全量 |
| `verdict` | string | `ok` / `dead` / `error`，供 UI 降级 |
| `observed_at` | string | 抓取日期；头像与简介随作者改动，按快照看待 |

不为「作者全部作品」单独开端点：移动版作品集是同一次请求副产物，本地已有作者书目时直接读本地。
作者页书目定案（2026-11-22）= **库内种子时间轴（`/author-books`，分年分组）+ 「其他作品」区块**（`offlibrary` = 作品集 − seed，置顶区块头 + 逐行标题/nid）；库外书点击走 rankSeed 预写 → 详情页（与官方榜单/清单页同一条收录链路），完整数据由后台 refresh 补全。作者页改版（概览卡 / 代表作 / 时间轴增强，2026-11-22）定案在 `app/docs/17-author-dimension.md`；书目数据源仍是本端点 + offlibrary 区块。

## 4. 限速与失败降级

- 复用引擎既有详情页抓取通路与全局限速（含拨号/超时配置），**不另起无节流的请求**；
  移动版、PC 版各至多一次；失败不重试阻塞前台，PC 失败不影响移动版已拿到的头像/名字/作品集。
- 网络失败、页面改版、死亡页 → `author_intro=""`、`author_avatar=""`，页面展示缺省头像、
  隐藏简介区；作者名与书目仍从本地种子显示。
- 不写 `seed.db`（只读）；是否把成功结果写入 `user.db` 作短期缓存由实现方决定，
  即便不写也不影响功能，故不新增种子列、不改 schema。

## 5. 边界

- 这是**作品详情页的副产物用法**，不改变 form/书架/watchlist 的任何口径。
- 分析侧 `analysis/fetchers/probe_web_dialogue.py::author_fields()` 是同组选择器的取样参考
  （核验 DOM 结构），**不是 App 数据来源**；不要为作者页跑全量作者预采。
- 上游页面改版，按 §2 选择器先改解析与测试再更新本文；字段含义变更先问维护者。
