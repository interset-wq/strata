# 作者资料：App 按需抓取（设计定案，不是内置数据）

> **用户裁定 2026-11-20**：作者详情页的资料**不预采、不随种子内置**。App 打开作者页时，
> 自动对「该作者名下的某一本书」的详情页发起请求，从 DOM 里取作者资料。
> 用户随后提示移动版也可能可取：实测移动版给**头像/作者名/作品集**，**intro 仍只有 PC 版有**（§2）。
> 本文只记数据与抓取契约；`app/` 的实现由开发 agent 负责，本文不规定其代码结构。

## 0. 为什么只能这样取

- 作者 `intro` 和头像**不在 App API 的 18 个业务字段里**，只能从 Web 详情页取：
  - 移动版 `https://m.sfacg.com/b/{nid}/`：头像 + 作者名 + **作品集链接**（该作者的书），但**无 intro**；
  - PC 版 `https://book.sfacg.com/Novel/{nid}/`：intro + 头像 + 作者名（实证见 §2）。
- 这两项随作者改动（简介会改、头像会换），是**快照值**，不是书目 immutable 属性；
  内置进种子会过期，且种子按发布版本分发，升级才更新。
- 取数成本很低：作者页本来就有该作者的书，任选一本即可，每页至多一次请求。
  引擎既有详情页抓取本就以移动版为基线——只要头像/名字/作品集，**不需要新增 PC 通路**；
  要 intro 才追加一次 PC 请求。

## 1. 触发与取数

1. 用户打开作者详情页；页面先用种子里已有的书目信息正常渲染，不等待网络。
2. 从该作者名下选一本书（建议选收藏最高或列表第一本），对**移动版详情页**发一次请求，
   取头像/作者名/作品集；**仅当作者页要展示 intro** 时，再追加一次该书的 **PC 详情页**请求。
   选书只在已有数据里挑，**不额外请求作者书目列表**。
3. 解析作者区 → 填入页面；失败/空值按下文降级，**不阻塞书目列表**。
4. 同一作者短时间内重复打开可用一次进程内缓存；缓存是运行时优化，不是预置数据。

身份匹配沿用项目约定：显示名 `casefold()`（**大小写不敏感**）、**空格敏感**；
能在 `dataset/author_ids.jsonl` 命中时用 `authorId` 分组更稳（显示名可改）。
头像 URL 里的数字（如 `.../avatars/upload/APP/1708/...`）**不是** `authorId`，不要反推。

## 2. DOM 选择器

### 2.1 移动版 `m.sfacg.com/b/{nid}/`（默认基线，实证 172004 / 477889 / 2237 / 4131）

作者区是 `<ul class="book_Author">`：

| 内容 | 选择器 | 处理 |
|---|---|---|
| 头像 | `.book_Author li:first-child img@src` | 同 PC，`common/0.gif` 按缺省头像处理 |
| 作者名 | `.book_Author li:first-child` 的 `img` 后文本 | 与 `authorId` 分组时以 id 为准 |
| 作品集 | `.book_Author li:nth-child(2) a@href + a` 文本 | `/b/{nid}/` 链接，即该作者的书；可作作者页书目来源 |

**移动版没有 intro**：PC 上 172004 的「新人作者，请多包涵」在移动版全文里不存在；
作者区第二栏固定的「请勿转载 / 未经网站或授权方许可」是站点文案，不是作者自述。
若你在手机 App 里看到别处的作者自述，那是另一个数据源，先问维护者，不要拿它推断 Web 结构。

### 2.2 PC 版 `book.sfacg.com/Novel/{nid}/`（仅取 intro 时才请求，实证 nid=172004）

| 内容 | 选择器 | 处理 |
|---|---|---|
| 简介 | `.author-box .author-desc` | 取纯文本、压缩空白；**可为空串**，用户明确有些作者没写，不编造文案、不拿书籍简介顶替 |
| 头像 | `.author-box .author-mask img@src` | 取 URL；`common/0.gif` 是站点缺省头像，按「无头像」显示占位图 |
| 显示名 | `.author-box .autor-name` | class 拼写就是 `autor`（页面如此）；仅用于展示，身份仍以 `authorId` 为准 |

兜底：若 `.author-box` 结构缺失，可从 `.author-info` 取头像与名字（`.author-name span`），
但 intro 仍只能来自 `.author-box .author-desc`，取不到就是空串。

判活：本站 HTTP 状态码零信息量（无效 nid 也返回 200）；页面含「小说不存在」视为死亡，
不对该 nid 重试。不取正文、不登录、不带用户态 cookie。

## 3. 返回契约（给 UI 的数据形状，非既有端点）

建议返回下面这组字段（移动版 + 可选 PC 版的并集）；具体端点名由开发 agent 定：

| 字段 | 类型 | 说明 |
|---|---|---|
| `nid` | int | 用来取作者资料的那本书 |
| `author_name` | string | 页面显示的作者名，可能为空 |
| `author_intro` | string | **只有 PC 版有**；可为空串，空是正常值，移动版抓取时为 NULL/缺省空 |
| `author_avatar` | string | URL，缺省图为 `common/0.gif` |
| `works` | array | 可选：移动版 `.book_Author` 的作品集（nid + 标题）；本地已有则不重复请求 |
| `verdict` | string | `ok` / `dead` / `error`，供 UI 决定降级 |
| `observed_at` | string | 抓取日期；头像与简介随作者改动，按快照看待 |

不要为「作者全部作品」单独开抓取端点：移动版作品集是同一次请求的副产物，
本地种子已有作者书目时直接读本地即可。

## 4. 限速与失败降级

- 复用引擎既有的详情页抓取通路与全局限速（含拨号/超时配置），**不要另起一套无节流的请求**；
  移动版、PC 版各至多一次；失败不重试阻塞前台。PC 失败不影响移动版已拿到的头像/名字/作品集。
- 网络失败、页面改版、死亡页 → `author_intro=""`、`author_avatar=""`，页面展示缺省头像、
  隐藏简介区；作者名与书目仍从本地种子显示。
- 不写 `seed.db`（只读）；是否把成功结果写进 `user.db` 作为短期缓存由实现方决定，
  但即便不写也不影响功能，故不新增种子列、不改 schema。

## 5. 边界

- 这是**作品详情页的副产物用法**，不改变 form/书架/watchlist 的任何口径。
- 分析侧 `analysis/fetchers/probe_web_dialogue.py::author_fields()` 是同一组选择器的
  取样参考（用于核验 DOM 结构），**不是 App 的数据来源**；不要为了作者页去跑全量作者预采。
- 上游页面若改版，按 §2 的选择器先改解析与测试，再更新本文；字段含义变更要先问维护者。
