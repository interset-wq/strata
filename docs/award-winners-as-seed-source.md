## 结论

1. **入种口径已定案**：净获奖 **911 本**（11 届，入种唯一数据源 `contest_awards_normalized.csv`），
   剔除 **602 本入围污染**、**140 本库外**走详情补采；获奖**只作筛选/徽标，不进排序打分**（避免与 `fav_pctl` 双重计权）。
2. **数据通路成立**：获奖名单不在 API，而是写死在活动页里的静态数据（四代形态见 `contest-roster-fields.md`，逐届明细见本文「事实」节）。
   一条 GET 即得全量名单，无分页、无鉴权；字段只有 nid + 书名，**成绩字段要去 dataset/app 另取**。
3. **「获奖=优质」被数据强力证实**：真实获奖子集收藏中位 1112–8372、同代分位中位 0.96–0.97，62–64% 落在同代 p90 以上。
4. **关键陷阱**：活动页 JS 里不是每组数组都是获奖——初审/复审模块（favs 中位 4–16）与获奖模块混在一起，
   整包抓会把入围书当获奖，稀释优质池。原台账 1,480 行中 602 本系入围，已全部剔除。
   （宽口径 1,411/412 仅作方向证据，见 §3，非入种口径。）

## 操作：入种定案与工程交接

### 4. 种子表设计（已定案）

现有 `seed.db` schema v4 有 5 张表（books / book_tags / deep_ranks / calendar_universe / seed_meta）。
获奖是作品级属性 + 可分级 + 多届累积，**新增一张独立表**（不塞进 books 列）：

```sql
CREATE TABLE contest_awards(
  nid        INTEGER NOT NULL,
  edition    TEXT    NOT NULL,   -- '十二征'/'十三征'/... 或 year
  award      TEXT    NOT NULL,   -- '金奖'/'银奖'/'铜奖'/'优秀奖'
  category   TEXT,              -- 长篇/中篇/短篇/对话（若能从页面判定）
  source_nid TEXT    NOT NULL,   -- 来源活动页标识 zw20240504
  PRIMARY KEY(nid, edition)
);
```

理由：不与 books 的 form/分位耦合（获奖是外加标签、不是排序池分母，呼应 E.23）；可多届（独立表天然支持）；
可增量（新届只追加本表 + 补 books）；App 专页可按 `edition/award/category` 聚合。

### 5. 专门页面的数据来源

`contest-display-in-app.md` 的三层数据可加第四层：本地种子 `contest` 字段（书页标签）、征文清单 API（清单浏览页）、赛事元数据（`analysis/references/contest-editions.md` 静态表）、**获奖表 `contest_awards`（来源为活动页四代形态，见 `contest-roster-fields.md`）**。专页排序仍用 `fav_pctl`、**不造新指标**；获奖本身作筛选条件、不作打分项。

## 边界与降级

- **数字现算仅参考**：favs 随快照变化，别把 186/1112/0.97 写进代码。
- **活动页是赛事期快照**：获奖名单是最终态、不会变，比参赛清单更适合做种子；但存放形态分四代
  （早期静态页无 → 十二/十三征 JS 静态 JSON → UUID 页 HTML `data-nid` → 日期式 Vue render 硬编码），
  提取器须都兼容（见 `contest-roster-fields.md`），早期静态页时代无获奖名单、本通路不覆盖。
- **module id 跨届变**：每届要现场判定获奖模块，不能硬编码；`alt` 纯数字的八征冬须走 HTML 结构恢复、不臆造奖项名。
- **获奖 ≠ 当前优质**：获奖是历史时点认可，书可能后来断更/变僵尸，仍要走 form/僵尸过滤。
- **奖项等级逐档状态**：净获奖 911 本里 44 本有可靠中文奖项名；其余 867 本标「待逐档标定」。**入种不依赖逐档名**——获奖本身是筛选标签。
- **独立赛事获奖未采（2026-11-22 实证）**：本地 contest 反查新增的独立赛事（IP 联动/题材/对话节日，见 `contest-roster-harvest.md` §2.8；原 29 个逐项探查，补漏的 278 按同形态降级）**只有参赛 tagId、无获奖名单**——净 911 本全部来自四季主线 + 点鸭线的 11 届，不覆盖它们。三层叠加导致取不到：① 绝大多数活动页 URL 未取（聚合站只收录主线、书页比赛标签是纯 `<span>` 无 href、随机 UUID 搜索引擎不索引）；② 唯一找到的 `xyzw2018`（经官方资讯站 `news.sfacg.com` 公告给出 URL）属**第 1 代纯图片静态页**，获奖即使存在也写在 `xyla_c*.png` 图里、无 nid 无文本；③ 获奖从不在任何 REST 接口（见 `contest-roster-fields.md` §8 端点探活）。**降级**：这些赛事只保留参赛清单 + favs 方向信号（宽口径、不入种），获奖不采、不臆造。将来用户 App 观测到带 `data-nid`/render 硬编码的第 3/4 代获奖页再补。

**残余待裁定（2026-11-21 已拍板，见 `contest-display-in-app.md` 裁定记录 7）**：

1. 逐档标定 → v1 不做：44 本显示具体奖项名、867 本徽标「征文获奖」；finer 粒度需要时另议（入种不依赖）。
2. 140 本库外补采 → v1 不主动补采：获奖表保留其行、不入 books（§7 已裁定可接受）。
