# 书单展示定案（Booklists in the App）

> **定位**：官方书单展示层的唯一权威——枚举方式、缓存、join 与降级以本文为准。
> **权威范围**：本文唯一维护书单展示设计；接口字段契约见 08（`/strata/booklists` 节）；
> 上游 API 事实（endpoint/expand/字段）来自 2026-11-22 实探（书单 #1 + 作品列表）
> 与 temp/novly 参考实现。
> **更新日期**：2026-11-23。

## 结论

1. **官方 API 无枚举动作**：`pages.sfacg.com/api/HttpProxy` 只接受
   `actionName=/bookList/{id}`（元数据）与 `/bookList/{id}/novel`（作品列表）；
   裸 `/bookList` 探针 HTTP 404（2026-11-22 实探）。枚举只能顺序 id 探测
   （temp/novly 同款方案）；全库约 1272 个书单（近似值，temp/novly 口径）。
2. **窗口探测 + 页不满即到底**：引擎每窗探 10 个连续书单号，**逐个**走
   共享限速器（1s/请求；一次提交 10 个会超 queueCap=8 丢尾部）。首窗
   ≈10 秒（一次性成本），每号原始响应进官方榜单缓存（24h——书单会更新，
   `lastUpdateDateTime` 是证据），当日再访秒回。无效号（data 缺失）确定性
   丢弃并缓存其空结果；窗口有效数 < 10 = 到底（temp/novly 在真实 id 空间
   验证过的语义）。
3. **本地 join 与红线**：详情端点 `BooksByNIDs` join seed——库内作品带
   `in_library=true` + `form` 徽标；库外只带官方字段（不伪造 form/分位，
   docs/12 红线）。书单内官方累计值（charCount→字数 / viewTimes→点击 /
   markCount→收藏）纯展示层，**永不进推荐打分**（docs/12）。库外作品点击
   先 rankSeed 预写再进详情页（收录链路同 roster 行）。
4. **降级**：传输错误 = 502 + UI 重试；无效号（元数据 data 缺失）= 404
   `not_found`；**不做库内兜底**——书单本身就是内容，没有替代品（与
   roster 的库内子集兜底不同：那儿的兜底对象是"参赛规模"）。
5. **入口**：首页长篇 tab 宫格第一格「分类」→「书单」（`/booklists`）。
   用户 2026-11-23 裁定：经典榜单筛选面板已有题材选择，分类路由冗余；
   `/browse?mode=category` 路由保留、首页不再提供入口。

## UI 形态

- **列表页**（`/booklists`）：顶部 #id 跳转框（直跳该号所在窗口）+ 无限
  滚动行卡（#id 主色强调 + 标题 + 简介 2 行 + 作者[VIP] + N 部作品 +
  更新日期）+ 回到顶部（>500px）。首窗加载显示「正在探测书单（首窗约
  10 秒）」进度文案。
- **详情页**（`/booklists/:id`）：头部卡片（#id 标题 + 简介 4 行 + 作者 +
  N 部作品 + 更新日期）+ 作品行卡（官方顺序，无排序控制；封面 44×60 +
  标题 + 作者/题材 + 字数/点击/收藏 MetricBadge（指标行顺序：字数→点击→
  收藏）+ 完结状态 + 逐本推荐语 2 行；库内行叠加 form 徽标）。

## 深化（2026-11-23，用户选定范围）

1. **详情页增强**：头卡加第二行——「库内 x/N」（本地 join 占比）+
   「推荐 N / 收藏 M」（官方 `recommendNum`/`markNum` 累计值）。书单自身
   统计纯展示，**永不进推荐打分**（docs/12 红线）。
2. **首页书单推荐行**：长篇 tab 在官方榜单宽卡之后加 3 个官方书单横排
   文本卡。引擎新端点 `/strata/booklists/recommend`：以 **UTC 日期为种子**
   从 1..1272 随机抽 count（默认 3、上限 10）个号——当日稳定、再访走
   24h 缓存秒回（banner 每日洗牌同款模式，种子在引擎侧算）；无效号自动
   补抽（上限 3×count），整批失效则降级短列表/空（不报错）。UI 加载
   失败/空结果整行隐藏——增益区块，不阻塞首页。
3. **「收录本书单」不做（探尽证据）**：用户选项为"先探、探到才做"，
   三路探针全负——① HttpProxy 候选 action `/novel/{id}/bookList` 返回
   HTTP 404；② PC 详情页全量（nid 292332，6772 字）无书单区块（页面
   区块 = 月票/打赏/投票/作者作品/粉丝/简评/书评/相似/读者印象/火袋/
   投月票/登录）；③ 第三方 DaoSearch 所称"作品页列出收录书单"是其镜像
   站自身页面，非 SF 官方。官方动作不存在，日后出现再探、再议。
4. **书单标题搜索不可行（红线）**：需枚举全库约 1272 号（每号一个限速
   请求），属后台批量抓取，不做。
5. **超时边界（2026-11-23 真机转圈报告修复）**：原实现最坏 10 个串行
   探测 × 客户端 30s 超时 ≈ 5 分钟纯转圈，且 UI 侧无任何超时。现三层
   有界：引擎**逐探测 15s**（`FetchBooklist` 的 `booklistTimeout`——挂死
   请求 15s 内中止，限速器 worker 不再被冻结）→ **窗口级 deadline**
   （列表 30s / 详情 25s / 推荐 20s，到期 502 `upstream_error`）→ **UI
   45s 最后兜底**（`_getOnline` 超时转「官方数据加载超时」错误态 + 重试）。
   重试成本低：逐号 24h 缓存，已成功的号秒回，只重取失败的号。

## 已知局限

- 书单号是稀疏探测空间：「页不满即到底」的语义在真实 id 空间验证过
  （temp/novly 全库浏览可用）；若官方日后在低号段批量废号，列表可能提前
  收尾——届时补一枚举端点探针。
- 详情作品列表无分页（官方一次性返回 `data.items`）；超大书单暂未见
  （#1 = 6 部），届时再议。
