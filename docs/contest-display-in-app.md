## 结论

1. **三源分工，别混**：① 本地种子 `contest` 字段（零请求，档案页骨架 + form/信号徽标）；② 征文清单 API（按需请求，补种子外参赛作品）；
   ③ 赛事元数据——日期内置配置（无清单端点），获奖名单另有活动页来源（不在清单接口里）。
2. **能零请求先做的是「赛事档案页本地视图」**：只用 `seed.books.contest` 聚合即得赛事列表、参赛书、form 分布、头部作品，
   符合「用已有数据长出视图」的既有路线（`app/docs/14-discovery-views.md`）。
3. **清单浏览页最大约束是 tagId 地图**，不是接口本身：地图已补全（四季主线四征起 + 少年/对话线 + 30 个独立赛事，见 harvest §2）；
   四/五/六征的 tagId 藏在静态页 JS 里、旧接口实测可用（2026-11-22 订正），一/二征页面下线、三征参赛展为空才确实无 API；
   sandbox/生产不同号，赛事结束后活动页可能改版/下线——「更早届次拿不到完整清单」仍是局部常态，需降级。
4. **「以我们的形式」= 用已有信号筛选排序，不造新指标**：form 六值、`fav_pctl` 同代分位、已有 `lqs`（推荐层已接入，见 `lqs-ranking-integration.md`）。
   app 主线是 novly/classic，**不引入征文专项指标**，这是展示层新视图，**不进推荐打分**。
5. **获奖入种已定案（净 911），只剩逐档标定未完**：获奖只作筛选/徽标，不进排序打分；`app/` 已解禁，schema v5 由开发 agent 实施中。

### 战略论证：为什么接入征文能缓解「数据落后」（压缩版）

用户判断：接入征文后 app 不必太担心数据落后，因为新世代参加征文的书占比非常高。
**方向成立，但「数据落后」有三层，征文只直接解决书目层。**

| 证据（快照，仅供参考） | 数值 | 口径 |
| --- | --- | --- |
| 库内带 `contest` 占比 | 2016 约 20.0% → 2024 约 59.7% | 报告 15，按创建年、库内 |
| 月票榜上榜书征文占比 | 2016 13.5% → 2024 约 97.8%，2022 后稳定 85–95% | 报告 15，**头部榜单、右截断**，非全部新书 |
| 征文日历 | 四季首尾相接、间隔 0–1 天，启动后 1–3 周进入投稿主体期 | 报告 06 |

**三层数据落后**：

| 层 | 征文能否解决 | 说明 |
| --- | --- | --- |
| 书目层（有哪些新书） | **基本能，最大价值** | 清单给 nid/标题/作者/封面/赛道，覆盖大部分新世代 |
| 成绩层（收藏/点击/状态新鲜度） | **不能** | 清单不含成绩/定年，刷新靠详情抓取写回与用户观测，或种子发版 |
| 覆盖层（是否覆盖全部新书） | **只覆盖一部分** | 2024 库内仍有约 40% 非征文；未参赛短篇清单抓不到 |

**两个不能省的边界**：① 清单给的是「参赛书全集」不是「热门子集」——95,433 本征文书仅 335 本上过月票榜（0.35%），
无成绩字段就无法从中识别热门；② 上榜 ≠ 参赛带来的因果效应——控制 VIP 后征文上榜率反低于非征文（0.67×），
同作者内对照仅 1.18×（报告 15）。**定位**：征文接入 = 书目发现 / 覆盖补强，与详情抓取（成绩刷新）、种子发版（全量基线）互补。
「知道 4 个 API 就够」不成立——四季是 4 条持续系列、每届新增 tagId；详见 `contest-url-api-patterns.md`。

## 事实：三层数据从哪来

| 数据项 | 来源 | 请求 | 稳定性 / 缺口 |
| --- | --- | --- | --- |
| 赛事名 / 届次 | 本地种子 `contest` 字段 | 零 | 单值、99 种取值、约 38.8% 有值；字符串里带「长篇/中篇/短篇/对话」赛道字样 |
| 参赛作品（库内） | 本地种子 `books` | 零 | 只含被扫描抓到的书；短篇欠采已知 |
| 作品 form / favs / fav_pctl | 本地种子 + 用户观测覆盖层 | 零 | 覆盖层优先、种子兜底（05 §3）；库外书没有 |
| 参赛作品（库外） | 征文清单 API | 按需 | 清单里约 29% 的 nid 不在 db，是补全短/中篇的关键 |
| 起止时间 / 赛程节点 | 内置静态配置（从 `analysis/references/contest-editions.md` 导出） | 零 | 官方无端点；配置会过期、随发版更新；早期届次无精确日 |
| 奖项 / 获奖名单 | **活动页来源，四代形态**（见 `contest-roster-fields.md`） | 零/按需（按代） | 第 2 代 JS 静态 JSON 需现场判定获奖模块；第 3 代 UUID 页 `alt` 直给奖项名；逐届明细见 `award-winners-as-seed-source.md` |

### 1. 本地种子层（零请求，先做）

`contest` 是**单值 TEXT**，取值形如「七征长篇」「五征短篇」「2025春季征文」「五征对话小说」——**赛道信息编码在字符串里**。
本地即可按赛事名聚合、按赛道字样粗分，**不需要 tagId**。

- 可得到：赛事枚举、每赛事库内参赛书、这些书的 form / favs / 封面 / 作者 / 定年。
- 得不到：完整参赛清单（欠采书不在）、精确赛道 tagId、赛事日期、获奖信息。
- 约束：旧书参赛是长尾，**不能用参赛书的 nid 下界推赛事启动日**（cohort bulk 下界定年一致晚于启动 9–20 天）。

### 2. 征文清单 API 层（按需请求，补库外）

两套端点按活动页年代分（完整档案见 `contest-roster-harvest.md`，字段见 `contest-roster-fields.md`）：

| | 旧 H5 页（2018–2022） | 新 SPA 页（2023 起） |
| --- | --- | --- |
| 地址 | `GET pages.sfacg.com/ajax/ashx/Common.ashx?op=getNovelsByTag` | `GET pages.sfacg.com/api/essay/getNovels` |
| 参数 | `op=getNovelsByTag&tagId={t}&ps=200&pi={0起}` | `tagIds={t}&page={n}&size={500}`（page 起始随版本变，以页面实际传参为准） |
| 条目 | `NovelID/NovelName/AuthorName/Intro/Cover/CategoryID` | `novelID/novelName/authorName/intro/cover/categoryID` |

**四条解析规则**：① 字段名两套大小写都要兼容；② tagId 是「赛事 × 赛道」编号，不能猜、按 `location.host` 取生产值；
③ `categoryID` 不能当 form 真值（E.28 只正向用 1/4），只作赛道提示；④ `intro` 是作品简介、不是作者 intro。

### 3. 赛事元数据层（官方无端点）

清单 API 只返回作品，**不返回赛事名/届次/日期/奖项/获奖**。

- **届次 + 起止时间**：`analysis/references/contest-editions.md` 已有用户逐届核实版，**这是分析档案不是 app 数据**；
  做档案页时从该文件**导出一份内置静态表**，不要在本文或 app 里另维护副本（单一真源）。早期精确日稀缺，缺失就只显示届次/年份，不编造。
- **获奖名单**：**有来源，不是 API，也不是私有 API**——四代形态见 `contest-roster-fields.md`（第 2 代 JS 静态 JSON 需现场判定获奖模块，
  第 3 代 UUID 页 `alt` 直给奖项名）；入种已按净 911 定案，逐档名仅 44 本可靠、867 本待标定（`award-winners-as-seed-source.md`）。
  获奖页 URL 随机串是 JS 写死的路由、每届漂移，见 `contest-url-api-patterns.md`。
- **官方活动页 URL（外链跳转用）**：从赛事静态表导出时可为每届附一个 `activity_url`，点击在浏览器/webview 打开官方页。
  这是**外链字段、不是抓取源**——URL 台账（含已下线的历史届）见 `contest-roster-harvest.md`，页面下线则降级为不可点。
  tagId 是另一回事（清单浏览页用），不要混为一谈：有 URL 不代表有 tagId（2022/2023 主题秋征有页面、tagId 未取），反之亦然（2021 主题秋征页面下线、tagId 464/465 已反查到）。
- **不爬活动页取赛事元数据**：静态表与作者 intro 同属快照型配置，会过期、随种子发版更新；活动页会改版/下线、稳定性差。

## 操作：两种页面形态

### 4. 形态一：赛事档案页（Contest Archive）

一届一页：赛事名/届次、起止时间（无则标「仅年份」）、赛道列表、参赛规模、按我们信号排序的代表作品（每个 form 一组）、获奖信息（档案页获奖区块 2026-11-22 移除——参赛者 top10 ≈ 获奖者，代表作区块已覆盖头部；获奖徽标保留书籍详情页，见状态行）。

- **赛事列表**：从种子 `contest` 枚举（零请求），新赛事进种子即自动出现。
- **日期/赛程**：读内置静态表；表中没有就只显示解析出的届次/年份。
- **参赛作品**：优先本地聚合，要完整清单才按需调 API（复用清单能力）。
- **「我们的形式」**：先剔污染——短/中篇组套用「征文名含『长篇』即假完结」裁定与用户裁定表（`fake-complete-short-medium.md`），
  否则档案页会把霸榜的假短/中篇当代表作展示；排序用 `fav_pctl`（累计 favs 混书龄，跨届横比系统性偏老赛事）；
  按 `long/medium/short/dialogue` 分组独立排序（长篇流量是中短篇上百上千倍，混排会淹没后两者）；
  novly 模式只浏览/收藏入 watchlist，不做「征文推荐分」、不进推荐打分白名单。

### 5. 形态二：参赛清单浏览页（Contest Roster Browser）

赛事 → 赛道 → 作品列表分页浏览；列表项显示清单自带的标题/作者/简介/封面/赛道，库内书额外叠加 form 与信号徽标。

| 年代 | URL 形态 | 清单 API | 浏览页能力 |
| --- | --- | --- | --- |
| 早期（四/五征 2016–17，六征 2018） | 静态页 `list.html` / 活动页内嵌 JS | 旧接口，tag 写死（275–277 / 377–380 / 383–386） | 按赛道拉官方清单；一/二/三征仍降级本地 |
| H5（2019–22） | `pages.sfacg.com/{h5,pc}/act/...` | 旧接口，tag 表部分有 | 有 tagId 的赛道可调，其余降级本地 |
| SPA / UUID（2023 起） | `pages.sfacg.com/h5/act/zwYYYYMMDD/pc` 或 UUID 页 | 新接口，十一/十二/十三征较全 | 完整清单可用 |

**join 本地**：库内显示清单字段 + form / fav_pctl 徽标（覆盖层优先、种子兜底），走既有详情页；
库外只显示清单自带字段，**无 form / fav_pctl 徽标**（这些是种子侧算的），不伪造、不用清单 `categoryID` 顶替 form。

**筛选排序**：仅限已有维度（form、赛道、世代/年份、库内/库外），不造「征文热度分」；库内可按 `fav_pctl`/favs 排，
库外只能按清单返回顺序（官方排序）并标注来源；混排时标清「我们的排序」与「官方顺序」。

**定案决策（2026-11-21，P1）**：

- **入口**：档案页在「浏览全部作品」之外加「查看官方清单」行；无 tagId 赛事（一/二/三征、未摸到号）入口保留，
  点开落清单页直接给本地库内子集并标「仅库内作品，清单不完整」（降级表同形）；有 tagId 但接口失效回落同形。
- **赛道**：多轨赛事（X 征长/中/短）列表顶部赛道 chip，切轨请求对应 tag；单轨赛事不显示 chip。
- **排序**：v1 保持官方返回顺序，无排序控件。
- **筛选**：顶部三态 chip，全部 / 仅库内 / 仅库外——端上展示筛选，不改数据请求。
- **库外书点击**：复用搜索页库外书链路——按需抓详情 + 自动收进关注库（用户裁定 2026-11-21），
  每次点击消耗 1 个限速详情请求，收录管理页可移除。
- **页长**：新 API `size=500`、旧 H5 `ps=200`（各自接口上限）。

## 边界与降级

**请求契约**：只取清单元数据，不取正文、不登录、不带用户 cookie；沿用引擎全局限速（端点间隔 ≥1s、队列硬上限），
清单翻页按页串行、失败即跳过；按页缓存 + 失败降级本地，不因清单不可用阻塞页面；
`status.errorCode`（新）/ `status`（旧）非 200 或结构缺失 → 视为接口失效，回落本地、不重试风暴。

**降级表**：

| 情形 | 处理 |
| --- | --- |
| 赛事无 tagId（一/二/三征、未摸到） | 只显示本地种子聚合，标「仅库内作品，清单不完整」 |
| 活动页改版 / 接口下线 | 清单不可用 → 回落本地子集；不显示空白、不清空已显示值 |
| 清单字段大小写变化 | 双格式解析；两者皆无 → 该条跳过，不猜字段 |
| 库外书无 form/分位 | 不显示徽标、不伪造；只显示清单自带字段 |
| 短/中篇头部含假完结 | 套用裁定剔除或标注，这是展示层必须守住的口径 |
| 赛事日期缺失 | 只显示届次/年份，不编造 |

**不做**：爬活动页取赛事元数据；用清单 `categoryID` 判 form；跨届横比累计 favs；为征文造新指标或推荐分；
把库外书写成种子；取正文/登录/带用户态；全库后台批量抓清单；清单排序控件（v1 保持官方顺序）。

**裁定记录**（均已拍板，本文不执行）：
