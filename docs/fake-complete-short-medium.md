# 假完结短/中篇：排名池污染问题（已实施）

> **定位**：本文是「被抛弃的长篇被恶意标注为完结」污染 short/medium 排名池的**权威定案**——裁定规则、命中范围、纠偏机制、工程落地结果仅在此维护。
> **状态**：已实施（2026-11-21，用户放行后）。P10 入种剔除 + 用户裁定表已写入 `seed_policy.py` / `build_seed.py`，两份种子重建为 `.25`，P1–P10 断言全过、假短篇残留 0。
> **权威范围**：本文唯一维护——P10 假完结剔除裁定（征文含「长篇」即假）、第二类僵尸逐本裁定（86430）、145 本命中范围、纠偏机制；form 六值判定见 `form-definitions.md`。
> **口径**：所有命中数、分布、fcr 均为某次种子快照现算值，仅供参考，随版本变化，禁止硬编码进代码。
> **更新日期**：2026-11-21。

## 1. 结论

1. 现有入选规则挡不住：`status=已完结` 是作者可自我声明的字段，E.11/E.20 只查它；E.19 的点击天花板只覆盖 `words≤5万`，5–15 万的中篇档没有对应闸门。
2. 这些书进入 short/medium 池后，短篇榜 `/rankings/short` 与经典榜默认 `order=favs` 都按**平台累计收藏**排序（累计值混着书龄与曝光分母）；`fav_pctl` 是全库同世代分位、跨 form 共用一个分母，切到 `pct` 也赶不走它们。这是「排名池被长篇曝光污染」，不是单纯的 form 误判，不宜用继续加 DOM/分类器精度解决（用户已裁定 form 侧不做精度军备）。
3. **用户已给出两条确定性裁定（2026-11-20）**：
   - **P10 主裁定**：short/medium 档里**征文名含「长篇」的一律是假完结**——命中 **145 本**（medium 93 / short 52），霸榜集中；
   - **第二类僵尸裁定**：「超级可爱的钟天的日常」（nid 86430）内容被替换为无意义文本，现有规则全抓不到，已逐本裁定 `invalid`。
   - 其余信号（标题长度、`favs/clicks`、`fcr`、`ckw`、`categoryId`）仍是弱证据，不能单独用。
4. 治理路径：已用裁定规则做**入种剔除**（治本，P10），`.25` 种子已验证清零（§2.6、§5）；排名层抗曝光口径仍作补充讨论，未实施。

## 2. 证据与裁定

### 2.1 现有规则为什么漏

| 条款 | 拦什么 | 为什么拦不住 |
|---|---|---|
| E.11 弃书 | 连载 short（除非 fav_pctl≥0.98） | 作者已标「已完结」，不触发 |
| E.20 中篇必须完结 | 连载 medium 一律出局 | 同上，状态是作者自报的 |
| E.19 点击天花板 | `words≤5万 且 clicks>215,723` → invalid | 这类书字数 5–15 万，**整档不在射程内** |
| P6/P7/P8/P9 断言 | invalid 零入种、short 不越天花板等 | 越线者已被挡；未越线的「貌似正常」书照样过 |

当前口径默认「作者说完结 + 字数在档内 = 真短/中篇」，而这个前提正是问题所在。

### 2.2 覆盖缺口（用户 2026-11-20 指出，已用搜索 API 验证）

- **后果一**：所有分布/分位数/fcr 中位数都建立在残缺的短篇分母上，统计信号只能定性、不能做硬阈值；真短篇缺席越多，霸榜实际越严重。
- **后果二**：短篇在走下坡路——早期有「回到旧时光」「听雨」那样的天花板，后续同时代天花板连 200 favs 都拿不到（如 751851 仅 72、662244 仅 170），而它们恰是最容易被扫描漏掉的一批；用绝对收藏排序会系统性低估新短篇。

### 2.4 用户裁定一：short/medium 档「征文名含长篇」即假（P10）

用户明确裁定（不是概率信号）：**在 short/medium 档里，凡征文名带「长篇」的书一律是假完结**。理由：征文同时开长/中/短赛道，作者技不如人就断更并改状态完结；长篇赛道流量是中短篇的上百倍甚至上千倍，长篇征文里的劣质书数据也可能远超真短篇优质书。（已知假书「徒儿是最强刺客怎么办」挂七征长篇，验证此规则。）

现算覆盖（种子快照，仅供参考）：

- short+medium 共约 1,189 本，**145 本命中**（medium 93 / short 52）；合并收藏 Top20 命中 8 本、Top50 命中 13 本——正是霸榜那批。
- 全库另有 2,957 本 `long` + 160 本 `dialogue` 也带长篇征文标记，但**不适用本裁定**：长篇书本就是长篇赛道、dialogue 是形态产品线。规则只在「形态被判成 short/medium、却报了长篇征文」时生效。
- 三个真天花板（听雨/回到旧时光/少女与龙）分别挂短篇征文或无征文，**均不命中**。

可疑名单生成方法（快照现算、仅供人审，不是判据）：对每个 form×世代算 `fcr` 中位数与点击 P90；评分 = 标题≥10字(+1) + 征文含「长篇」(+2) + `fcr` 低于同代中位(+1) + 点击高于同代 P90(+1) + 收藏高于同代 P90(+1)；取 `score≥3 且 favs≥500`，按 score/收藏排序（约 122 本、`score≥4` 约 64 本）。已知假书「徒儿是最强刺客怎么办」命中 `score=4`、三个真天花板均不命中，验证名单方向。名单导出见 §2.3 末注。

### 2.5 用户裁定二：第二类僵尸 86430

假书有两套不同机制：

| 类型 | 表现 | 现有处置 |
|---|---|---|
| 第一类：Web 死链 | 详情页「小说不存在」（HTTP 200）、app 打开 404 | E.25：`web_dead.jsonl` → `ineligible` + P9 |
| 第二类：内容替换 | 页面正常、阅读入口仍在，但正文被换成无意义文本；大多由长篇转换而来 | 此前无规则，本轮起走用户裁定通道 |

86430 是用户目验的第二类僵尸，**现有规则全都抓不到**：DOM 预读文案是作者正常说明（E.24 全种子 DOM 审计判它 `prose`）、征文挂「五征中篇」不含「长篇」（§2.4 不命中）、clicks=214,737 比天花板 215,723 低 986（没越线）、字数 4.2 万 / 收藏 1,616 / `fav_pctl=0.961` 各项「看起来正常」。结论：**这类只能靠用户目验**。已按 E.27 写入 `analysis/anchors/form_user_verified.jsonl`（nid 86430 → `invalid`，级 -1），在 `.25` 重建时经 `forms.classify` 级 -1 自动出局（已验证不在种子内）。当前只确认这一本，**不做批量推定**。

### 2.6 现场核查：「app 用了旧 db」怀疑的证伪（2026-11-21）

用户发现数据里仍有假短篇，怀疑 app 打包了旧 db。只读核查结果：**不是旧 db 问题，是剔除规则从未落地**。

- **（实施前）两份资产同步且为当时最新**：`app/assets/` 与 `app/ui/assets/` 的 `manifest.json`、`seed.db.gz` 逐字节一致（MD5 相同），均为 `seed_version=20260503.24`、18,897 本；`InstallSeed` 按 `seed_version` 分目录装载，版本变化即解压重装并清旧版本，运行时加载路径正常——排除"旧 db / 缓存"假设。
- **唯一"旧"的是 git 提交态**：HEAD 提交的 manifest 仍是 `.23`（18,656 本），工作区 `.24` 尚未提交（与一批 `app/` 未提交改动同处工作区）。即便发布出去的是 `.23`，它和 `.24` 的假短篇情况相同——换 db 不解决问题。
- **（实施前）实测 `.24` 种子**：解包 `seed.db.gz` 直接查 `books` 表，`form∈{short,medium} 且 contest 含「长篇」` 仍为 **short 52 + medium 93 = 145 本**（与 §2.4 定案同批）；86430 在种子里仍是 `short`，用户裁定表未生效。原因：P10 从未写进 `seed_policy.py`（该文件只有 E.19 的 P6 假短篇条款）；裁定文件 2026-11-21 才提交、晚于 `.24` 的 2026-11-20 构建。
- **结论**：假短篇在种子里是**规则缺口**，不是缓存/版本问题；重装、换版本、清缓存都无效。治本路径是 §5 主方案 B（改 `seed_policy.py` 入种剔除 + 重建两份种子）。
- **实施结果（2026-11-21，用户放行）**：按方案 B 落地——`seed_policy.py` 新增 `fake_complete_ids()`（`form∈{short,medium}` 且 `contest` 含「长篇」），并入 `ineligible` 且从征文保底候选中二次剔除（145 本里 124 本过保底门槛，不二次过滤会被加回）；新增 P10 断言；`build_seed.py` 版本 `.24`→`.25`、常量 admitted 18,849→18,704、seed 18,897→18,751。重建后实测：假完结残留 **0**、86430 出局、medium 580→487 / short 609→556（后者含 86430），P1–P10 全过、覆盖率 96.53%，两份资产 MD5 一致，引擎 `go test ./...` 全过。

## 3. 纠偏机制（长期）

- **确定性裁定优先**：用户逐本目验 → 写入 `form_user_verified.jsonl`（级 -1），不经任何估计、不绕过断言；与 P6/P7/P8/P9 冲突说明裁定需复核，不许为裁定绕过断言。该通道只决定 form，不扩大爬取、不加启发式——裁定是终点不是训练集（跨档/作者传播已证明会大规模误判）。
- **规则治本（已实施）**：P10 规则入种剔除（§5 B），一次性清掉 145 本污染源、所有池子受益、可解释可断言，P10 断言守门。
- **排名层兜底（补充方案 A）**：裁定落地后，剩余「待目验」书仍可能污染排名，可对 short/medium 榜加一层抗曝光排序口径（如要求最低 `fcr` 或 `favs × fcr` 组合键，UI 明示「按口碑转化排」）——需在同代内比较并设样本下限，不作为主方案。
- **覆盖缺口独立处理**：「补采短篇」与「剔除假短/中篇」是两件独立的事，当前裁定只涉及后者；是否补采另立任务，不影响 P10 执行。

## 4. 边界

- **信号支持度**：样本分母残缺（已 API 验证，只能定性）> 征文含「长篇」（确定性，145 本，不适用 long/dialogue）> 86430 第二类僵尸（逐本裁定）> 标题长度 / fcr / ckw / categoryId（弱信号，同代内参考）。
- **不写批量规则**：剩余约 60 本「待目验」书无长篇征文标记但仍可疑，需用户逐本目验；已确认的假书走 `form_user_verified.jsonl` 裁定，不写成批量规则。用户已明确第二类僵尸「大多是长篇转换而来」，但**只确认了 86430 一本**，不得据此对剩余书批量推定。
- **不改 form 判据、不做假完结检测器**：本问题的性质是池间曝光挤压，不靠 form 精度军备解决（form-definitions.md 已补 P10 指针）。

## 5. P10 规则全文与落地记录

**主方案 B —— 入种前剔除「长篇征文」短/中篇（用户裁定）**

在 seed policy 的 `ineligible` 加一条：`form ∈ {short, medium}` 且 `contest` 含「长篇」→ 剔除，类似 E.25 Web 死链（无豁免）。这不是统计阈值、不需要人审校准——用户已给出确定理由与方向。

- 优点：一次性清掉 145 本污染源，所有池子受益，规则可解释、可断言（新增 P10）。
- 代价：种子数量与覆盖率断言要改，两份 APK 种子要重建（E.26 教训）——**均已执行**，见 §2.6 实施结果。
- 边界：只剔除 short/medium 档；`long` 档 2,957 本和 `dialogue` 档 160 本带长篇征文标记的书**不受影响**（P10 判定只用 `_form()` 结果，这两档不在 `short/medium` 内）。

实现落点：`app/tools/seedbuild/seed_policy.py` 的 `fake_complete_ids()` + `admit()` 的 `ineligible` 与 `contest_added` 过滤 + `postconditions` 的 P10；`app/tools/seedbuild/build_seed.py` 的常量与 manifest 统计。种子版本 `.25`。

**不推荐方案 C —— 只标注不处理**：短/中篇详情页显示「累计点击/收藏可能来自长篇渠道」提示，榜单照旧；零误伤但排名问题原样保留、与用户裁定不符。
