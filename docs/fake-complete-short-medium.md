# 假完结短/中篇：排名池污染问题（分析待裁定）

> **用户发现（2026-11-20）**：种子里的中篇/短篇很多是「被抛弃的长篇被恶意标注为完结」。
> 它们与真短/中篇在形态上几乎没有明显差别，却因为**在官方 App 吃的是长篇流量**，
> 在收藏/点击等多项数据上远超真短/中篇，于是**排名天然占优**，把真短/中篇挤出榜单。
>
> **性质**：这是「排名池被长篇曝光污染」，不是单纯的 form 误判；不宜用继续加 DOM/
> 分类器精度的方式解决（用户已裁定 form 侧不做精度军备）。本文只做定性与方案梳理，
> 数字均为某次种子快照现算值、仅供参考，随版本变化；不硬编码到代码。
> 本轮只写文档，`app/` 实现由开发 agent 负责。

## 0. 结论先行

1. 现有入选规则挡不住：`status=已完结` 是作者可自我声明的字段，E.11/E.20 只查它；
   E.19 的点击天花板只覆盖 `words≤5万`，5–15 万的中篇档没有对应闸门。
2. 这些书进入 short/medium 池后，短篇榜 `/rankings/short` 与经典榜默认 `order=favs`
   都按**平台累计收藏**排序；累计值混着书龄与曝光分母（报告 02/08），
   长篇渠道喂出来的 favs/clicks 直接变成排序优势。
3. 用户已给出两条**确定性裁定**（2026-11-20）：
   ① short/medium 档里**征文名含「长篇」的一律是假完结**（§2.2）——命中 145 本，霸榜集中；
   ②「超级可爱的钟天的日常」（86430）是**第二类僵尸**——内容被替换为无意义文本，现有规则全抓不到（§2.3）。
   其余信号（标题长度、`favs/clicks`、`ckw`、categoryId）仍是弱证据，不能单独用。
4. 治理路径：优先用裁定规则做**入种剔除**（治本）；排名层的抗曝光口径作为补充讨论。
   都不需要再改 form 判据或做「假完结检测器」。落地需改 `app/` 种子策略，当前禁止我编辑。

## 1. 现有规则为什么漏

| 条款 | 拦什么 | 为什么拦不住这类书 |
|---|---|---|
| E.11 弃书 | 连载 short（除非 fav_pctl≥0.98） | 作者已标「已完结」，不触发 |
| E.20 中篇必须完结 | 连载 medium 一律出局 | 同上，状态是作者自报的 |
| E.19 点击天花板 | `words≤5万 且 clicks>215,723` → invalid | 这类书字数在 5–15 万，**整档不在射程内** |
| E.21 正文征文否决形态估计 | 只否决对话形态估计 | 形态本来就是字数档，无影响 |
| P6/P7/P8/P9 断言 | invalid 零入种、short 不越天花板等 | 越线者已被挡；未越线的「貌似正常」书照样过 |

换句话说：**当前口径默认「作者说完结 + 字数在档内 = 真短/中篇」**，
而这个前提正是用户观察到的问题所在。

用户新观察：**很多真中短篇的标题字数很少**（上面三个天花板分别 2/5/4 字），
而假书标题是典型长篇网文式长标题（10 字）。现算：

- 种子 short/medium 标题长度中位数：short 9 字、medium 10 字；
  收藏 Top50 的平均标题长度约 10.3（short）/ 10.7（medium）字，
  三个天花板明显低于头部均值。
- 但标题长度与世代混杂：medium 标题 ≤4 字组世代中位 2017、收藏中位 23；
  11 字以上组世代中位 2021、收藏中位 546。**长标题书普遍更新，不能单独当硬判据**。
- 用户进一步指出（2026-11-20）：**真短篇更像传统小说，标题简洁朴素**
  （用户举例「落樱之剑」「一堂历史课」「血与梦」一类），且**年代越早越像传统小说**；
  年代越往后标题字数增加（用户举例「不争气少女与绝望少年」「我和异虫妻子的二三事」）。
  → 含义：标题长度主要是**写作范式 / 年代的代理**——早期真短篇沿用传统小说式短标题，
  后期真短篇也会被网文式长标题同化。所以**长标题不等于假书、短标题不等于真书**，
  只能在同世代内作弱参考，绝不跨代比较、更不能直接判真假。
  五个举例标题经搜索 API 全部精确命中（nid 见 §2 覆盖缺口表），确系覆盖缺口而非记忆出入；
  本文件未据这些举例改动任何 form/入选判定。
- 因此标题长度只作为弱信号；用户随后给出的「长篇征文即假」是确定性裁定（§2.2），
  优先级高于标题长度与 fcr 等统计信号。

**可疑名单生成方法**（快照现算、仅供人审，不是判据）：对每个 form×世代算
`fcr` 中位数与点击 P90；评分 = 标题≥10字(+1) + 征文含「长篇」(+2) +
`fcr` 低于同代中位(+1) + 点击高于同代 P90(+1) + 收藏高于同代 P90(+1)；
取 `score≥3 且 favs≥500`，按 score/收藏排序，共 122 本（score≥4 者 64 本）。
输出 `analysis/out/suspicious_short_medium.csv`（不入库），供用户目验、回收真假锚点。
已知假书「徒儿是最强刺客怎么办」命中 score=4，验证名单方向；三个真天花板均不命中。

### 2.2 用户裁定：短/中篇档「征文名含长篇」即假（2026-11-20）

用户明确裁定（不是概率信号）：**在 short/medium 档里，凡征文名带「长篇」的书一律是假完结**。
理由：征文同时开长/中/短赛道，作者看到自己技不如人就断更并把状态改成完结；
长篇赛道流量是中短篇的**上百倍甚至上千倍**，所以长篇征文里的劣质书数据也可能远超真短篇优质书。
（用户已知假书「徒儿是最强刺客怎么办」挂七征长篇，验证此规则。）

现算覆盖（种子快照，仅供参考）：

- short+medium 共 1,189 本，**145 本命中**（medium 93 / short 52）；
- 合并收藏 Top20 里命中 8 本、Top50 里命中 13 本——正好是霸榜的那批；
- 全库另有 2,957 本 `long` + 160 本 `dialogue` 也带长篇征文标记，
  **它们不适用本裁定**：长篇书本就是长篇赛道，dialogue 是作品形态产品线；
  规则只在「形态被判成 short/medium、却报了长篇征文」时生效。
- 三个真天花板（听雨/回到旧时光/少女与龙）分别挂短篇征文或无征文，**均不命中**。

已把主名单 `analysis/out/suspicious_short_medium.csv` 加 `user_verdict` 列：122 本中
61 本标「假（用户裁定：长篇征文）」、1 本标「假（用户目验：第二类僵尸，86430）」、
剩余 60 本仍「待目验」；裁定为假的单独导出
`analysis/out/long_contest_fake_short_medium.csv`（145 本全量，不止名单内的 61 本）。

**实施边界**：这是内容剔除规则，落在种子入种层（`app/tools/seedbuild/seed_policy.py` 的
`ineligible`）最干净，但该目录属 `app/`，当前禁止我编辑；需用户放行或由开发 agent 落地。
落地后种子数、覆盖率断言与两份 APK 种子都要重建（E.26 教训）。

### 2.3 第二类僵尸：内容被替换为无意义文本（2026-11-20 用户目验）

用户指出假书有两套不同机制，此前只处理了其中一套：

| 类型 | 表现 | 现有处置 |
|---|---|---|
| 第一类：Web 死链 | 详情页文案页「小说不存在」（HTTP 200），app 打开 404 | E.25：`web_dead.jsonl` → `ineligible` + P9 |
| 第二类：内容替换 | 页面正常、阅读入口仍在，但**正文被换成无意义文本**；**大多由长篇转换而来** | 此前无规则，本轮起走用户裁定表 |

「超级可爱的钟天的日常」（nid 86430）是用户目验的第二类僵尸，**现有规则全都抓不到**：
- DOM 预读文案是作者正常说明（「新书是本书的秽土转生版本…」），E.24 全种子 DOM 审计判它 `prose`，判不出正文已被替换；
- 征文挂「五征中篇」，不含「长篇」，§2.2 裁定不命中；
- clicks=214,737，比 E.19 天花板 215,723 低 986，刚好没越线；
- 字数 4.2 万、收藏 1,616、`fav_pctl=0.961`，各项指标都「看起来正常」。

结论：**这类只能靠用户目验**（用户「不需要 DOM 判决，很多你可以直接问我」）。
已按 E.27 写入 `analysis/anchors/form_user_verified.jsonl`（nid 86430 → `invalid`，级 -1），
下次重建种子时自动出局；当前 APK 种子未变。当前只确认这一本，不做批量推定。

## 3. 为什么排名天然占优

- `/rankings/short`：meta 明写 `ordering=favs`，直接按收藏降序。
- `/rankings/classic?form=short|medium`：默认 `order=favs`，可选 `pct`（`fav_pctl`）。
- `fav_pctl` 是**全库同世代分位**、跨 form 共用一个分母；假中篇的高收藏在该世代里
  照样落在极高分位，所以切到 `pct` 并不能把它们赶出去。
- 结果：短/中篇榜首被长篇流量书占据，真短/中篇的优质作品拿不到曝光位——
  与 09 附录 D「中篇并入短篇会让 favs Top200 里 197 本是中篇」是同一类
  **池间曝光挤压**问题，只是这次挤压来自「伪装成短/中篇的长篇」。

## 5. 方案选项（裁定已明确，实施待放行）

### A. 只改排名，不动种子（补充方案）

保持 form/入选不变，给 short/medium 榜加一层**抗曝光排序口径**：例如要求最低
`fcr` 或按 `favs × fcr` 一类组合键排序，并在 UI 明示「按口碑转化排」。
- 优点：不误杀书、不改种子版本、不动 form 判据，回退容易。
- 代价：需要定阈值/公式；`fcr` 随世代与书龄漂移，必须只在**同代内**比较并设样本下限。
- 定位：裁定规则落地后，剩余「待目验」书仍可能污染排名，A 是对它们的兜底，不是主方案。

### B. 入种前剔除「长篇征文」短/中篇（用户裁定，主方案）

在 seed policy 的 `ineligible` 加一条：`form ∈ {short, medium}` 且 `contest` 含「长篇」→ 剔除，
类似 E.25 Web 死链（无豁免）。这不是统计阈值、不需要人审校准——用户已给出确定理由与方向。
- 优点：一次性清掉 145 本污染源，所有池子受益，规则可解释、可断言（新增 P10）。
- 代价：种子数量与覆盖率断言要改，两份 APK 种子要重建（E.26 教训）；
  改的是 `app/tools/seedbuild/seed_policy.py`，当前禁止我编辑 `app/`，需放行或交开发 agent。
- 边界：只剔除 short/medium 档；`long` 档 2,957 本和 `dialogue` 档 160 本带长篇征文标记的书**不受影响**。

### C. 只标注、不处理（不推荐）

在短/中篇详情页显示「累计点击/收藏可能来自长篇渠道」提示，榜单照旧。
- 优点：零误伤、零工程。
- 代价：排名问题原样保留，与用户裁定不符。
