# 全局文档：篇幅加权口碑分 `lqs`

> **状态**：2026-11-18 定案（用户：`pr` 排不掉 15–50 万字作品，而读者更愿意看长篇；
> 推荐池篇幅偏短会直接削弱使用意愿）。**口径定稿、尚未实施**——随 `form` 列一起进种子 v3。
> **范围**：仅长篇区（`form = long` 且 `words > 15 万`，排除 `dialogue` / `ip_collab`）；
> 中篇区（5–15 万）**待定**。
> **红线**：不改 `pr`、不改分位五列与其分母、不改报告 23、不动定年；`lqs` 只作排序信号，
> **不作质量标签**展示。
> 数字全部由 `analysis/lib/lqs.py` 现算（`cd analysis && uv run python -m lib.lqs`），
> 口径为 universe 241,758 行，禁止硬编码。
> 使用方：推荐层（`app/docs/12-dual-mode.md` §3.2 白名单）、种子构建（`app/docs/02-data-model.md`）。

## 0. 一句话

```
lqs = q × (0.75 + 0.25 × len)
```

`q` = 同「世代 × 收藏档」内的 `pr` 分位（去掉收藏规模对赞藏比的机械影响）；
`len` = `log(字数/15万) / log(100万/15万)`，夹在 `[0,1]`（超过 100 万字不再加分）。
结果与收藏量秩相关 **−0.01**（不是热度榜）、与 `pr` 秩相关 **+0.62**（仍是口碑驱动）。

## 1. 为什么 `pr` 单独不够

长篇区 17,028 本（`form=long` 且字数 >15 万），其中 16,478 本 `favs ≥ 10`。
`pr` 与篇幅**强负相关**：

| 篇幅档 | 本数 | `pr` 中位 | 收藏中位 |
| --- | ---: | ---: | ---: |
| 15–30 万 | 7,304 | 0.515 | 289 |
| 30–50 万 | 3,659 | 0.299 | 1,441 |
| 50–100 万 | 3,003 | 0.240 | 3,449 |
| 100–200 万 | 1,772 | 0.224 | 7,597 |
| 200 万+ | 740 | 0.236 | 17,010 |

`pr` 前 1%（196 本）的篇幅构成：**15–30 万 78.1%**、30–50 万 16.3%、50–100 万 5.6%、
100 万以上 **0 本**。前 5%（832 本）：73.2% / 19.0% / 6.6% / 1.1% / 0.1%。

读者的实际选择相反——同代、同一 `pr` 五分位内，长篇的收藏中位数是 15–30 万字的倍数
（2017–2021 逐年现算）：30–50 万 **1.6–2.1×**、50–100 万 **2.2–3.4×**、
100–200 万 **3.5–8.4×**、200 万+ **5.1–10.7×**。全库收藏加权中位篇幅 **102.1 万字**。

> 机制：`pr` 的分母是收藏，长篇读者更难读完、更难留下赞；比值天然压低长书。
> 而推荐若直接按 `pr` 排序，推荐池会被压到 20 万字量级——这正是要修的问题。

## 2. 定义

| 常量 | 值 | 理由 |
| --- | --- | --- |
| `ZONE_FORM` | `long` | 只作用长篇区；对话/互动（88 万字仍属 `dialogue`）不适用 |
| `ZONE_MIN_WORDS` | 150,000 | 命名长篇但字数不足的不入池（「X 征长篇」中位仅 1.4 万字） |
| `EVIDENCE_MIN_FAVS` | 200 | 证据下限：`favs` 200 以下 `pr` 抽样噪声压倒信号（覆盖长篇区 99.6% 收藏） |
| `PR_CAP` | 5.0 | `pr` 长尾截断（原文最大 23.5，来自 15 收藏级小样本） |
| `LEN_LO / LEN_HI` | 15 万 / 100 万 | 篇幅系数 0 → 1 的锚点；>100 万封顶，防灌水刷分 |
| `LEN_K` | 0.25 | 篇幅权限：系数区间 `[0.75, 1.00]`，见 §3 校准 |
| `MIN_CELL` | 40 | 「世代 × 收藏档」最小样本，不足退回同档全体分位（回退率 1.8%） |

**质量项 `q`**：先把 `pr` 按收藏档切开（200–1k / 1k–5k / 5k+），再在「世代 × 档」内取分位。
不分档则回到老问题——`pr` 中位随收藏规模从 1.48（10–50 收藏）掉到 0.17（5k+），
分位会被规模而非口碑主导。分档后 `q` 与 `favs` 秩相关 −0.06、与字数 +0.10，接近干净。

**篇幅项 `len`**：对数插值。用对数是因为 15→30 万与 80→95 万对读者的意义不同；
封顶在 100 万是因为再长的边际收益已很小（200 万+ 档的收藏中位并不比 100–200 万多一个量级）。

**合成用乘性、保留下界 0.75**：加性混合允许篇幅补偿质量（低质长书压过高质短书）；
乘性下篇幅最多拿走 25% 的分数，且 `q` 低的书永远起不来。

> **与报告 23 的「不连乘」约束的关系**：那条约束针对「篇幅效率 × `pr`」——两个都带质量
> 含义的信号相乘会重复计分。这里的 `len` 是**显式先验**（读者承诺意愿），不是质量证据，
> 且权限封顶 25%。该约束由此修订为：**篇幅先验可以进推荐，但必须有下界、有上限、
> 不得作为质量标签**。

## 3. 校准（为什么是 0.25）

以一个可观测事实锚定：**全库收藏加权中位篇幅 1,020,850 字**（"典型的一次收藏落在多长的书上"）。
调节 `K` 让推荐池的篇幅分布对齐它：

| `K` | 推荐池 top1000 中位篇幅 | 与收藏加权中位差 | `rho(lqs, pr)` | top1000 里 15–30 万占比 |
| ---: | ---: | ---: | ---: | ---: |
| 0.20 | 934,880 | −8.4% | 0.633 | 4.7% |
| **0.25** | **1,030,464** | **+0.9%** | **0.623** | **0.8%** |
| 0.30 | 1,089,268 | +6.7% | 0.611 | 0.0% |
| 0.40 | 1,133,540 | +11.0% | 0.585 | 0.0% |
| 0.50 | 1,179,922 | +15.6% | 0.556 | 0.0% |

`K = 0.25` 同时满足两点：篇幅对齐误差 <1%，口碑保真度仍 >0.6。再大就开始超配长书
（`K=0.5` 时与 `pr` 的相关掉到 0.556，榜单向"字数榜"退化）。

- **top200 篇幅构成**：50–100 万 23%、100–200 万 45%、200 万+ 32%、15–50 万 **0%**。
- **top1000**：中位篇幅 1,030,464 字，收藏中位 5,454，其中 `favs<1k` 占 14.9%

## 5. 边界

- **`favs < 200` 的长篇不给分**（`lqs = NULL`）：约 4,900 本、0.4% 收藏；它们仍可按
  `fav_pctl` / `praise_pctl` 出现在其它榜，只是不进篇幅加权推荐池。
- **中篇区（5–15 万）待定**：同一公式会把所有中篇压到 0.75 下界（`len` 恒为 0），
  等于硬排除；要进中篇，需要单独定标（长度锚点下移），**不要直接复用本指标**。
- **对话/互动不适用**：`form=dialogue` 优先于篇幅，88 万字的对话小说不进长篇池。
- **连载中不因长而加分**：`status` 不进入 `lqs`；断更书不因字数进推荐池（沿用 06 与
  双模式 §3.3 的候选池门槛）。
- **不作质量标签**：详情页只并列展示「132 万字 / 同代口碑分位 92%」，不给「好/差」判定；
  与 `pr` 并列而非替代（报告 23 的双组分位原则）。

## 6. 实施（种子 v3，与 `form` 同批）

- `books` 加 `lqs REAL`，索引 `(lqs DESC)`；`NULL` 语义见 §5。分位五列与分母不动。
  （落地细节见 `app/docs/02-data-model.md`。）
- 唯一实现 `analysis/lib/lqs.py`（`compute()` + 审计 CLI）；`build_seed.py` 调它，
  `validate.py` 加断言：`lqs ∈ [0,1]`、非空数 = 长篇区 `favs≥200` 数、
  `|rho(lqs, favs)| < 0.1`（防退化成热度榜）。
- 引擎：发现流默认 `ORDER BY lqs DESC`；长篇榜增加 `sort=lqs` 选项；
  详情/列表 API 暴露 `lqs` 与 `lqs_pctl`（供"同代分位"展示，见 `app/docs/08-engine-api.md`）。
- 双模式：novly 模式展示收藏原值，但**排序**仍走 `lqs`（`app/docs/12-dual-mode.md` §3.2 白名单）。
- 上线后若拿到留存数据，只用它调 `LEN_K`（0.2–0.4），不改公式结构。

## 7. 不做什么

- 不重算 `pr`、不改分位分母、不改报告 23 的三段式结论与图。
- 不把 `lqs` 用到短篇/中篇/对话区，不用绝对 `favs` 做质量门槛（§2 的 200 只是证据下限）。
- 不把 `words` 原始值打进推荐打分——`len` 是归一化先验，不是"字数越多越好"的直通规则。
