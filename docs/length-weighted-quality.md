# 全局文档：篇幅加权口碑分 `lqs`（长篇区排序分）

> **定位**：本文是长篇区排序分 `lqs` 的唯一权威口径——公式、常量、校准、边界仅在此维护。
> **状态**：2026-11-18 指标口径定稿并随 `form` 列落进种子 v3；截至 2026-11-19 工程现状为：app 主线是经典模式（classic，只读平台累计值），`lqs`/`mqs` 暂不接入引擎与推荐层，两份规格归档备查。规划见 `quantitative-mode-metrics.md`。
> **权威范围**：本文唯一维护 `lqs` 的定义与边界；推荐层接入规格见 `lqs-ranking-integration.md`，中篇域 `mqs` 见 `medium-quality-score.md`（同指标不同域、不合并）。
> **口径**：所有规模数字、相关系数、篇幅分布均为快照现算值（口径 universe 约 24 万行，随数据版变化），仅供参考，禁止硬编码进代码；由 `analysis/lib/lqs.py` 现算。
> **更新日期**：2026-11-21。

---

## 1. 结论

```
lqs = q × (0.75 + 0.25 × len)
```

- `q` = 同「世代 × 收藏档」内的 `pr` 分位（去掉收藏规模对赞藏比的机械影响）；
- `len` = `log(字数/15万) / log(100万/15万)`，夹在 `[0,1]`（超过 100 万字不再加分）；
- 结果与收藏量秩相关 **−0.01**（不是热度榜）、与 `pr` 秩相关 **+0.62**（仍是口碑驱动，均为快照现算）。
- **只作排序信号，不作质量标签**；不改 `pr`、不改分位五列及其分母、不改报告 23、不动定年。

---

## 2. 为什么 `pr` 单独不够

长篇区（`form=long` 且字数 >15 万，本数快照现算、见 `form-definitions.md`）的 `pr` 与篇幅**强负相关**（快照现算）：

| 篇幅档 | `pr` 中位 | 收藏中位 |
| --- | ---: | ---: |
| 15–30 万 | 0.515 | 289 |
| 30–50 万 | 0.299 | 1,441 |
| 50–100 万 | 0.240 | 3,449 |
| 100–200 万 | 0.224 | 7,597 |
| 200 万+ | 0.236 | 17,010 |

`pr` 前 1% 的篇幅构成：15–30 万占 78.1%、100 万以上 0 本。而读者实际选择相反——同代、同一 `pr` 五分位内，长篇收藏中位是 15–30 万字的 1.6–10.7 倍（随篇幅递增，逐年现算）；全库收藏加权中位篇幅约 102 万字。

> 机制：`pr` 的分母是收藏，长篇读者更难读完、更难留下赞，比值天然压低长书。直接按 `pr` 排序会把推荐池压到 20 万字量级——这正是 `lqs` 要修的问题。

## 3. 定义与常量

| 常量 | 值 | 理由 |
| --- | --- | --- |
| `ZONE_FORM` | `long` | 只作用长篇区；对话/互动（88 万字仍属 `dialogue`）不适用 |
| `ZONE_MIN_WORDS` | 150,000 | 命名长篇但字数不足的不入池（「X 征长篇」中位仅 1.4 万字） |
| `EVIDENCE_MIN_FAVS` | 200 | 证据下限：`favs` 200 以下 `pr` 抽样噪声压倒信号 |
| `PR_CAP` | 5.0 | `pr` 长尾截断（原文最大 23.5，来自 15 收藏级小样本） |
| `LEN_LO / LEN_HI` | 15 万 / 100 万 | 篇幅系数 0 → 1 的锚点；>100 万封顶，防灌水刷分 |
| `LEN_K` | 0.25 | 篇幅权限：系数区间 `[0.75, 1.00]`，见 §4 校准 |
| `MIN_CELL` | 40 | 「世代 × 收藏档」最小样本，不足退回同档全体分位（回退率约 1.8%，快照现算） |

- **质量项 `q`**：先把 `pr` 按收藏档切开（200–1k / 1k–5k / 5k+），再在「世代 × 档」内取分位。不分档则 `pr` 中位随收藏规模从 1.48（10–50 收藏）掉到 0.17（5k+），分位会被规模而非口碑主导。
- **篇幅项 `len`**：对数插值（15→30 万与 80→95 万对读者意义不同）；封顶 100 万（200 万+ 档收藏中位并不比 100–200 万多一个量级）。
- **合成用乘性、保留下界 0.75**：加性混合允许篇幅补偿质量（低质长书压过高质短书）；乘性下篇幅最多拿走 25%，且 `q` 低的书永远起不来。
- **与报告 23「不连乘」约束的关系**：那条约束针对「篇幅效率 × `pr`」两个都带质量含义的信号相乘；这里 `len` 是**显式先验**（读者承诺意愿）、不是质量证据且封顶 25%。该约束修订为：**篇幅先验可以进推荐，但必须有下界、有上限、不得作为质量标签**。

## 4. 校准结论：为什么是 `K = 0.25`

以「推荐池 top1000 中位篇幅对齐全库收藏加权中位篇幅（快照约 102 万字）」为锚，调节 `K`（快照现算）：

| `K` | top1000 中位篇幅 | 与加权中位差 | `rho(lqs, pr)` |
| ---: | ---: | ---: | ---: |
| 0.20 | 934,880 | −8.4% | 0.633 |
| **0.25** | **1,030,464** | **+0.9%** | **0.623** |
| 0.30 | 1,089,268 | +6.7% | 0.611 |
| 0.50 | 1,179,922 | +15.6% | 0.556 |

`K = 0.25` 同时满足篇幅对齐误差 <1%、口碑保真度 >0.6；再大就开始超配长书、榜单向「字数榜」退化。上线后若拿到留存数据，只调 `LEN_K`（0.2–0.4），不改公式结构。

## 5. 行为（快照现算）

- top200 篇幅构成：50–100 万 23%、100–200 万 45%、200 万+ 32%、15–50 万 **0%**。
- top1000：中位篇幅约 103 万字，收藏中位 5,454，`favs<1k` 占 14.9%（仍能捞出小众长书）；收藏覆盖 11.8%（纯收藏榜 top1000 覆盖 47.2%）。
- 15–30 万字最好的一本（29.5 万字 / 6,017 收藏）排 890 / 12,126（前 7.3%）——不封杀，但退出推荐头部。

## 6. 边界

- **`favs < 200` 的长篇不给分**（`lqs = NULL`，约 4,900 本、0.4% 收藏，快照现算）；它们仍可按 `fav_pctl` / `praise_pctl` 出现在其它榜，只是不进篇幅加权推荐池。
- **中篇区（5–15 万字）已定参（`mqs`），归档未落地，见 `medium-quality-score.md`**：同一公式会把所有中篇压到 0.75 下界（`len` 恒为 0），故 mid 域下移锚点单独定标，**不直接复用本指标**；两域不重叠、**分数不可比**。
- **对话/互动不适用**：`form=dialogue` 优先于篇幅，88 万字的对话小说不进长篇池。
- **连载中不因长而加分**：`status` 不进入 `lqs`；沿用候选池门槛。
- **不作质量标签**：详情页只并列「132 万字 / 同代口碑分位 92%」，不给「好/差」判定。

## 7. 落地（工程侧，本文不执行）

- 种子：`books` 加 `lqs REAL`，索引 `(lqs DESC)`；`NULL` 语义见 §6，分位五列与分母不动。
- 唯一实现 `analysis/lib/lqs.py`（`compute()` + 审计 CLI）；`build_seed.py` 调它，`validate.py` 断言：`lqs ∈ [0,1]`、非空数 = 长篇区 `favs≥200` 数、`|rho(lqs, favs)| < 0.1`（防退化成热度榜）。
- 引擎接入方式、排序键、分页游标、对话曝光与验收断言见 `lqs-ranking-integration.md`；**不要直接 `ORDER BY lqs DESC` 替换所有流**。
- 双模式：novly 模式展示收藏原值，但排序仍走 `lqs`（`app/docs/12-dual-mode.md` 白名单）。

## 8. 不做什么

- 不重算 `pr`、不改分位分母、不改报告 23；不把 `lqs` 用到短篇/中篇/对话区。
- 不用绝对 `favs` 做质量门槛（200 只是证据下限）。
- 不把 `words` 原始值打进推荐打分——`len` 是归一化先验，不是「字数越多越好」的直通规则。
