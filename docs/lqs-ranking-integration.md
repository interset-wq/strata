## 1. 先纠正一个问题：篇幅塌陷发生在哪条排序上

用户提出 `lqs` 的动机是「推荐若推短书会掉留存」。实测当前三个排序口径的 Top-100
（候选 = 非授权 + 有封面 + `seed.books`，17,243 本）：

| 排序键 | Top100 中位字数 | <15 万字 | form 构成 | Top100 收藏和 |
|---|---:|---:|---|---:|
| `clicks DESC`（当前 `/discover`） | 2,992,456 | 0 | long 96 / dialogue 4 | 10,789,913 |
| `fav_pctl DESC`（分位榜口径） | 2,144,535 | 0 | long 100 | 9,998,498 |
| **`pctl_pr DESC`** | **71,272** | **61** | long 39 / medium 26 / short 16 / dialogue 19 | **2,364** |
| **`pr DESC`** | **100,944** | **59** | long 41 / medium 45 / dialogue 8 / short 4 / ip 2 | **3,083** |
| `lqs DESC`（仅 lqs 非空） | 1,532,700 | 0 | long 100 | 1,371,515 |

**结论**：会把推荐池压到 6–7 万字的是 `pr` / `pctl_pr` 这类赞藏比信号，
不是 `fav_pctl` 或 `clicks`。`/discover` 当前按 `clicks` 排，篇幅并不短；
但 `clicks` 是平台累计展示值，按双模式 §3.2 **不得进推荐打分**。
所以 `lqs` 的接入目的有两个，缺一不可：

1. **在推荐打分中替代 `pr` / `pctl_pr`**——保住篇幅，同时保持口碑驱动
   （`rho(lqs, pr)=+0.62`，不是热度榜）。
2. **在推荐流中替代 `clicks` 作为排序键**——让排序只用白名单字段，合规。

不要把 `/discover` 的展示口径当成 bug 改掉：它是展示流，`clicks` 在那里是合法展示值。
若产品决定把 `/discover` 升级为推荐流，才按本文 §3 替换其排序键与游标。

## 2. 已撤回的方案（不要执行）

我在讨论中提过「按 form 分桶配额 60/15/15/10 混排」——**实测有害，已撤回**：
该方案 Top100 中位字数只有 **295,773**（<15 万字 41 本），
比现状 299 万字低一个数量级，与目标完全相反。
不要按全量 form 配额混排，尤其不要把 `medium`/`short` 按比例塞进推荐头部。

对话品类若需要曝光，用**长对话小配额**（见 §3.3），不要按 form 占比配额。

## 3. 实施规格

### 3.1 落点

当前代码里没有独立的推荐打分实现：`/discover`（`store.go:538`）是展示流，
`RankingFavs`（`store.go:302`）是分位榜，Classic board 的 `recommend`（`store.go:468`）
按 `praises DESC` 属展示层。执行方需**新增一条推荐流**（建议独立端点 `/strata/recommend`），
不改动上述三条既有查询的口径；若产品明确要求复用 `/discover`，则把它整体切换到本规格。

### 3.2 排序键（两级，不能合并成一个数）

`lqs` 只有长篇区有值，直接 `fillna(fav_pctl)` 混排会把高收藏短篇顶上来——
实测 Top100 中位字数掉到 203,943、form 混杂。正确做法是**组间优先 + 组内兜底**：

```
ORDER BY (lqs IS NULL) ASC,        -- lqs 非空的长篇区优先
         lqs DESC,                 -- 组内：篇幅加权口碑
         fav_pctl DESC,            -- lqs 为空时按同代收藏分位兜底
         seed.books.nid ASC        -- 稳定 tie-break，游标必需
```

验证结果：该排序 Top100 中位字数 **1,508,741**、中位收藏 7,882、<15 万字 0，
100 本全为 long。游标键 = `(has_lqs, lqs, fav_pctl, nid)`，
用 keyset 比较而非 OFFSET；序列化格式由执行方定，但必须保证重放不重不漏。

### 3.3 对话曝光（可选，需产品确认）

若发现流需要对话品类露出，只允许**长对话小配额**：
从 `form=dialogue AND words>=150000` 中按 `fav_pctl DESC` 取 **5 本**插入 Top-100
（有封面的长对话 190 本，足够），其余 95 本按 §3.2。

实测该方案 Top100 中位字数 **1,460,527**、中位收藏 8,384，
form = long 95 / dialogue 5，篇幅几乎不降。
**不要**从全量 2,711 本有封面对话里取配额（中位字数仅 14,157）。

### 3.4 候选门槛与硬约束

- `is_licensed = 0`；封面 hard gate 保留
  （`COALESCE(c.cover, NULLIF(seed.books.cover_url,'')) IS NOT NULL`，双模式 §5）。
- `fav_pctl IS NOT NULL`（双模式 §3.3 的可推荐门槛当前代理；正式门槛待拍板）。
- `clicks` / `favs` / `praises` 原始值**只作展示字段**，不得出现在 ORDER BY / WHERE 打分。
- `pr` / `pctl_pr` 不得替代 `lqs` 作推荐打分（见 §1）。
- `lqs` 不作质量标签展示；详情页只并列「字数 + 同代分位」（权威文档 §5）。
- 中篇区（5–15 万）不因本规格获得排序信号，仍待定；不改 `form` 判据、不改深榜、不改种子。

## 4. 验收断言（执行方自测，数字现算）

| 断言 | 基线 / 阈值 |
|---|---|
| Top100 中位字数 | ≥ 1,000,000（§3.2 实测 1,508,741） |
| Top100 字数 <15 万 | = 0（§3.2 实测 0；若启用 §3.3 配额则 dialogue 5 本均 ≥15 万） |
| Top100 收藏和 | ≥ 1,600,000（§3.2 实测 1,623,876；比 clicks 榜低是合规代价，需产品确认） |
| `rho(lqs, favs)` | \|ρ\| < 0.1（防退化成热度榜；权威文档红线） |
| 排序键审计 | ORDER BY / WHERE 中无 `clicks` / `favs` / `praises` 原始值 |
| 分页稳定性 | 同一 cursor 重放不重不漏；同分 nid 升序 |
| 覆盖率 | 推荐池可用书 = 有封面且 `lqs` 非空者（当前 10,536 本），`lqs=NULL` 时走 §3.2 兜底 |

## 5. 前置依赖与风险

- **封面已不再是主要瓶颈，但仍是硬门槛**：`lqs` 非空 10,799 本里有封面 10,536 本（98%）；
  非授权种子整体封面覆盖 17,371/18,184 = **95.5%**。双模式 §5 规定无封面书不进发现流，
  剩余 815 本无封面书只能走 UI 占位（原 1,602 本缺口中多数连载短/中篇已被 E.11/E.13 剔除或豁免回种）。
- **合规代价**：`clicks` 榜 Top100 收藏和 1,079 万 vs `lqs` 榜 134 万；
  换成白名单信号会明显降低头部的累计收藏展示量。这是展示/推荐解耦的既定代价，
  不是回归——`RankingFavs` 与 Classic board 仍保留原口径供展示。
- **校准窗口**：上线后若拿到留存数据，只调 `LEN_K`（0.2–0.4），不改公式结构
  （权威文档 §6）。期间不得用 `clicks` 回流调权（双模式 §3.4）。
