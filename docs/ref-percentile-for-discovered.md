# 库外书同代分位指标：参照分位 `ref_pctl`（断点表查表法）

> **状态**：2026-11-21 设计定案。**只出文档，`app/` 冻结**（v6 主线由开发 agent 施工），
> 未改任何代码、种子或数据集。落地步骤见 §7，须裁定后执行。
>
> **解决的问题**：自动收录的书（搜索 / 官方榜单点击详情触发）有成绩字段和 nid 定年，
> 但不在 `universe` 里，算不出 `fav_pctl`，因此进不了任何分位榜。本文定义一个人人可算的
> 参照分位，让库外书与种子书用**同一把尺子**排序。
>
> **上游口径**：分位定义与三条红线见 [`metrics-definitions.md`](./metrics-definitions.md) §2；
> 定年与外推边界见同文 §1.1；库外书链路见 `app/docs/08-search.md` §search-remote/§discovered。
>
> **数字口径**：本文所有断点数字是 `analysis/out/novels.csv` 现算的**形态示例**
> （内容上界 2026-05-03），仅说明表的样子，**不是定案值、禁止硬编码**；
> 构建时由生成器从 `universe` 现算。

## 0. 一句话与"为什么不是收藏速率"

```
ref_pctl(nid, favs) = 把 favs 插入其定年世代的收藏分布，查断点表线性插值得同代相对位置 (0,1]
```

它"更好"在三点，逐条都相对现有指标：

1. **比绝对 `favs` 好**：跨代可比。绝对收藏被书龄与曝光分母支配（报告 02/08 红线）。
2. **比"收藏速率 `favs / 书龄`"好**：速率看似用定年消除了书龄，实测**放大**世代差异——
   各代收藏中位 CV=0.385，除书龄后速率 CV=**0.749**（新书有曝光红利、分母小，速率虚高；
   2024→2026 速率中位 0.011→0.068 差 6 倍）。速率只解决书龄、没解决曝光分母，已否证。
3. **比现有 `fav_pctl` 好**：现有分位依赖运行时访问 24 万行 `universe`，库外书无处可查；
   断点表把分布固化成一张小表，种子书与库外书都能算，且语义与现有 `fav_pctl` 同源
   （同一分布、同一 `rank/N` 定义），两套书不再用两把尺子。

**定年在这里的角色**：不进公式做分母（那是速率的错误用法），只做**分组键**——
决定这本书查哪一世代的断点表。这是"结合数字字段 + nid 定年"的正确结合方式。

## 1. 库外书缺什么：三层缺口

| 层 | 种子书 | 库外书（自动收录） | 对分位的影响 |
| --- | --- | --- | --- |
| universe 归属 | 在 241,864 行内 | **不在** | 运行时 `rank/N` 无分母 → 算不出 `fav_pctl` |
| form | 已判六值 | **无**（seed-only，靠 DOM/字数/征文判定） | 不挡路：现有 `fav_pctl` 分母不分 form（恒定），故不需要 form |
| 成绩字段 | 快照全字段 | 详情抓取后：`favs`/`praises`/`words`（HTML）或 `clicks`/`favs`/`words`（App API） | `favs` 两条路径都有 → 可作通用主信号；`praises`/`clicks` 各有缺口，见 §5 |

**数据获取链路**（指标层不关心书怎么进 `discovered`，只要有 `favs` + nid 即可）：
官方榜单条目 nid → 点击详情 → `book()` 走库外 overlay（`api.go::book`）→ `bookRefresh`
抓取并写入 `book_meta`/`observations`。**前置条件**：该 nid 须已有 `book_meta` 行，否则
`book()` 返回 404。榜单点击是否稳定触发这次详情抓取，属 app 链路，须开发 agent 确认
（本轮不改 `app/`）。`nid` 定年由 Go `eras.Estimate(nid)` 给出（`api.go::book` 已填
`est_year/est_date/est_conf`），与 Python `lib/eras.estimate` 同源、golden-test 对齐。

## 2. 指标定义

### 2.1 断点表 `fav_breakpoints`

对 `universe`（`is_licensed=0` 且 `est_year ∈ [2007,2025]`，2026 右删失排除）按 `est_year`
分组，在每组内对 `favs` 取一组单调递增的分位点：

```
P = {p_1, ..., p_m}   # 如 0.01, 0.02, ..., 0.50, ..., 0.99
B[year] = [(favs_at(p_i), p_i) for i in 1..m]   # favs_at(p) = 该代 favs 的 p 分位值
```

- 语义与 `fav_pctl = rank(favs, within=est_year)/N` 一致：`p` 即"该代有多少比例的书收藏 ≤ 此值"。
- 表中 `favs_at(p)` 是**带重复值的离散分布**的分位数，用线性插值（与 pandas `quantile` 默认一致）。
- 断点密度 `m` 是构建参数（建议 0.01–0.50 步长 0.01、0.50–0.99 步长 0.05，约 70 点/代），
  由校准定，现算验证即可；19 代 × 70 点 ≈ 1,330 对，纯数字表 **几十 KB**，可随种子打包。

### 2.2 查表 `ref_pctl`

```
输入: nid, favs
year    = eras.Estimate(nid).EstYear
若 year 不在断点表 → 降级（§5.2）
若 favs 为空       → NULL（不参与排序）
B = fav_breakpoints[year]
若 favs <= B[0].favs             → 返回 B[0].p * (favs / B[0].favs)   # 低端线性外推，夹到 (0, B[0].p]
若 favs >= B[-1].favs            → 返回 B[-1].p                        # 顶端封顶，不造 1.0 之外的值
否则 找到相邻两点 (a,pa),(b,pb) 满足 a <= favs <= b
     返回 pa + (favs - a) / (b - a) * (pb - pa)                       # 线性插值
```

- 取值 `(0, 1]`，与 `fav_pctl` 同量纲；REAL 存储，端上不存档位。
- 同一个 `favs` 在同一世代必得同一分位，**确定性、无随机**。
- 库外书 `favs` 更新后（再次抓详情）重算即可，无状态。

### 2.3 与现有 `fav_pctl` 的关系

- **不修改** `fav_pctl` 列、分母、五分位体系、任何报告（遵守 `metrics-definitions.md` §6）。
- `ref_pctl` 是**同源异路**：同一分布、同一定义，一个运行时算（种子）、一个查表算（全库）。
- 理想情况下同一本书两值接近（插值误差）；差异来自表的离散化与 §5 的时点差。
- 命名 `ref_pctl`（参照分位）为建议，强调"以 universe 为参照系"，待裁定。

## 3. 数据来源与口径约束

| 输入 | 来源 | 种子书 | 库外书 |
| --- | --- | --- | --- |
| `favs` | HTML `writeHTML` / App API `writeApp.MarkCount` | 快照 2026-05-03 | 详情抓取时点（实时） |
| `est_year` | `eras.Estimate(nid)` | 同算法 | 同算法（Go 端已填） |
| `est_conf` | 同上 | 锚点内插为主 | **新书多落外推段**，见 §5.3 |

**三条红线的适用**：
- 累计跨时点不可比 → 见 §5.1（时点差必须标注）。
- 快照态≠当期态 → 库外书 `status`/`words` 是抓取时的当期态，仅 `favs` 进指标，不混。
- 累计不回流推荐打分 → `ref_pctl` 是分位信号（白名单），**不是**累计原值回流；
  但 `clicks` 因曝光分母问题**不参与**本指标（§5.4）。

## 4. 断点表构建（生成器规格）

- 位置：新增 `analysis/build_fav_breakpoints.py`，输入 `analysis/out/novels.csv` +
  `lib/eras.py`，输出随种子打包的紧凑表（如 `fav_breakpoints.json`，仅数字）。
- 分母口径必须与 `metrics-definitions.md` §1.2 的 universe **完全一致**
  （正版剔除、`est_year∈[2007,2025]`），否则参照系漂移、与 `fav_pctl` 不可比。
- 每代样本量写入表头元数据（现算，如 2023 约 2.6 万、2025 约 1.5 万），供 UI 显示"参照 N"。
- 断言：断点严格递增、覆盖 `gen_min..gen_max`、与 `fav_pctl` 在同代样本上插值误差在阈值内。
- 版本随种子发版；断点表与 `seed_version` 绑定，避免跨版本口径错配。

## 5. 边界与降级（本文最重要的一节）

### 5.1 时点差——必须标注，不可沉默
`universe` 分布是 2026-05-03 快照，库外书 `favs` 是实时值。新世代在两次时点间增长快，
用今天的收藏查 5 月的分布会**系统性偏高**。缓解只有标注，没有免费午餐：
- UI 显示"参照分位（2026-05 分布）+ 抓取时间"，**不显示裸数字当作当期分位**。
- 近世代（如 `est_year ≥ gen_max-1`）的 `ref_pctl` 标"参考"，与种子书同代分位区分对待。
- 不做"用实时值反推快照值"的校正——无同书历史分布，校正即臆测。

### 5.2 2026 世代（右删失）无断点
`universe` 排除 2026，故 `est_year=2026` 的库外新书查不到表。**降级**：
- 首选：单列一张 2026 断点表，但明确标注"右删失样本、仅含年内前 4 个月新书、仅供排序不充分比较"；
- 或：该世代不参与分位榜，回退到绝对 `favs`（在近新书子集内），并标注不可比。
- 两个选项须裁定（§8）。

### 5.3 外推段定年不可靠 → 查错世代
最新锚点 nid=788,076（2026-11-01）。`nid` 更大的新书定年落外推段，误差 132–153 天，
`est_year` 可能跨年错位，导致**查错断点表**（跨代分位不可比，误差远大于表内插值）。
- `est_conf='low'` 且 `mode='extrap_high'` 时，`ref_pctl` 标"定年低置信"，不与精确档混排首位；
- 若可拿到 App API `AddTime`（`exact` 档，秒级），优先用其年份作分组键，规避外推；
- **注意**：文档 [`metrics-definitions.md`](./metrics-definitions.md) §1.1 仍写"外推阈值
  nid>774,850"，该数已随锚点追加过期（现为 788,076）；本次不改该文数字，仅在此标注。

### 5.4 `clicks` 与 `praises` 不作通用输入
- `clicks`：混曝光分母、禁回流打分，且 App API 路径字段名为 `ViewTimes` 与 CSV `clicks` 口径需映射 → **不用**。
- `praises`：只有 HTML 路径有，App API 路径缺失 → 依赖它会让一半库外书算不出，**不作主信号**；
  可作为后续口碑修补的可选加权，须另案。
- 因此 `ref_pctl` 当前**只用 `favs`**——唯一两条抓取路径都给出、且最接近真实偏好的字段。

### 5.5 假完结 / 僵尸污染
库外书未经 form 判定，含第二类僵尸（正文替换为无意义文本）与假完结短/中篇
（见 [`fake-complete-short-medium.md`](./fake-complete-short-medium.md)）。它们可能有收藏却非正常作品。
- `ref_pctl` 只算相对位置，不做质量判断；若榜单对头部敏感，须叠加"详情页存活判据"过滤，另案。

## 6. 榜单接入与展示

- **定位**：这是 C 类（端上观测）能力向"有成绩字段的库外书"的扩展，不是 A 类种子榜的替换。
  不跨 A/B/C 混排（遵守 `app/docs/03-rankings.md` §5）。
- **入口**：库外书单独的"发现/已收录"榜按 `ref_pctl DESC` 排；或作为详情页的
  "同代参照位置"徽标（与种子书 `fav_pctl` 徽标同文案、标"参照"）。
- **标注三件套**（缺一不可，否则违反展示红线）：
  ① 候选池=本机已收录库外书；② 参照系=universe 2026-05 快照，N=该代行数；③ 抓取时间。
- **样本不足**：`discovered` 数少于阈值时整块隐藏，不做降级展示（沿用 C 类规则）。

## 7. 落地步骤（待裁定后，本轮不执行）

1. **分析**：`build_fav_breakpoints.py` 生成断点表 + 断言 + 与 `fav_pctl` 插值误差校验。
2. **种子**：断点表随 `build_seed.py` 打包，`manifest` 记断点表版本；`app/assets/` 与

3. **引擎**：Go 侧加查表函数（输入 `est_year`+`favs`，输出 `ref_pctl`）；`book()` 的库外

4. **前端**：榜单/徽标按 §6 展示三件套；`ref_pctl=NULL` 或低置信的处理按 §5。
5. **验收**：同代样本上 `|ref_pctl - fav_pctl|` 在阈值内；库外书可得值比例；外推段标注生效。

## 8. 不做什么 + 待裁定

**不做**：
- 不改 `fav_pctl` 五列、universe 分母、任何报告；不引入第二种"分位"语义。
- 不用收藏速率、绝对收藏、clicks 作为本指标的输入或替代（§0/§5.4 已否证/红线）。
- 不用 `ref_pctl` 做推荐打分回流之外的用途；展示层仍并列绝对收藏原值。
- 不改 `app/`（冻结）；不在本轮生成断点表产物。

**待裁定**：
1. **指标名**：`ref_pctl`（建议）还是其他？（须避免与 `fav_pctl` 混淆）
2. **2026 世代**（§5.2）：单列右删失断点表，还是该世代不进分位榜、回退绝对收藏？
3. **断点密度与插值**：步长参数、顶端是否封顶 1.0，是否校准确定。
4. **阈值**：样本不足隐藏阈值、外推/低置信是否允许上榜（及是否仅降位而非排除）。
5. **榜单形态**（§6）：独立"已收录分位榜" vs 仅详情页徽标 vs 两者都做。
6. **榜单点击→详情→收录链路**（§1）：是否稳定触发 `bookRefresh` 写 `book_meta`？
   若否，需开发 agent 在 app 链路补，指标层等数据就绪。
