# 库外书同代分位指标：参照分位 `ref_pctl`（断点表查表法）

> **定位**：本文是库外书参照分位 `ref_pctl` 的唯一权威口径——它是**位置分 `fav_pctl` 的库外域实现**（同一分布、种子书运行时算 vs 库外书查表算），不是第 3 个核心指标；核心定案见 `quantitative-mode-metrics.md`。指标名 `ref_pctl` 已定名。
> **状态**：2026-11-21 设计定案；只出文档，`app/` 冻结（v6 主线由开发 agent 施工），未改任何代码、种子或数据集。落地为工程侧事项，本文不执行。
> **权威范围**：本文唯一维护——`ref_pctl` 的定义、断点表规格、查表算法、边界与降级、展示口径；分位定义与三条红线见 `metrics-definitions.md`，定年阈值（外推边界）见同文。
> **口径**：所有断点数字、样本量均为 `analysis/out/novels.csv` 现算的形态示例（内容上界 2026-05-03），随数据版本变化，仅供参考，禁止硬编码进代码；构建时由生成器从 universe 现算。
> **更新日期**：2026-11-21。

---

## 1. 结论

```
ref_pctl(nid, favs) = 把 favs 插入其定年世代的收藏分布，查断点表线性插值得同代相对位置 (0,1]
```

自动收录的书（搜索 / 官方榜单点击详情触发）有成绩字段和 nid 定年，但不在 `universe` 里，算不出 `fav_pctl`，进不了任何分位榜。`ref_pctl` 让库外书与种子书用**同一把尺子**排序。

它「更好」在三点，逐条都相对现有指标：

1. **比绝对 `favs` 好**：跨代可比（绝对收藏被书龄与曝光分母支配）。
2. **比「收藏速率 `favs / 书龄`」好**：速率实测**放大**世代差异——各代收藏中位 CV=0.385，除书龄后速率 CV=0.749（新书曝光红利、分母小，速率虚高；2024→2026 速率中位 0.011→0.068 差 6 倍）。速率只解决书龄、没解决曝光分母，已否证。
3. **比现有 `fav_pctl` 好**：`fav_pctl` 依赖运行时访问约 24 万行 universe，库外书无处可查；断点表把分布固化成一张小表，种子书与库外书都能算，且语义同源（同一分布、同一 `rank/N` 定义）。

**定年的角色**：不进公式做分母（那是速率的错误用法），只做**分组键**——决定这本书查哪一世代的断点表。

## 2. 定义与判定

### 2.1 库外书的三层缺口

| 层 | 种子书 | 库外书（自动收录） | 对分位的影响 |
| --- | --- | --- | --- |
| universe 归属 | 在 universe 内 | **不在** | 运行时 `rank/N` 无分母 → 算不出 `fav_pctl` |
| form | 已判六值 | **无**（seed-only） | 不挡路：`fav_pctl` 分母不分 form，故不需要 form |
| 成绩字段 | 快照全字段 | 详情抓取后：`favs`/`praises`/`words`（HTML）或 `clicks`/`favs`/`words`（App API） | `favs` 两条路径都有 → 通用主信号；`praises`/`clicks` 各有缺口 |

数据链路（指标层不关心书怎么进 `discovered`）：榜单条目 nid → 点击详情 → `book()` 走库外 overlay → `bookRefresh` 抓取并写入 `book_meta`/`observations`。前置：该 nid 须已有 `book_meta` 行，否则 `book()` 返回 404；榜单点击是否稳定触发详情抓取属 app 链路，须开发 agent 确认。`nid` 定年由 Go `eras.Estimate(nid)` 给出，与 Python `lib/eras.estimate` 同源、golden-test 对齐。

### 2.2 断点表 `fav_breakpoints`

对 universe（`is_licensed=0` 且 `est_year ∈ [2007,2025]`，2026 右删失排除）按 `est_year` 分组，在每组内对 `favs` 取单调递增分位点：

```
P = {p_1, ..., p_m}   # 如 0.01..0.50 步长 0.01、0.50..0.99 步长 0.05，约 70 点/代
B[year] = [(favs_at(p_i), p_i) for i in 1..m]   # favs_at(p) = 该代 favs 的 p 分位值（线性插值）
```

- 语义与 `fav_pctl = rank(favs, within=est_year)/N` 一致：`p` 即「该代有多少比例的书收藏 ≤ 此值」。
- 19 代 × 约 70 点 ≈ 1,330 对，纯数字表几十 KB，可随种子打包；断点密度 `m` 是构建参数，现算验证即可。

### 2.3 查表 `ref_pctl`

```
输入: nid, favs
year    = eras.Estimate(nid).EstYear
若 year 不在断点表 → 降级（§4.2）
若 favs 为空       → NULL（不参与排序）
B = fav_breakpoints[year]
若 favs <= B[0].favs    → 返回 B[0].p * (favs / B[0].favs)   # 低端线性外推，夹到 (0, B[0].p]
若 favs >= B[-1].favs   → 返回 B[-1].p                       # 顶端封顶，不造 1.0 之外的值
否则 找相邻两点 (a,pa),(b,pb) 满足 a <= favs <= b
     返回 pa + (favs - a) / (b - a) * (pb - pa)              # 线性插值
```

- 取值 `(0, 1]`，与 `fav_pctl` 同量纲；REAL 存储，端上不存档位；确定性、无随机。
- 库外书 `favs` 更新后（再次抓详情）重算即可，无状态。
- **不修改** `fav_pctl` 列、分母、五分位体系、任何报告；`ref_pctl` 是**同源异路**：同一分布、同一定义，一个运行时算（种子）、一个查表算（全库）。理想情况下同一本书两值接近（插值误差），差异来自表的离散化与 §4 的时点差。

## 3. 操作：数据来源与构建

| 输入 | 来源 | 种子书 | 库外书 |
| --- | --- | --- | --- |
| `favs` | HTML `writeHTML` / App API `writeApp.MarkCount` | 快照 2026-05-03 | 详情抓取时点（实时） |
| `est_year` | `eras.Estimate(nid)` | 同算法 | 同算法（Go 端已填） |
| `est_conf` | 同上 | 锚点内插为主 | 新书多落外推段（§4.3） |

三条红线的适用：累计跨时点不可比 → 时点差必须标注（§4.1）；快照态≠当期态 → 库外书只 `favs` 进指标、status/words 不混；累计不回流打分 → `ref_pctl` 是分位信号（白名单）、不是累计原值回流，`clicks` 不参与（§4.4）。

**生成器规格**：新增 `analysis/build_fav_breakpoints.py`，输入 `analysis/out/novels.csv` + `lib/eras.py`，输出随种子打包的紧凑表（如 `fav_breakpoints.json`，仅数字）。分母口径须与 `metrics-definitions.md` 的 universe **完全一致**，否则参照系漂移、与 `fav_pctl` 不可比。断言：断点严格递增、覆盖 `gen_min..gen_max`、与 `fav_pctl` 在同代样本上插值误差在阈值内；版本随种子发版、与 `seed_version` 绑定。

## 4. 边界与降级（本文最重要的一节）

### 4.1 时点差——必须标注，不可沉默
universe 分布是快照、库外书 `favs` 是实时值；新世代在两次时点间增长快，用今天的收藏查 5 月分布会**系统性偏高**。缓解只有标注：UI 显示「参照分位（2026-05 分布）+ 抓取时间」，不显示裸数字当当期分位；近世代（`est_year ≥ gen_max-1`）标「参考」，与种子书同代分位区分；不做「用实时值反推快照值」的校正（无同书历史分布，校正即臆测）。

### 4.2 2026 世代（右删失）无断点
universe 排除 2026，故 `est_year=2026` 的库外新书查不到表。降级二选一（须裁定）：单列 2026 断点表并标注「右删失样本、仅含年内前 4 个月新书、仅供排序不充分比较」；或该世代不参与分位榜、回退绝对 `favs`（近新书子集内）并标注不可比。

### 4.3 外推段定年不可靠 → 查错世代
外推段新书的 `est_year` 可能跨年错位、导致查错断点表（跨代分位不可比，误差远大于表内插值）。处置：`est_conf='low'` 且 `mode='extrap_high'` 时标「定年低置信」，不与精确档混排首位；若可拿到 App API `AddTime`（`exact` 档、秒级），优先用其年份作分组键。**定年阈值与外推边界见 `metrics-definitions.md`。**

### 4.4 `clicks` 与 `praises` 不作通用输入
`clicks` 混曝光分母、禁回流打分，且 App API 字段名 `ViewTimes` 与 CSV `clicks` 需映射 → 不用。`praises` 只有 HTML 路径有 → 依赖它会让一半库外书算不出，不作主信号（可作后续口碑修补的可选加权，另案）。故 `ref_pctl` **只用 `favs`**——唯一两条抓取路径都给出、最接近真实偏好的字段。

### 4.5 假完结 / 僵尸污染
库外书未经 form 判定，含第二类僵尸与假完结短/中篇（见 `fake-complete-short-medium.md`）。`ref_pctl` 只算相对位置、不做质量判断；若榜单对头部敏感，须叠加「详情页存活判据」过滤，另案。

## 5. 榜单接入与展示

- **定位**：C 类（端上观测）能力向「有成绩字段的库外书」的扩展，不是 A 类种子榜的替换；不跨 A/B/C 混排（遵守 `app/docs/03-rankings.md`）。
- **入口**：库外书单独的「发现/已收录」榜按 `ref_pctl DESC` 排；或作详情页「同代参照位置」徽标（与种子书 `fav_pctl` 徽标同文案、标「参照」）。
- **标注三件套（缺一不可）**：① 候选池=本机已收录库外书；② 参照系=universe 2026-05 快照、N=该代行数；③ 抓取时间。
- **样本不足**：`discovered` 数少于阈值时整块隐藏，不做降级展示（沿用 C 类规则）。

## 6. 落地步骤（工程侧，本文不执行）

1. **分析**：`build_fav_breakpoints.py` 生成断点表 + 断言 + 与 `fav_pctl` 插值误差校验。
2. **种子**：断点表随 `build_seed.py` 打包，`manifest` 记版本；双产物同步（项目硬约束）。
3. **引擎**：Go 侧加查表函数（输入 `est_year`+`favs`，输出 `ref_pctl`）；`book()` 的库外 overlay 与 `discoveredList` 附带该值，`est_conf` 一并返回供 UI 标注。
4. **前端**：按 §5 展示三件套；`ref_pctl=NULL` 或低置信按 §4 处理。
5. **验收**：同代样本上 `|ref_pctl - fav_pctl|` 在阈值内；库外书可得值比例；外推段标注生效。

## 7. 边界：不做什么 + 待裁定

**不做**：不改 `fav_pctl` 五列、universe 分母、任何报告，不引入第二种「分位」语义；不用收藏速率、绝对收藏、clicks 作输入或替代（§1/§4.4 已否证/红线）；展示层仍并列绝对收藏原值，累计原值不回流推荐打分；不在本轮生成断点表产物。

**待裁定**（合法产品待定，不影响指标定义）：
1. **2026 世代**（§4.2）：单列右删失断点表，还是该世代不进分位榜、回退绝对收藏？
2. **断点密度与插值**：步长参数、顶端是否封顶 1.0，是否校准确定。
3. **阈值**：样本不足隐藏阈值、外推/低置信是否允许上榜（是否仅降位而非排除）。
4. **榜单形态**（§5）：独立「已收录分位榜」vs 仅详情页徽标 vs 两者都做。
5. **榜单点击→详情→收录链路**（§2.1）：是否稳定触发 `bookRefresh` 写 `book_meta`？若否，需开发 agent 在 app 链路补。
6. **是否解禁 `app/`** 进入 §6 落地，及由谁施工。
