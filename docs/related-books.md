# 书籍详情页「相关推荐」调研与实施方案

> **状态**：算法方案 **v5**（2026-11-26，用户裁定）已落地；v4.1 已被取代。
> **v5 补充裁定（2026-11-26）**：cover **不得作为任何判断依据**——sfacg 曾弄丢大量
> 优质书籍的封面，cover 为空是源站数据事故、不是作品质量信号；只作展示字段，
> 空值由 UI 占位兜底（详见 §3.2）。
> **已落地**：store `RelatedBooks`（`app/engine/internal/store/related.go`）、
> `GET /strata/related`、详情页 `_similarRail`（文案「相关推荐」）。
> 口径继承：`app/docs/12-dual-mode.md`（展示/推荐解耦、口碑驱动、累计值禁回流）、
> `app/docs/18-runtime-metrics.md`（cqs/cps 唯一权威）、`app/docs/05-detail-fetch.md`（覆盖层/离线）。
> 文中计数为种子 `20261126.38` 快照现算，随数据版本变化，禁硬编码进代码。

### v5 变更（2026-11-26 用户裁定：指标只排展示顺序）

用户发现「怎么可能是诗词鉴赏」「苍蓝之境」等书被高频推荐，裁定：
**所有自定义指标（cqs/cps/pr）不能影响被推荐的候选书籍，只能影响选中书籍的排序。**
v4.1 把 cqs/pr 同时用作候选门槛（`cqs IS NOT NULL` / `pr IS NOT NULL AND favs≥10` /
cps 中层带）与选书 `ORDER BY score DESC`，导致高指标书在每组都排第一、跨锚点垄断。

v5 把指标从 WHERE / 选书 ORDER BY 全部移除：

| 环节 | v4.1（违规） | v5（定稿） |
| --- | --- | --- |
| 候选准入 | cqs/pr 非空 + cps 中层带 + favs≥10 + 有封面 | **只用内容/非指标门槛**：非授权、同 form、非当前 nid、非同作者；**封面缺失不排除** |
| 选书排序 | `ORDER BY score DESC`（cqs/pr） | 内容信号：全标签重叠数 DESC、年代接近、nid ASC + 强标签分层轮流 |
| 展示顺序 | 与选书同序 | **唯一用指标处**：选满 limit 后按 cqs / 平滑 pr DESC 重排，NULL 垫底 |

实证（`analysis/out/related_v5.py`，同一组随机 300 锚点 × 6 位）：v4.1 重复率 66.4%
（单本最高 19 次）、命中 40.6%；v5 重复率 **21.3%**、命中 **44.2%**，诗词鉴赏/苍蓝之境/
遗落的少女/当只小鸡/黑魔王霍格沃兹五本关注书**全部降到 0 次**。指标从候选移除没有引入
低质量书（cqs=NULL 的 10,711 本 favs 中位 838、最高 28 万，只是没进评分格）。

## 1. 结论

详情页相关推荐 = **以当前书为锚点的强标签召回（分级 + 分层 + 轮流，全用内容信号）+
选出后按口碑分排展示顺序**，做成纯本地、离线可用的 `GET /strata/related`
（纯 seed 查询、无网络），复用现有横滑 UI。

- **不是**协同过滤（无用户行为日志）、**不用**平台累计值排序（双模式红线）。
- 与已有「同作者其他作品」rail 互补：前者按作者，本方案按题材/标签/世代。
- 核心设计（v5 强化）：**"相关""选中"与"展示顺序"三层解耦**——内容相似度决定召回谁、
  分哪一层、选中哪几本；口碑分（cqs/pr）**只在选满后决定展示顺序**，绝不进入候选或选书。
  这是防止高指标书被反复推荐的硬约束（用户 2026-11-26 裁定）。

## 2. 现状（已核实）

- **详情页唯一出口**是「同作者其他作品」横滑（`book_detail_page.dart::_relatedRail`，走
  `/author-books`，纯 seed、离线、8 本、不足 2 本整行隐藏），无"看了这本还能看什么"的内容出口。
- **后端零相似度逻辑**：`store.go` 只有 `Recommend`/`RecommendCQS`（全局口碑流）与
  `AuthorBooks`（作者作品）；无 related/similar 函数，无向量/嵌入、无 FTS5（02 明确不建）。
- **可用字段**（`books` 25 列）：`genre`（9 值题材）、`book_tags`（51,147 行）、`form`（六值互斥）、
  `est_year`/`est_date`（定年）、`author`；口碑信号 `cqs`/`cps`/`pr`。
- **信号约束**：`cqs` 只在 long（4,235 本有值）/ dialogue（1,048）可信；short/ip_collab 无 cqs，
  量化流已回退 `pr`（08/18 既定）。`clicks/favs/praises` 原始累计值**禁入排序**。
- **召回量充足**：同 form+genre+cqs 池 510–1,656 本（加 |Δyear|≤3 仍有 132–1,166），
  短篇 pr 池 266 本，标签 ≥1 重叠同 form 书 514 本——无需跨 form 或动用累计值。

## 3. 算法（v5 定稿）

### 3.1 锚点归一化

按当前 nid 取锚点，遵循"收录均等原则"（08 §recommend 三源并集）：
`seed.books` → 已评分 `discovered` → `book_meta`，字段 `form / genre / est_year / author / tags`。
库外书无 form 时按 `book_meta.form` 兜底；仍无 form 则不进相关推荐。

### 3.2 候选硬门槛（WHERE）—— 无任何自定义指标

1. `is_licensed=0`（授权 47 本不参与）；
2. `form = 锚点 form`（18 §2 红线 1，跨 form 不相关）；
3. `nid <> 锚点` 且 `author <> 锚点`（同作者交给已有 rail）。

**cover 不是判断依据**（用户 2026-11-26 补充裁定）：sfacg 曾弄丢大量优质书籍的
cover，`cover_url` 为空是**源站数据事故**，与作品质量无关。cover 只在 SELECT 里
取出（`COALESCE(covers.cover, NULLIF(cover_url,''))`）供卡片展示，空值由 UI 的
`coverImage` 本地占位兜底（`book_detail_page.dart`）；**绝不进候选 WHERE、选书
ORDER BY 或任何打分**。原「有封面」门槛已删除（v4.1 及以前继承发现流，误把丢图
当成低质量）。

**v5 移除的旧门槛**（指标决定"谁被推荐"，违反用户裁定）：`cqs IS NOT NULL`、
`pr IS NOT NULL AND favs≥10`、cps 20–80 中层带（原 §6 决策 1，随 v5 作废）。
cqs=NULL 的书照常入选——它们不是低质量（10,711 本、favs 中位 838），只是没进评分格。

### 3.3 强标签（唯一有效的相似信号）

- **定义**：全库 `book_tags` 出现 ≤ 1,000 本（约 6%），排除 `20XX萌神` 等运营年份标签。
- **泛标签不单独构成相关**：`女性主角`(6,059)/`战斗`(3,146)/`异世界`(2,946)。实证：放行泛标签会让
  「诗词鉴赏」推出整屏恋爱文，也会让「英雄再临」错过核心卖点「超级英雄」（全库 64 本）。
- 泛标签仍用于 B 档召回打散（§3.4），但**不进排序分**。

### 3.4 分级召回（高档凑不满 8 本才降档）

| 档 | 条件（同时满足） | 语义 |
| --- | --- | --- |
| A′ | 同 genre + `\|Δyear\| ≤ 3` + ≥1 强标签重叠 | 同题材、同代、同核心卖点 |
| B | 同 genre + `\|Δyear\| ≤ 5` | 同题材近代（弱相关兜底，按全标签重叠数打散，见 §3.5） |
| C′ | `\|Δyear\| ≤ 3` + ≥1 强标签重叠（跨 genre） | 换题材但同代同卖点 |
| 末档 | 同 form 口碑 Top8 | 数据薄处保底不空 |

- **极稀疏标签放宽世代**：锚点若有 df ≤ 100 的强标签（`师尊` 28 / `超级英雄` 64 / `女武神` 63），
  A′/C′ 的 `|Δyear|` 上限从 3 放宽到 8——这类书同类极少且常跨代（「师尊」锚点 2018、
  同类集中 2024–25，全被 Δ≤3 挡在门外）。
- `book_tags` 用 `EXISTS (SELECT 1 FROM book_tags WHERE nid=候选 AND tag IN (锚点强tags))`，
  51k 行有 `idx_bt(tag,nid)`，单锚点查询可控。

### 3.5 选书排序（v5，全是内容信号）—— 决定"选中哪几本"

选书阶段**不含任何自定义指标**，只用内容相似度：

1. **SQL 粗排**：全标签重叠数 DESC、年代接近、nid ASC（泛标签也计入重叠，
   但只用于打散、不合成排序分）。
2. **分层**：A′/C′ 候选归入其命中的最稀有强标签组，按该标签 df ASC 整组靠前。
3. **轮流**：锚点有多个强标签时按标签轮流各出一本再循环，不让单一卖点占满。
4. 任一档凑不满 8 本 → A′→B→C′→同 form 逐级降档；B 档必须按重叠数打散，
   **禁用锚点无关的纯口碑榜**。

### 3.6 展示排序（v5 唯一用指标处）—— 决定"选中的书谁排前面"

选满 limit 本之后，才按口碑分 DESC 重排展示顺序（nid 升序打破平手，无指标值垫底）：

- long/dialogue 用 `cqs`；short/medium/ip_collab 用**贝叶斯平滑 pr**：
  `pr_s = (praises + 500×μ0)/(favs + 500)`，μ0 = 种子书 `praises/favs` 中位
  （与 cqs 的 `pr_s` 同公式、κ 同为 500，18 §1），压掉"赞39/藏14"小样本比值虚高。
- 指标**只在此处**生效：进不了候选/选不了书，故高指标书无法垄断推荐位。
- `clicks/favs/praises` 原始累计值始终**禁入任何排序**（docs/12 §3.2）；
  `favs` 仅作平滑 pr 的分母，不是排序键。
- 锚点无强标签（全泛标签 / 无标签）→ A′/C′ 空，走 B 或末档，**诚实弱相关、不硬凑**。
- 短/中/IP 无 cqs → 全程用平滑 pr，UI 不显示任何 cqs 文案。
- 与「同作者」rail 交叉去重；数量 8 本；全程纯 seed，断网可用。

## 4. 端点与 UI（已实现）

- **`GET /strata/related?nid=&limit=`**：纯本地；`nid` 必填；`limit` 默认 8、上限 20。
  响应 `{meta:{pool:"seed", form, genre, tier, ordering}, items:[RankItem...]}`；
  `RankItem` 复用现有结构（含展示用 `favs/clicks/praises`，后端只 SELECT 不排序）。
  `meta.tier` 回显**贡献了条目的最后一档**（a/b/c/fallback，未推任何本时为 none），
  `ordering`（cqs|pr）供诊断，不向用户展示指标名。
- **store 层**新增 `RelatedBooks(ctx, anchorNid, limit)`，与 `AuthorBooks` 并列；
  按档多次查询至凑满，参数化防注入。
- **UI**（`book_detail_page.dart`）：在 `_relatedRail` 之后新增 `_similarRail`，用 `_infoRail`
  横式条卡（200dp = 56×78 封面 + 书名 13px 最多三行 + 一行作者·年代），与作者轨的
  封面卡（`_coverRail` 86dp + 书名 12px 三行）**不共用骨架**：62dp 封面卡时代书名普遍截断，
  而推荐的作者全是陌生人，书名+年代才是决策信息，封面与文字并排才放得下长标题（用户 2026-11-26）。
  `FutureProvider.autoDispose.family`；加载中/失败/<2 本整行隐藏，点击跳 `/book/:nid`。
  同作者去重由后端硬门槛（`author <> 锚点`）承担，两条轨天然不相交，前端不再去重。
  文案避开"猜你喜欢"（协同过滤心智）与精确名次叙事。

## 5. 为什么不选这些方案（取舍记录）

| 备选 | 否决理由 |
| --- | --- |
| 协同过滤 / "看了这本的人也看" | 无用户行为日志；clicks 回流即破 docs/12 红线 |
| 单纯 cqs Top（复用 `/recommend`） | 与当前书无关，退化成全局榜 |
| 连续相似度加权分 | 无语义语料、分数不可解释；分级召回已够用 |
| 向量/嵌入/FTS5 | 02 明确不建；无模型、无语料 |
| 用 `favs/clicks` 挑"同类热门" | 累计值禁入排序；`favs` 只可做展示锚 |
| 构建期预计算 related 表 | 16k×16k 组合爆炸；单书现算足够 |
| 标签共现扩展 | 实证输出与分层版完全相同，无贡献 |
| `favs≥100` 硬门槛 | 实证把听雨锚点核心命中 4/6→1/6，反伤相关；改用 pr 平滑 |
| 题材内 cqs 分位重算 | cqs 已是格内中位差，重复归一化 |
| B 档纯口碑榜 | 跨锚点重复 bug 根因；改为全标签重叠打散 |
| bucket（收藏档+年代打散） | 重复率只降到 51%，且依据是数值距离而非内容相似度 |
| **指标进候选 / 选书排序**（v4.1） | 用户裁定硬红线：高指标书会永远被推荐。v5 把 cqs/pr/cps 全部移到"选中后的展示排序"，重复率 66.4%→21.3% |
| **cps 中层带**（原 §6 决策 1） | 同属"指标影响候选"，随 v5 作废 |
| **有封面才准入选**（v4.1 及以前） | cover 缺失是 sfacg 丢图事故、不是质量问题，整批排除会误伤优质书；改为只取展示值、空值 UI 占位（2026-11-26 用户裁定） |

## 6. 落地拍板（用户 2026-11-26）

1. **UI 形态：独立 rail**。排在「其他作品」之后——一条讲"这个人还写了什么"，
   一条讲"这类书还有什么"，混排会让人误以为推荐也出自同一作者。
2. **文案：「相关推荐」**。不用「同好推荐」（社群心智）、「相似题材」（只描述一个维度）、
   「猜你喜欢」（协同过滤心智）。
3. ~~cps 中层带：加~~ —— **v5 作废**：用户裁定指标不得进候选，中层带是 cps 门槛，
   已移除。原意图（避免固化头部反复推）由"指标只排展示顺序"从根上解决。

## 7. 验证记录（真实种子实跑）

`related_v5.py`（只读、`out/` 不入库）。口径：锚点取 6 本推荐，`命中` = 命中锚点强标签

### 7.1 手段实证（对四个天花板案例 A/B）

| 手段 | 效果 | 结论 |
| --- | --- | --- |
| 强标签区分力（df≤1000） | 英雄再临捞出「超级英雄」同类；诗词鉴赏不再泛推恋爱文 | 采纳 |
| 分层优先 | 怪谈/魔女 0/6→6/6 | 采纳 |
| 多标签轮流 | 橘味 1/6→3/6（不再被热血挤满） | 采纳 |
| 稀疏标签 Δ≤8 | 师尊 0/6→6/6（同类在 2024–25，原本被世代窗口挡住） | 采纳 |
| pr 贝叶斯平滑 κ=500 | 短篇推荐 favs 从 14–25 抬到 51–254，灌水消失 | 采纳 |
| 标签共现扩展 | 输出与分层版完全相同 | 否决 |
| `favs≥100` 硬门槛 | 听雨核心命中 4/6→1/6 | 否决 |
| 题材内 cqs 分位重算 | cqs 已含格内归一，重复 | 否决 |

多题材头部复核 v4 未退化：武林之王退隐 5/6 武侠、舰长变女武神 6/6「分支小说」、
带手机到崩坏 6/6 女武神/舰长。

### 7.2 跨锚点重复 bug 与 v4.1 修复（用户实测发现）

全库 favs top50 用 v4 跑，50×6=300 个推荐位只覆盖 **178 本**、**59% 是重复书**
（「遗落的少女」11 次、四本校园书 6 本推荐完全相同）。根因：B 档「同题材口碑榜」锚点无关，
同题材锚点拿到同一张榜。A/B 对比：

| 方案 | 不同书 | 重复率 | 强标签命中 |
| --- | --- | --- | --- |
| v4 | 178 | 59.0% | 71.3% |
| bucket | 206 | 51.0% | 71.3% |
| **v4.1（B 档全标签重叠打散）** | **232** | **38.7%** | **70.0%** |

v4.1 当时判断"A′ 档高频书（賽西莉亞 5 次）是同标签组真相似、不算 bug"——**此判断后被用户
推翻**：A′/任何档的高指标书反复出现都是同一个根因（指标进了选书），v5 从根上消除。
top50 完整表格由 `related_top50_v41.py` 复现（300 位/232 本/38.7%/70.0%）。

### 7.3 剩余天花板（算法修不了）

- **标签标注噪声**：「闭嘴恶龙」的「运动」标签在同类里 top 共现是倒追/恋爱，与带孩子无关；
  轮流把它当卖点，反让 3/6 席位给非相关书。需标签清洗，超出本方案范围。
- **无标签锚点**（约 5%）：只能同 form 同题材兜底，平滑 pr 只保证不灌水、不制造相关。
- **全泛标签锚点**：「我转生就超神」「我的女友是反派」降级 B 档，质量尚可但不精准。
- **标签漏标**：「于是，我成为了魔女」标签无"魔女"，只能召回推理向；每本仅 3–5 个 tag，
  卖点漏标是数据层天花板。
- **标签漏标 / 无标签**：v5 后 cqs=NULL 已不再是门槛（§3.2），但"卖点没被打成 tag"
  仍召回不到，属数据层天花板。

### 7.4 v5：指标只排展示顺序（用户裁定，当前定稿）

用户发现「怎么可能是诗词鉴赏」「苍蓝之境」被高频推荐，裁定指标不得进候选。
`related_v5.py` 用**同一组随机 300 锚点 × 6 位**做 A/B（seed `20261126.38`）：

| 方案 | 位 | 不同书 | 重复率 | 强标签命中 |
| --- | --- | --- | --- | --- |
| v4.1（指标进候选+选书） | 1800 | 938 | 66.4% | 40.6% |
| **v5（指标只排展示顺序）** | 1800 | **1593** | **21.3%** | **44.2%** |

- 关注书频次：诗词鉴赏 1→0、苍蓝之境 3→0、遗落的少女 7→0、当只小鸡 3→0、
